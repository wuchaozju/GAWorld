\section{Purpose and Scope}

This supplement documents the validation protocol and artifact audit reported in the main paper. It is
designed to let a reviewer verify the reported numbers without launching a simulator or calling an LLM.
No result in this supplement was generated by a new simulation run. Repository paths are stated relative
to the project root in the anonymous artifact package.

The audit distinguishes four evidence-record classes:
\begin{itemize}
    \item \textsc{real}: an artifact emitted by an existing GAWorld run;
    \item \textsc{diagnostic}: a re-analysis of a real artifact for measurement or failure analysis;
    \item \textsc{synthetic}: a fabricated structural fixture used only to exercise benchmark code; and
    \item \textsc{incomplete}: an absent, interrupted, or statistically insufficient artifact.
\end{itemize}
Evidence is labeled before scoring. Synthetic and incomplete items never enter a model-validity result.
Here \textsc{diagnostic} denotes a declared transformation of a source artifact, not a competing claim
about how that source was generated. Thus one real report can support both a real descriptive record and
a diagnostic derivative, provided the source-to-statistic relation is explicit.

The audit snapshot was assembled on 2026-07-11 from repository HEAD \texttt{424cd46ae5c7}, but the
working tree contained changes and therefore
that commit does not identify the audited bytes. Full SHA-256 values in the package README are the
controlling identifiers. We searched the benchmark reports and scorecard, current economy outputs, and
known emotion, network, and memory experiment-result directories needed by the five configured tracks.
This is a purposive audit of benchmark-relevant evidence, not an exhaustive inventory of every log.

Every scientific test returns one of \{pass, fail, unassessed\}. Separately, the reproducibility gate
returns \{\textsc{ok}, \textsc{unverified}, \textsc{untrustworthy}\}. We therefore report
$(\text{outcome},\text{gate},\text{coverage})$ rather than hybrid labels such as ``fail/unverified.''

\section{Formal Validation Protocol}

\subsection{Track A: Macro Empirical Fit}

For metric $i$, let $x_i$ be the simulated aggregate, $a_i$ an external anchor, and $\tau_i>0$ a relative
tolerance. The implemented bounded score is
\begin{equation}
s_i=\max\left(0,1-\frac{|x_i-a_i|}{|a_i|\tau_i}\right).
\end{equation}
The track diagnostic is the arithmetic mean of the observed $s_i$, subject to configured hard invariants
such as money conservation. A result must additionally state:
\begin{enumerate}
    \item the number of underlying agent observations;
    \item the definition and source of each anchor;
    \item whether the target was directly parameterized; and
    \item which metrics were configured but unavailable.
\end{enumerate}
An input-derived match is classified as a calibration or implementation check. It is not evidence that an
unencoded group-level pattern emerges.

The current harness configures an urban Engel coefficient anchor of $0.288$ and a savings-rate anchor of
$0.35$. The savings definition is explicitly described as measurement-sensitive in the benchmark design;
it must not be treated as a universal ground truth.

\subsection{Track B: Emergent Dynamics}

Track B is specified but not implemented in the audited version. A valid stylized-fact test requires a
predeclared statistic $g$, horizon $T$, tolerance or hypothesis test $H$, and minimum number of seeds $R$:
\begin{equation}
\mathcal{T}_{B}=(g,T,H,R,\text{data source}).
\end{equation}
Candidate tests include logistic diffusion fit, network modularity and homophily slopes, and distributional
tail shape. A report based only on initialization, co-location, or a missing state file is incomplete.

\subsection{Track C: Counterfactual Validity}

For an event run $E$ and matched baseline $B$, the implemented endpoint contrast is
\begin{equation}
\Delta^{\mathrm{final}}_{e,m}=y^{E}_{m,T}-y^{B}_{m,T}.
\end{equation}
The archived comparison files also store the whole-run contrast
\begin{equation}
\Delta^{\mathrm{whole}}_{e,m}=\frac{1}{|\mathcal{T}|}
\sum_{t\in\mathcal{T}}\left(y^{E}_{m,t}-y^{B}_{m,t}\right).
\end{equation}
Neither estimand is universally preferable. The endpoint is vulnerable to terminal noise, while the
whole-run mean can dilute a late intervention with pre-event observations. An evaluation must state which
estimand implements the scientific question.

For preregistered direction $d_{e,m}\in\{-1,+1\}$, a single-run sign check is
\begin{equation}
I_{e,m}=\mathbf{1}\left[d_{e,m}\Delta_{e,m}>0\right].
\end{equation}
In multi-seed mode, the item is supported only when the interval estimate excludes zero and the mean has
the expected sign. With one observation, the item is statistically unassessed even if its point estimate
has the expected direction.

A placebo event uses threshold $\epsilon$ and passes metric $m$ if $|\Delta_{e,m}|<\epsilon$. The current
implementation defaults to $\epsilon=0.05$. Domain-specific work should justify or replace this value.
The audited protocol does not yet preregister a confidence level, interval estimator, minimum seed count,
multiple-comparison rule, or scale-aware equivalence margin. Until those choices are fixed, the
multi-seed path is a software capability rather than a completed inferential protocol.

In the currently implemented deterministic mode, same-seed comparison indexes state rows by
$(\text{agent},\text{step},\text{metric})$ and reports the fraction of intersecting rows equal within
absolute tolerance. No intersecting rows is failure, not success. This subtest is not a universal
requirement for stochastic simulators: a stochastic mode should preregister a replicated distributional
agreement test instead. Relative to the declared mode, the gate state is:
\begin{align}
\textsc{ok} &\quad\text{if determinism is assessed and passes},\\
\textsc{unverified} &\quad\text{if determinism is not assessed},\\
\textsc{untrustworthy} &\quad\text{if determinism is assessed and fails}.
\end{align}

Let $c=n_{\mathrm{eval}}/n_{\mathrm{configured}}$. Coverage is reported beside the component result and
is not multiplied into it, because multiplication would be equivalent to imputing every unassessed item
as zero. Coverage cannot repair a failed declared trust protocol.

\subsection{Track D: Individual and Memory Consistency}

The proposed probes are profile agreement, traceable recall, contradiction rate, and behavior under
memory ablation. For claim $q$ about an agent's remembered event, traceability is
\begin{equation}
\operatorname{trace}(q)=\mathbf{1}[\text{a timestamped episode supports }q].
\end{equation}
If an LLM judge scores coherence or persona agreement, the judge prompt, model version, order effects,
and calibration against human labels must be reported. The audited harness does not yet implement this
track.

\subsection{Track E: Reproducibility and Cost}

Track E includes cross-seed coefficient of variation, wall-clock and token cost per agent-day, structured
parse failure rate, and a mode-appropriate reproducibility test. The audited version implements only the
deterministic-mode subtest through Track C. Therefore, Track E is incomplete.

would be an error because each intervention-metric cell has only one observation.

This exact fingerprint is strong evidence of fixture-like output, but it does not establish lineage without

treated as empirical model performance.

The multi-seed fixture separately defines five values for each intervention-metric pair. Three groups are
tight and have the expected sign; the tax group straddles zero to exercise the non-significant code path.
Those values are likewise excluded from cross-seed robustness claims.

\section{Offline Verification Procedure}

The following checks read existing files and do not start GAWorld:

{\footnotesize
\begin{verbatim}
cd /path/to/anonymous/GAWorld
r=benchmark/results/reports
r=$r/report_20260615T005429.md
rg -n '0\.3368|0\.0068' "$r"
rg -n '0\.0201|-0\.0086' "$r"
rg -n '0\.08|-0\.12|0\.09|0\.06' \
  benchmark/gaworld_bench.py \
  benchmark/results/scorecard.json
\end{verbatim}
}

The current macro row can be inspected with Python's standard library:
{\footnotesize
\begin{verbatim}
import csv
from pathlib import Path
p = Path('output/economy')
p /= 'wealth_snapshot.csv'
rows = list(csv.DictReader(p.open()))
print(len(rows))
print(rows[0]['engel_coefficient'])
print(rows[0]['savings_rate'])
\end{verbatim}
}
Expected output is \texttt{1 0.48 0.05}. The conservation audit analogously contains one row with drift
\texttt{0.0}.

Live benchmark commands that include \texttt{--run} require an LLM provider and are outside this audit. No such
command was executed to prepare the paper.
