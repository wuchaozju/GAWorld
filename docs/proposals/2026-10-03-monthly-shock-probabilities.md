# 加薪 / 裁员概率按月解释

日期：2026-10-03
状态：**已实施（2026-10-03）**——可比性版本 7。
实现见 `gaworld/economy/finance.py`（`_monthly_to_daily`、`_check_daily_shocks`），
测试 `tests/test_monthly_shock_probabilities.py`。
上游：内生通胀提案（`2026-10-03-endogenous-inflation.md`）实施时发现，记在机制来源表里。

## 一、现状（改之前）

`_check_daily_shocks` 每个仿真日给每个居民抽一次签，直接拿配置里的数当**当天**的概率：

| 阶段 | 涨薪（底噪 0.008 + `raise_chance`） | 裁员（底噪 0.001 + `layoff_risk`） |
|---|---|---|
| 扩张 | 每天 3.8% | 每天 0.3% |
| 顶峰 | 每天 2.8% | 每天 0.6% |
| 收缩 | 每天 1.3% | 每天 1.6% |
| 谷底 | 每天 1.0% | 每天 2.6% |

每次涨薪 +5–25%，每次随机裁员收入砍掉 50–85%（随机裁员不会恢复原工资）。
按 2000 人、默认配置跑一年测出来（`_check_daily_shocks` 直接抽，不含医疗急症）：

| | 每人每年加薪 | 每人每年被裁 | 年末工资倍数 p10 / 中位 / p90 |
|---|---|---|---|
| 一直扩张 | 11.8 次 | 1.1 次 | 0.18 / 1.69 / 8.77 |
| 一直谷底 | 1.0 次 | 9.6 次 | 0.10 / 0.10 / 0.10 |
| 默认周期 | 6.7 次 | 4.0 次 | **0.10 / 0.10** / 0.54 |

默认周期跑一年，**中位居民的工资落在最低时薪的地板上**（0.10 = 8 / 80 元）。
打开需求驱动的通胀时，这些工资涨落原样变成通胀：3 人一年的测试里有 234 天顶在 15% 上限。

这些数是按月写的：按月读，扩张期每月 0.3% 被裁，谷底每月 2.6%；
美国 JOLTS 的裁员与解雇率常态约 **1.0%/月**（BLS，2024 年 5 月），2020 年 3 月疫情峰值 9.0%。
按天读，扩张期每月约 8.6% 被裁——相当于疫情峰值，而且是在「好年景」。

## 二、改法

**配置值不变，改成每人每月的概率**；仍然每天抽一次，每天的概率取
`1 − (1 − p_月)^(1/30)`，使一个月的 30 次抽签合起来恰好是 `p_月`
（不用 `p/30`：月概率 50% 会变成 40%）。

- 涉及：`shocks.layoff_base_prob`、`shocks.raise_base_prob`、各阶段的 `layoff_risk`、`raise_chance`。
  乘数（`econ_security` 对裁员、`income_skill` 对涨薪）先乘在月概率上，再换算。
- **不变，仍按天**：
  - `medical_emergency_prob`（0.0005/天 ≈ 每年 17% 的人碰上一次大病）——按天读是说得通的量级，按月读则变成每年 0.6%。
  - `event_layoff_prob`（0.6）——它本来就是「裁员事件生效的那一天」被裁的概率下限。
- 按天抽而不是月底一次抽：日步长的 run 不会在月底集中出事；月 / 年步长（`_period_days`）照旧抽 `days` 次，一个月的步长恰好是一个月的风险。抽签次数不变，只是阈值变了。
- 不加「按天 / 按月」开关：旧行为是错的，不需要保留成选项；要复现旧 run 用旧代码（可比性版本 6 及以前）。

## 三、改之后（同样的测法）

| | 每人每年加薪 | 每人每年被裁 | 年末工资倍数 p10 / 中位 / p90 |
|---|---|---|---|
| 一直扩张 | 0.50 次 | 0.03 次 | 1.00 / 1.00 / 1.23 |
| 一直谷底 | 0.11 次 | 0.34 次 | 0.23 / 1.00 / 1.00 |
| 默认周期 | 0.32 次 | 0.11 次 | 0.51 / **1.00** / 1.19 |

需求驱动的通胀（3 人一年）：月度通胀率大多在 1.3%–5.7%；一年里顶到上限的天数从 234 降到 30（见四、2）。

## 四、可比性与遗留

1. **改变所有默认 run** → 新增可比性版本 7（`gaworld/core/comparability.py`）。版本 ≤ 6 的 run 在收入、财富、恩格尔系数、储蓄率、
   以及依赖收入的情绪 / 压力上都与之后的 run 不可比，平行世界合并、研究闭环、Bench Track C 都会按版本拦住。
2. **（已改，见 `2026-10-03-layoff-recovery.md` §二）需求驱动的通胀把大病自付费算成需求。** 上面那 30 天是一次 2.1 万元的医疗急症（3 人里 1 人）进入 30 天消费窗口造成的；
   人口多时会被摊薄，但大病不是需求拉动。是否把 `healthcare` 的急症支出排除在需求之外，另行决定（该机制默认关）。
3. **（已改，可比性版本 8，见 `2026-10-03-layoff-recovery.md` §一）随机裁员的收入损失是永久的。** 恢复期结束后只有「失业」人生事件带来的失业会按原职业重新就业；随机裁员砍掉的 50–85%
   只能靠之后的加薪（或换工作事件）慢慢补。按月解释后一年里约 11% 的人碰上（默认周期），所以 p10 是 0.51。是否让随机裁员也在恢复期后回到原工资带，另行决定。
4. `shocks.bonus_month_prob` 在配置里有，代码里没有任何地方读它（顺带发现，未动）。
