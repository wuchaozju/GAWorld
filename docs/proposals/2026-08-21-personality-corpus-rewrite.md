# 设计提案：给 51 份人物设定补写独立的人格材料

> 前置：`docs/proposals/2026-08-20-big-five-personality.md`（大五人格子系统，已落地）。
> 本提案解决那份文档 §11.6 遗留的两件事：语料覆盖率过低，以及共线性闸门 FAIL。
> 状态：**已拍板**（D1 注入 r≈0.3 / D2 新增字段 / D3 先跑 5 人试水）。
> 采样器与生成脚本 `scripts/author_personality.py` 已就绪并做过零成本预演，语料未动。见 §10。

---

## 0. 一句话结论

**"把性格段写长一点"多半解决不了共线性**，因为问题不在长度，在推断方向。
建议把方向倒过来：**先独立采样 OCEAN，再据此生成人物设定的行为描述**，
而不是从人物设定反推 OCEAN。这一步同时解决覆盖率、共线性和幅度偏差三件事，
成本 51 次调用（比现有标定便宜 15 倍）。

---

## 1. 诊断

### 1.1 「性格与情绪特征」是标签，不是描述

51 份人物设定里，该字段的字数：

| 区间 | 份数 |
|---|---|
| ≤20 字 | 27 |
| 21–40 字 | 22 |
| 41–80 字 | 2 |
| >80 字 | 0 |

中位数 **20 字**，最短 11 字。实例：

```
Profile 09 赵子昂：创造导向，成就动机强。            （11 字）
Profile 07 沈嘉和：开放敏感，重视创作自由。          （12 字）
Profile 08 林思萌：情绪外显，对即时反馈依赖。        （13 字）
```

从「创造导向，成就动机强」里能读出开放性和尽责性的一点线索，读不出外向性、
宜人性、神经质。这就是覆盖率的直接成因——不是标定器保守，是材料里真的没有：

| 维度 | 有证据的居民 |
|---|---|
| N 神经质 | 35/51 |
| C 尽责性 | 26/51 |
| O 开放性 | 17/51 |
| E 外向性 | 13/51 |
| A 宜人性 | 11/51 |

### 1.2 五个状态变量就写在同一份 profile 里，紧挨着性格段

```
**性格与情绪特征**：开放敏感，重视创作自由。
...
**研究增强变量初始化**：
- policy_sensitivity：0.55
- platform_dependence：0.35
- risk_preference：0.65
- voice_propensity：0.50
- mobility_intent：0.55
```

标定脚本**没有**读到这几个数字（`parse_profile` 只取性格/日常/价值观三段）。
可是标出来的开放性与 `mobility_intent` 的相关仍然是 **r = +0.90**。
唯一的解释是：这一行散文和这五个数字，是同一个作者对同一个人的两种写法。
散文是那五个数的中文版。

### 1.3 五个状态变量本身就高度相关

| | policy | platform | risk | voice | mobility |
|---|---|---|---|---|---|
| policy_sensitivity | 1.00 | −0.27 | 0.17 | 0.36 | −0.13 |
| platform_dependence | | 1.00 | 0.54 | 0.27 | **0.68** |
| risk_preference | | | 1.00 | 0.40 | **0.78** |
| voice_propensity | | | | 1.00 | 0.40 |
| mobility_intent | | | | | 1.00 |

除 `policy_sensitivity` 外，其余四个基本是同一个「冒险／流动／平台化」因子的不同侧面。
这意味着**任何一个与其中之一强相关的特质，多元 R² 都会很高**——
闸门不是在挑刺，是在如实反映"这个维度已经在模型里了"。

### 1.4 所以"多写点"很可能没用

无论是人来补写还是让 LLM 补写，写手看到的都是同一份人物设定。
写出来的新段落大概率仍然是那五个数的展开，只是更长。
**长度提高覆盖率，但不改变共线性。** 这是本提案最重要的一句话。

## 2. 四个方案

| | 方案 | 解覆盖率 | 解共线性 | 代价 |
|---|---|---|---|---|
| **A** | **反向生成**：先采样 OCEAN，再据此写人物设定 | ✅ 100% | ✅ 构造上保证 | 语料要改；51 次调用 |
| B | 只补写，仍走反向标定 | ✅ | ❓ 很可能不解决（见 §1.4） | 语料要改；765 次调用 |
| C | 不动语料，把 voice/mobility 移出闸门对照集 | ❌ | ⚠️ 只是改判据 | 零成本，但等于给结论让路 |
| D | 反过来由 OCEAN 重新生成五个状态变量 | ✅ | ✅ | 否决：这五个变量已被经济/干预/交通等子系统消费，重算会改变所有既有实验 |

**推荐 A。** B 的问题在 §1.4；C 是自欺——把"结果型"变量踢出对照集这个理由站得住脚，
但它没有让人格多携带一点信息，只是让报告好看；D 的破坏面太大。

## 3. 方案 A 细节

### 3.1 采样：独立，还是带上文献量级的真实相关？

数值实验（n=51，5 个自变量，调整后 R²，闸门线 0.50）：

**完全独立采样**（2000 次抽样）：

| 中位数 | p90 | p99 | 最大 |
|---|---|---|---|
| 0.00 | 0.10 | 0.21 | 0.37 |

从不触线，余量很大。

**刻意注入与 `risk_preference` 的真实相关**：

| 目标 r | adj R² 中位数 | p95 |
|---|---|---|
| 0.2 | 0.04 | 0.20 |
| 0.3 | 0.08 | 0.27 |
| 0.4 | 0.15 | 0.35 |
| **0.5** | **0.24** | **0.44** |
| 0.6 | 0.36 | 0.54 ← 开始失败 |

也就是说，**可以一直保留到 r ≈ 0.5 的真实相关而仍然通过闸门**。
这一点很关键：现实里开放性与感觉寻求／风险偏好的相关就在 0.3–0.4，
把人格做成与状态变量**严格正交**反而不真实。
当前 r = 0.90 的问题不是"有相关"，是"是同一个东西"。

> **待拍板 D1**：采样时注入 r ≈ 0.3 的相关（更真实，仍安全通过），
> 还是完全独立（最保守，但人为地把人格与风险偏好切断）？

### 3.2 生成：约束比提示词更重要

每人一次调用，输入 = 采样到的五维 + 该 profile 的**不可变事实**
（姓名、年龄、性别、户籍、职业、日常生活、价值观、家庭），输出 = 一段 60–120 字的描述。

四条硬约束：

1. **写可观测行为，不写标签。** 不许出现"开放性高"「外向」「尽责」这类词，
   也不许出现分数。要写"会绕路去看新开的店"这种能被观察到的事。
   （理由与锚句相同：中文语料里人格标签没有稳定的行为先验。）
2. **五个维度各至少一句**，包括分数接近 0 的维度——那不是"不写"，
   而是要写成"在这件事上没什么突出倾向"，否则覆盖率问题会以另一种形式回来。
3. **不得与不可变事实矛盾**，但**允许与五个状态变量张力共存**。
   一个 `risk_preference=0.2` 的人可以在人格上偏开放——真人本来就这样，
   而且这正是我们要的增量信息。这条要写进提示词，否则模型会自动去对齐。
4. **不得重述已有的日常生活段。** 那一段描述"做什么"，新段落描述"怎么做、为什么"。

### 3.3 落点：新增字段，不改写原字段

建议在 profile 里**新增** `**人格与行为倾向**`，保留原 `**性格与情绪特征**` 不动。

理由不是保守，是有具体依赖：`gaworld/behavior/dynamic.py` 的
`_PERSONALITY_KEYWORDS`、`generate_social_interrupts` 的 `is_extrovert`、
`economy/finance.py` 的 `_infer_wealth_drive` 都在对这段文字做关键词匹配，
`_heuristic_schedule` 也从中读作息线索。改写它等于同时改动四个子系统的输入，
而这些改动的效果无法与人格本身的效果分开——正是本项目一直在避免的事。

需要同步的代码点（都很小）：

| 位置 | 改动 |
|---|---|
| `gaworld/sim/agents_loader.py::parse_profile` | 多解析一个字段 |
| `generative_city_sim.py::build_agent` | 多带一个键 |
| `gaworld/personality/anchors.py::personality_line` | 决定新段落是否与锚句并存（见 §3.5） |
| 6 处 prompt 的角色资料块 | 各加一行 |

> **待拍板 D2**：新增字段（推荐），还是直接把新描述并进 `性格与情绪特征`？

### 3.4 反向标定这一步可以整个删掉

方向倒过来之后，`data/agents_big5.csv` 的值就是采样值本身
（`source=sampled_authored`），不需要再让 LLM 从自己写的文字里读回分数——
那一步只会引入噪声，而且读回来的值与写进去的值不一致时，谁对？

`scripts/calibrate_big5.py` 保留，用途变成：
（a）为**外部导入的** agent（社交媒体导入那条路）标定；
（b）作为对照臂——用它对新语料重标一遍，与采样真值比对，
就得到一个"标定器准不准"的直接测量。这比现在的任何间接检验都硬。

### 3.5 一个需要一并想清楚的事

新段落是由 OCEAN 写出来的，所以它**已经携带了人格信息**。
那么 `prompt` 通道的锚句就与它部分重复了。两种读法：

- 锚句仍有价值：它按场景只挑相关的两维，起的是**强调**作用，
  而 profile 段落是每次都在的背景。
- 或者：`prompt` 通道可以默认关掉，让 profile 文本承担，
  这样 A4 消融臂的语义反而更干净（= profile 之外**额外**的提示词推力）。

这不是本提案要定的事，但改完语料后应当重新评估，否则会出现同一件事说两遍。

## 4. 不矛盾怎么保证

生成之后加一道**独立**的检查（不是同一次调用里自查——自查形同虚设）：

一个新的调用，输入 = 完整 profile（含新段落）+ 家庭记录，
输出 = `{"conflicts": [...]}`，专门找"新段落与不可变事实打架"的地方，例如
"喜欢深夜外出"配上"与学龄前子女同住且早班"。有冲突的重新生成，
最多重试两次，仍冲突的转人工，并在报告里列出来。

注意这道检查**只查与不可变事实的矛盾**，不查与五个状态变量的张力——
后者是特性不是缺陷（§3.2 约束 3）。

## 5. 验收

改完语料后必须重跑，全部是零 token 或极低成本：

| 检查 | 判据 |
|---|---|
| 覆盖率 | 五维全部 51/51（采样值天然全覆盖，此项等于自动通过，但仍要打印以防退化） |
| 共线性 `big5_collinearity.py --annotate` | 每维 adj R² < 0.30；`redundant` 列应当被清空 |
| 效应上限 `big5_effect_ceiling.py` | 幅度 0.30 仍在 S/P 两档带内（人群 sd 会从 0.45–0.74 回到 1.0，见 §6） |
| 不矛盾抽检 | 51 份全查 + 人工抽 10 份 |
| 标定器对照（可选） | 用 `calibrate_big5.py` 重标新语料，与采样真值的相关应显著为正 |
| 全量测试 | 与基线同一组失败（当前 8 个存量） |

## 6. 顺带解决的第三件事：幅度偏差

`style_fit_amplitude = 0.30` 是在 **sd = 1.0** 的合成人群上量出来的。
实际标定人群的 sd 只有：

| 维度 | 实际 sd | 非零人数 |
|---|---|---|
| O | 0.58 | 15/51 |
| C | 0.60 | 22/51 |
| E | 0.48 | 10/51 |
| A | 0.45 | 7/51 |
| N | 0.74 | 28/51 |

也就是说**当前跑出来的人格效应，比闸门测到的上限还要弱一半左右**——
不是设计如此，是覆盖率不足的副作用。补满之后 sd 回到 1.0，
0.30 这个值才真正对应闸门量到的那条曲线。这一点在改完之后要重新确认，
不排除届时需要把幅度调小。

## 7. 风险

1. **不可逆地改动核心语料。** `data/hangzhou_profiles_with_names.md` 是本项目
   所有实验的输入。改完之后**旧 run 与新 run 在人格维度上不可比**
   （情绪轨迹已经因为 D6 不可比了，这次是第二处）。
   建议：改之前把旧文件复制成 `data/hangzhou_profiles_with_names.v1.md` 并在
   CHANGELOG 记明分界。
2. **人物会变得"更像被设计出来的"。** 由五个数生成的描述，可能读起来比手写的
   更规整、更像模板。这正是 §3.2 约束 1 和 4 要压的风险，但只能靠抽检发现。
3. **张力可能读起来像矛盾。** `risk_preference=0.2` + 高开放性的人，
   在日记里可能显得别扭。这是有意为之（§3.2 约束 3），但要提前认下来。
4. **51 人改了，500 人合成人口没改。** `population/synth.py` 生成的
   `personality_bits` 本来就是状态变量的函数，那条路径走的是先验采样，
   本来就没有共线性问题；但两套人群的人格来源会不一致。
   → **待拍板 D3**：合成人口是否也改成"先采样、再生成描述"以保持一致？

## 附录：为什么不建议方案 C（移出对照集）

把 `voice_propensity` 和 `mobility_intent` 从闸门对照集里剔除的理由是站得住的：
它们是**行为倾向**，更像人格的下游结果，而不是与人格竞争的同级构念。
算了一下真剔除会怎样（调整后 R²，仍只在有证据的子集上）：

| 维度 | 全部五个 | 剔除 voice + mobility | 只留 policy + platform |
|---|---|---|---|
| O 开放性（n=17） | 0.77 | 0.70 | **0.59** |
| C 尽责性（n=26） | 0.53 | 0.42 | 0.41 |
| E 外向性（n=13） | 0.74 | **0.27** | 0.19 |

结果比预期更有意思，也更不利于方案 C：

- **E 的冗余是一处具体配对**（`voice_propensity`，r = 0.76）。剔掉就过了。
- **O 的冗余是弥散的**：哪怕只留 `policy_sensitivity` 和 `platform_dependence`
  两个变量，adj R² 仍有 0.59，照样 FAIL。开放性重叠的不是某一个变量，
  是 §1.3 里那个「冒险／流动／平台化」因子整体。

所以方案 C 救得了外向性，救不了开放性——而开放性正是重叠最严重的那一维。

而且这不改变一个事实：在当前语料下，知道一个居民的 `mobility_intent`
就几乎等于知道了他的开放性（r = 0.90）。无论把哪个叫做"原因"，
**模型里都只有一份信息**。闸门量的是信息增量，不是因果方向。
改判据能让报告通过，不能让人格多说出一句新话。

## 10. 拍板与预演（2026-08-21）

### 10.1 裁定

| # | 裁定 |
|---|---|
| D1 | **注入 r ≈ 0.3 的真实相关**，只给两个有文献依据的配对：开放性↔`risk_preference`、外向性↔`voice_propensity`。C/A/N 与这五个变量之间没有可引用的既有结论，因此独立采样，不编造配对 |
| D2 | **新增 `**人格与行为倾向**` 字段**，原 `性格与情绪特征` 一字不动 |
| D3 | **先跑 5 人试水**，确认文风与不矛盾之后再动全量 |
| D4 | 现有 LLM 标定版 CSV 保留为对照臂 |
| D5 | `prompt` 通道是否仍默认开，改完语料后再评估 |

### 10.2 两处实现上的取舍

**相关注入用残差化，不用直接混合。** `z = r·s + √(1−r²)·e` 只在 e 与 s 恰好正交时
才给出准确的 r；n=51 下 r 的标准误约 0.14，同一个公式换个种子实测值会在 0.16–0.44 之间跑。
改成先把先验抽样对状态变量做残差化再混合，实测相关**恰好**落在 0.30，与种子无关。

**目标行为直接复用运行时的锚句**（`gaworld/personality/anchors.py::ANCHORS`），
一字不改地喂给生成器，并且用主题标签（对新事物／做事方式／社交倾向／与人相处／情绪反应）
而不是维度名。前者保证 profile 里的描述和运行时注入提示词的句子说的是同一个人，
后者避免模型把标签原样写回去。

### 10.3 预演：不花一次调用就能确认的三件事

采样器跑完全量（51 人），把采样值直接送进两道闸门：

```
dim         n   policy  platform  risk   voice  mobility   adjR²  verdict
O 开放性   51     0.19     0.18    0.30    0.23    0.31      0.05  ok
C 尽责性   51     0.05     0.19    0.20    0.16    0.28      0.00  ok
E 外向性   51    -0.01     0.18    0.20    0.30    0.28      0.03  ok
A 宜人性   51    -0.02    -0.03    0.02    0.10    0.15      0.00  ok
N 神经质   51    -0.05     0.12    0.06   -0.10   -0.00      0.00  ok
worst adjusted R² = 0.05   → 全部通过
```

1. **覆盖率**：五维全部 51/51（对比现状 N 35 / C 26 / O 17 / E 13 / A 11）。
2. **共线性**：最差 adj R² 从 **0.77 降到 0.05**，闸门返回 0。
   注入的两处相关如实出现在表里（O↔risk 0.30、E↔voice 0.30）；
   连带的 O↔mobility 0.31 是因为 mobility 与 risk 本身相关 0.78——这是真实结构，不是重复。
3. **效应上限**：人群 sd 回到 1.00（现状 0.45–0.74），幅度 0.30 仍然 PASS。
   §6 说的「当前效应比闸门量到的弱一半」因此会自动消失。

**剩下唯一的未知是文风**——这正是 5 人试水要看的，也是唯一必须花调用才能知道的部分。

### 10.5 试水第一轮（5 人）与据此做的修正

文风的**下限**是好的：五段里没有一处出现人格标签，也没有出现分数，
写出来的都是能被看见的事——「催的人一问她就笑着把时间往后挪」、
「连中午点外卖都反复切换 app 拿不定主意」、「散场时主动叫车把喝多的捎上」。
方向也对，抽查五人的五维与文本一一吻合。

但有四个问题，都会在 51 份的尺度上变成系统性缺陷：

| # | 问题 | 实测 |
|---|---|---|
| 1 | **照抄提示词的措辞** | 3/5。提示词里举例说"要写「会绕路去看新开的店」这种事"，03 号第一句就是「陈一航会绕路去看新开的店」，05 号是「路过新开的店会进去看一眼」；02 号照搬了锚句原文「独处超过两天」 |
| 2 | **五条同序，读成清单** | 5/5 都是 O→C→E→A→N。03 号尤其明显：五个短句，一句一维 |
| 3 | **字数全线超标** | 目标 60–120 字，实际 160–285 字，5/5 超出，最多 2.4 倍 |
| 4 | **校对器把"没有矛盾"写进了矛盾数组** | 03 号那条的正文是「整体未发现与已确定事实不可同时成立的矛盾」，却被列为一处矛盾。51 份跑下来这个计数会变成噪声 |

修正：

1. **提示词里不再给具体例句**，改成描述性质（"旁人能看见的具体动作、场合、口头禅，
   放在这个人自己的生活场景里"），并明写"不要照抄这份提示词里的任何措辞"。
2. **五条目标的顺序按 agent 确定性打乱**，并明写"不要按上面的顺序逐条写"。
3. 字数带收紧为 **90–150 字**，并明写超过算不合格。
4. **校对器的 JSON schema 改成必须引用互相打架的两句话**
   （`{"from_facts": ..., "from_paragraph": ...}`），缺任一侧的条目在代码里直接丢弃。
   这样"未发现矛盾"这种形状根本写不进数组。

另外加了一道**零成本的机械检查**，每份生成完就跑，不合格自动重试一次：
标签泄漏、照抄锚句、字数越界。拿第一轮的五份回测，**5/5 都会被拦下**
（顺带查出第三处照抄：02 号的「独处超过两天」，人眼漏了）。

检查结果会写进预览文件，所以下一轮不需要靠人一段段读来发现这类问题。

### 10.6 试水第二轮：三个问题解决了，一个没有

| 问题 | 第一轮 | 第二轮 |
|---|---|---|
| 照抄提示词措辞 | 3/5 | **0/5** |
| 五条同序、读成清单 | 5/5 | **0/5**（01 从情绪起、02 从做事起、03 从社交起、04 从做事起、05 从做事＋情绪起） |
| 校对器把「没有矛盾」写进矛盾数组 | 有 | **0 处误报**，五份全干净 |
| 字数超标 | 5/5（160–285） | **5/5（193–348）——没解决** |

文风本身明显变好，写的是这个人自己的生活：「文泽路那家咖啡店」「下沙这片」
「余杭出了个新的人才补贴申报通道，他点开看了一遍，合上电脑没动」。
这是**写出来的人**，不是生成出来的人。

#### 字数：换个提示词是没用的

第二轮明写了「90–150 字，超过算不合格」，并且不合格自动重试一次。结果：
五份第一次全部超标（239–325 字），**五次重试全部仍然超标，其中两份比第一次更长**。

结论很直接：**重新采样一个写长的模型，只会再得到一段长的**。
字数不是「这次运气不好」，是这个模型在这个任务上的稳定行为。

#### 改法：把两类失败分开处理

- **标签泄漏 / 照抄措辞 / 生成为空** → 重新生成。这些是坏样本，重采样有意义。
- **超长** → **压缩**。压缩是另一个任务，而且是模型确实擅长的任务：
  内容已经定了，只需要删。而且它**会收敛**——每一轮都从更短的文本出发，
  不像重新生成那样每次从同一个分布里重抽。

生成侧同时把「90–150 字」换成「**写 4 到 5 句话**」。
句数是模型真正会遵守的约束，字数不是；而且句数少于维度数，本身就在逼它合并，
顺带压住第一轮那种一句一维的清单感。

#### 上限为什么定 180

不是拍的。agent 1 现有的角色资料块（职业 62 + 性格 61 + 日常 56 + 价值观 41 + 标签）
约 **300 字**。加一段 280 字的人格描述，这个块直接**翻倍**——
而「人物志压过当天处境」正是大五提案一开始就要避免的失真，
锚句限制每段最多两条也是同一个理由。180 字让这个块增加约 60%，处境仍然是主角。

顺带说明：这也是为什么不能干脆接受 280 字了事。

预计成本随之变成：51 次生成 + 51 次校对 + 超长的另加 1–2 次压缩 ≈ **155 次**
（原估 118 次；仍远低于旧标定的 765 次）。

### 10.7 试水第三轮：句数约束也没用，真正的病因是"要写的太多"

第三轮改成「写 4 到 5 句话」，结果**更长**：首次生成 307–673 字（第二轮是 239–348），
02 号写出 673 字。句数约束不控制长度，它只是让模型写更长的句子。

压缩确实有效但会**触底**：329→232、673→479、419→308、308→201、307→262，
每一轮砍掉约 15–35%，第二轮压缩几乎不再变短。原因是压缩提示词写着
「五条行为倾向一条都不能丢」——那是一条**内容下限**，压到下限就压不动了。

所以问题不在提示词的措辞，在于**我要求它说的东西本来就太多**。

#### 病因：「五条都要写到」这条要求是从旧方向抄过来的

§3.2 约束 2 要求五个维度都写，包括分数接近 0 的，理由是"否则覆盖率问题会以另一种形式回来"。
**这条理由在新方向下不成立**：分数是采样出来并冻结在 CSV 里的，覆盖率天然 100%，
散文只是下游产物。给一个 z = −0.10 的维度写一句「他在这方面不偏不倚」，
增加字数、零信息量。

实测这就是长度的主要来源。以 01 号为例（O −0.35、C +0.48 都不显著）：
232 字里有约 80 字花在这两个维度上，其中「周末偶尔在客厅瑜伽垫上做拉伸」
还同时违反了「不要复述日常生活」——因为它得找点东西来填。

而且这条要求与运行时的设计**自相矛盾**：`anchors.py` 早就用 `floor_z` 跳过不显著的维度，
理由一模一样。

#### 改法：只写显著维度（|z| ≥ 0.5）

采样人群的实际分布：**平均每人 3.0 个显著维度**，范围 1–5，没有人是 0 个。
3 个维度、一条一句，180 字是宽裕的，不再需要跟模型拉锯。

配套：提示词里的条数、句数、字数上限都按实际条数动态填；
明写「没列出来的方面一个字都不要提——不要补'他在某某方面不偏不倚'，那是凑字数」；
压缩提示词的内容下限也从"五条"改成"原文写到的每一个倾向"。

#### 顺带：校对器这轮抓到了第一个真矛盾

01 号：设定「周末多用于补觉」↔ 段落「刷技术博客刷到半夜，又把睡眠往后推了两小时」。
格式规范（两侧都有原话引用），是个真问题，不是第一轮那种把「未发现矛盾」写进数组的误报。
schema 的收紧生效了。

### 11.2 一个我没预料到的问题：新旧两段人格描述互相矛盾

不矛盾检查比对的是"不可变事实"（姓名／年龄／职业／居住／日常生活／价值观），
**没有把 `性格与情绪特征` 列进去**——因为 D2 决定不动那个字段，我就没把它当成需要对齐的对象。

| | 旧行 | 新段落 |
|---|---|---|
| 28 沈丽娜 | 外向、**对不确定性耐受度较高** | 客户没当场点头，「回家路上就忍不住把'我再想想'翻来覆去地嚼，连晚饭吃什么都没心思定」 |

### 11.3 裁定：提示词只渲染新段落

`personality_line` 在有 `behavior_tendencies` 时**用它替代**旧行，而不是并列。

**哪一个该赢不是掷硬币**：采样分数驱动 `rules` 通道，新段落是与之一致的那份描述。
若提示词仍显示旧标签，`prompt` 通道与 `rules` 通道就在描述两个不同的人，
A3/A4 消融臂会失去意义。

`agent["personality"]` 本身一字未动，所以四个做关键词匹配的子系统
（`dynamic.py` 的原型表与 `is_extrovert`、`finance.py` 的 wealth drive、
`_heuristic_schedule` 的作息线索）行为完全不变——**D2 的真实要求是保护它们，
不是保护那一行在提示词里的出场**。

代价：51 条旧行里有 11 条带具体情境触发（如"在绩效评估、裁员传闻时期会出现明显焦虑"），
这部分不再进提示词。考虑到其余 40 条基本是纯标签、且新段落本身就是 148 字的行为描述，
这个损失可以接受。

### 11.4 教训：不可变事实的边界要按"会不会一起进提示词"划，不是按"会不会被改"划

我把 `性格与情绪特征` 排除在校验之外，理由是"这个字段不改"。
但校验要防的是**输出与上下文打架**，而上下文是"所有会一起出现在提示词里的东西"。
字段改不改，和它要不要参与一致性检查，是两个问题。
```
`scripts/author_personality.py::IMMUTABLE_FIELDS` 若日后再加生成任务，
判断标准应当是"会不会和产物同时出现在同一个提示词里"。
```

| N 神经质 | **+0.50** | +0.60 (n=10) | −0.42 (n=12) |
| C 尽责性 | **+0.39** | +0.45 (n=11) | −0.36 (n=11) |
| A 宜人性 | **+0.32** | +0.42 (n=12) | +0.00 (n=12) |
| O 开放性 | +0.18 | +0.27 (n=11) | +0.00 (n=12) |
| E 外向性 | **−0.13** ← 一开始是负的 | | |

E 为负值得追一下。查下来是**我的词表错了，不是语料错了**：
第一版 E 词表用的是名词（约／聚／局／饭局），而这些名词在高外向和低外向的句子里
都会出现——分不清"去"和"推掉"。两位最低 E 的居民实际写的是：

```
21 E=−2.23  饭局上有人拉他去唱K，他总说店里有事得先走，饭点过了一小时人就溜号
46 E=−1.83  同事约她下班临时聚餐，她说"我今晚有安排"，宁可绕路去便利店买一份饭团
```

教科书级的低外向，但每一句都含「饭局」「约」「聚餐」。
换成带方向的短语（主动搭话／找借口推…）之后，E 的 r 从 **−0.13 变成 +0.19**。

结论：五个维度的方向在免费方法能分辨的范围内都是对的；
E 仍然最弱，但那是关键词计数读不出「说'我今晚有安排'是在拒绝」这层语义的局限，
不是语料的问题。**这也是为什么 §5 把"标定器对照"列为验收项而不是可选项——
只有语义级的重标才能真正回答这个问题。**

### 11.7 未了

- 标定器对照臂（765 次调用）仍未跑。

## 12. 对照臂结果（2026-08-21，765 次调用）

用 `scripts/calibrate_big5.py --compare` 让一个**独立的打分器**重读生成出来的
`人格与行为倾向` 段落，看它能不能读回当初写进去的分数。

### 12.1 跑之前先改了一处，否则这次测量作废

标定器的 `_context` 拼的是「性格与情绪特征 + 日常生活 + 价值观」——**没有新段落**。
照原样跑，它评的是那条已知与采样分数矛盾（9/51）的旧标签，相关必然接近零，
而我会误判成"生成器没把分数编码进去"。

改成：有 `人格与行为倾向` 时**只评这一段**（与 `personality_line` 的规则一致）。
日常生活／价值观也去掉了——它们当年是因为性格行只有 20 字才加进来凑材料的，
现在只会把**产生了状态变量的那份作者意图**重新拖回一个"整个目的就是独立于它"的测量里。

另加一道守护：`--compare` 指向 `--out` 会被拒绝，免得覆盖真值。

### 12.2 主结果：生成器通过

事先定的判据是「有证据 r ≥ 0.6 为强」。五维全部达标：

| 维度 | 全部 r | 有证据 r | **只看刻意写了的格子** | n |
|---|---|---|---|---|
| N 神经质 | 0.83 | 0.85 | **0.89** | 36 |
| O 开放性 | 0.79 | 0.80 | **0.87** | 30 |
| C 尽责性 | 0.72 | 0.72 | **0.87** | 29 |
| E 外向性 | 0.67 | 0.68 | **0.76** | 26 |
| A 宜人性 | 0.59 | 0.60 | **0.69** | 32 |
| **合计** | | | **0.79** | **153** |

最后一列才是对生成器的公允测量：生成器只写 |z| ≥ 0.5 的显著维度，
其余的格子文本里根本没东西可读。**r = 0.79 意味着分数确实被编码进了行为描述，
而且一个没看过分数的读者能把它读回来。** traits→text 这个前提成立。

分档看也稳：|z| 落在 [0.5,1)、[1,1.5)、[1.5,∞) 三档的 r 分别是 0.83 / 0.80 / 0.88。

### 12.3 副产品：打分器本身有个过度声称的缺陷

事先定的第二条判据没达标。生成时实际写进去 **155** 格，
打分器却把 **225** 格标成"有证据"——多出来的 72 格：

- 相关 **r = −0.01**（刻意写的那 153 格是 +0.79）
- 打分绝对值均值 0.59–0.85，**不是中点**，是看起来很确定的值
- 重标 sd **1.49**，而这些格子的真值 sd 只有 0.31 —— 在真值最窄的地方给出最宽的分布

**先排除了统计假象。** 这些格子按定义 |z| < 0.5，取值范围被截断，
而截断本身就会把相关往零压。用 Thorndike Case II 修正算了一下：
已知 [0.5,1) 档 r = 0.83、真值 sd = 0.76，把 sd 压到 0.31 后**单靠截断**预期 r ≈ 0.52。
实测 −0.01，比预期低 0.53。**截断解释不了这个差距**，剩下的是打分器自己加的东西。

看它给的"证据"就明白了——**跨维度串味**：

```
agent 1  O 真值 −0.35  打分 2.0  证据「他自己来、等到截止才填、走固定流程」
                                   ← 这是为低宜人性和低尽责性写的场景
agent 3  C 真值 +0.11  打分 6.0  证据「已改到第三版，绕路还U盘，当天试过示波器」
                                   ← 这是为高开放性写的场景
agent 2  C 真值 +0.05  打分 4.0  证据「材料未涉及尽责性维度」← 却仍标 stated=true
```

### 12.4 试过的修法都不work，如实记下来

| 规则 | 判有证据 | 真的写了 | 凭空的 | 精确率 |
|---|---|---|---|---|
| 现状（任一次 stated） | 225 | 153 | 72 | 68% |
| + 证据自称「未涉及」则否决 | 223 | 152 | 71 | 68% |
| + 还要求证据非空 | 223 | 152 | 71 | 68% |
| 多数票（2/3）+ 上面两条 | 201 | 142 | 59 | 71% |
| 一致票（3/3） | 181 | 134 | 47 | 74% |

**投票收紧几乎没用**，因为三次重复高度一致（255 格里 181 格是 3/3 票）——
模型是**自信地**过度声称，不是在犹豫。
文本关键词否决也没用：我的 `未涉及|看不出` 正则大多命中的是**合法证据**里的
「脸上看不出什么波动」（那正是低神经质的真凭证），既无效又有害。
一致票能把精确率抬到 74%，代价是丢掉 12% 的真信号。

### 12.5 这件事的实际影响与结论

对 51 位居民**没有影响**——他们的分数是采样出来的，标定器只是读者。

但 `calibrate_big5.py` 还有一个生产用途：**给外部导入的 agent 打分**
（社交媒体导入那条路）。那里没有真值兜底，按这次的比例，
**约三成的格子会是凭空生成的，且带 sd 高达 1.49 的自信度**。
另外还有系统性偏移（Pearson 看不到）：宜人性 +0.39、开放性 −0.33、神经质 −0.29。

**建议**：导入路径上不要单独信任标定器的 `stated` 标志。
要么只采纳一致票（3/3）并接受 74% 的精确率，要么改成对每个维度**单独提供只含该维度
相关句子的材料**（把串味从输入端切断，而不是在输出端筛）。后者更贵但更对。
这不在本提案范围内，另开。

## 13. 为 D5 做准备时先发现了两处接线缺陷（2026-08-21）

D5 是「prompt 通道是否默认开」。要量它就得先能量——结果一查，**这个通道当时根本
量不了**：它只接了三分之一，而它的配置块是空转的。

### 13.1 缺陷一：9 处提示词仍在渲染那条已被裁定不再渲染的旧行

§11.3 的裁定是「提示词只渲染新段落」，理由是新旧两段在 9/51 份档案里互相矛盾。
但裁定只落到了 6 个调用点（`_news.py:571`、`goals.py:237`、`_diary.py` 的
`anchor_block`，以及 `generative_city_sim.py` 里的 3 处）。
另外 9 处照旧拼 `f"性格与情绪特征：{agent.get('personality')}"`：

| 文件 | 函数 | 干什么 | 现接到的场景 |
|---|---|---|---|
| `sim/_action.py` ×2 | `_llm_generate_actions`、动作空间打分 | **主决策路径** | `action` (c,n) |
| `sim/_news.py` ×2 | `info_seek_and_store`、摘录改写 | 信息摄入 | `news` (o,n) |
| `sim/_rag.py` ×2 | RAG 冷启动的外部知识 | 长期背景知识 | `news` (o,n) |
| `cognition/realism.py` ×1 | `build_daily_intentions` | 当天意图 | `routine` (c,e) |
| `generative_city_sim.py` ×1 | `_rewrite_weekend_schedule_from_profile` | 周末日程改写 | `routine` (c,e) |
| `generative_city_sim.py` ×1 | `infer_event_effect` | 政策事件影响推断 | `news` (o,n) |

最刺眼的是 `_action.py`：`SCENES` 里 `action` 这一项在包内**从没被调用过**
（只有顶层模块接了一处），而它恰恰是本方案「主战场在规则层，prompt 层作对照」
里那个要对照的决策。换句话说，A4 消融臂当时就算跑了，覆盖也是残缺的。

**最后两处是被我自己的检索方式漏掉的。** 第一遍 `grep` 只扫了 `gaworld/`，
而 `generative_city_sim.py` 是仓库根上的历史顶层模块、不在包里——
它已经接了 3 处，看上去"这个文件是接过的"，于是没再核。
真正暴露它的是 `test_daily_routine_context` 那两个既有失败用例的报错正文里
赫然印着 `性格与情绪特征：稳重`。**教训：接线类改动的完备性判据只能是
"全仓库检索该字面量为空"，不能是"相关包检索为空"。**

已全部改为 `personality_line(agent, scene)`。改完全仓库（除 `legacy/`、`backup/`、
测试与脚本）检索 `性格与情绪特征：{agent` 为空。

`scripts/dev/agent_capability_test.py` 里还有一处，是能力探针不是生产路径，
本次没动——改它等于改探针在探什么。

两点如实记下：

- `_news.py` 那两处沿用历史遗留的 `"\\n".join(...)`（字面反斜杠 n，不是换行）。
  `personality_line` 返回的是真换行，于是同一段 profile 里两种分隔符混用。
  这在已接线的 `:571` 上早就是这样了，本次保持一致、没有顺手"修"——
  改它会静默改变提示词格式，属于另一件事。
- `social/network.py` 的场外社交档案生成器按 key 循环拼 `personality`，
  没有标签行、也不渲染新段落，所以**不构成同一段提示词内的自相矛盾**，
  只是用了过时素材。是另一档次的问题，本次没动，记在这里。
- `SCENES["social"]` 至今无处可接——模拟器还没有"社交决策"这种 LLM 提示词。
  保留条目，并加了一条测试：**再有第二个场景变成死条目就会红**。

### 13.2 缺陷二：`personality.prompt.*` 是个空转旋钮

`render_midpoint / render_spread / strong_z / max_dims` 四个参数在
`config_docs.py` 里有中文说明、在 `settings/personality.py` 里有值，
而 `anchors.py` 的函数签名里写的是**同样数值的字面量默认参数**。
于是：行为是对的，配置是死的——改配置什么也不会发生。

这种缺陷在日常使用里完全看不见，对消融却是致命的：**消融就是拧旋钮**。
一个拧不动的旋钮会让 A4 得出「怎么调都没差别」，而那是接线的结论，不是人格的结论。

修法沿用本方案既有的架构约束（`traits.py` / `anchors.py` 是只依赖标准库的叶子模块，
不许读 CONFIG）：plugin 在 `agents.built` 时把旋钮拷到 agent 记录上，
读侧从记录取默认值，显式关键字仍然优先（脚本扫参数用）。
顺带把一直硬编码在 `anchors.py` 里的 `floor_z` 也提成配置项——见下，它是 D5 的分水岭。

验证（51 人 × 5 个 prompt 场景，数锚句条数）：

| 配置 | 锚句条数 |
|---|---|
| 默认 | 303 |
| `max_dims = 1` | 216 |
| `floor_z = 0.5` | 272 |
| `render_midpoint = 1.2` | 129 |
| `render_spread = 0.05` | 317 |
| 记录里没有 `prompt` 键（老记录） | 303 ← 向后兼容 |

### 13.3 零成本证据：语料重写之后，锚句还剩多少活干

接线修完，D5 才能问。先不花调用能确定的（`scripts/big5_prompt_coverage.py`，
可复现，`--floor-z` 可扫）：

**锚句写的维度，段落基本都已经写过了。** 生成器写 `|z| ≥ 0.5` 的维度（`FLAT_Z`），
锚句的门槛是 `|z| ≥ 0.25`（`floor_z`）再按概率抽。两条线一比：

| 场景 | 维度 | 有锚句的人 | 锚句条数 | 段落已写（重复） | 段落没写（新信息） |
|---|---|---|---|---|---|
| routine | c+e | 43 | 56 | 48 | 8 |
| action | c+n | 44 | 65 | 60 | 5 |
| goals | o+c | 46 | 61 | 53 | 8 |
| news | o+n | 42 | 62 | 59 | 3 |
| social | e+a | 41 | 59 | 52 | 7 |
| **合计** | | | **303** | **272 (89.8%)** | **31 (10.2%)** |

**303 条锚句只来自 20 个模板句。** 39 位居民拿到**逐字相同**的
「做事方式：你做事有条理，被打断之后通常会想着把落下的补上。」，
另 39 位拿到逐字相同的低尽责句。语料重写整件事的目的，就是把
"泛泛的人格话术"换成"每个人自己的具体场景"；锚句是把泛泛那句又贴回了上面。

**成本**：非空锚块平均 42.6 字，摊到每次决策提示词约 **36 tokens**，
乘以每个 agent 每天的决策次数再乘以天数。

### 13.4 于是 D5 的问题变了

原来的 D5 是「人格要不要进提示词」。那个问题**已经被语料重写回答了**：
段落进了，而且 §12 量到独立读者能把分数读回来（刻意写的格子 r = 0.79）。
可以对照 `--apply` 之前那次标定：同一批 155 格、同一个打分器、同一个量表，
旧语料上 **r = 0.17**，且 100/155 格打分器直接给中点「材料未涉及」。
段落把分数编进行为描述这件事，是重写带来的，不是锚句带来的。

剩下的 D5 是个小得多、也具体得多的问题：

> 在段落已经用**这个人自己的场景**说过之后，再加一句**所有同极人共用的泛泛话**，
> 作为"本次决策要重点看这两维"的强调，能不能改变结构化选择？
> 值不值每次 36 tokens，和 20 句话反复出现在 51 个人身上的同质化风险？

**不能靠零成本推断答案。** 重复不等于无效——提示词里重复本来就抬显著性，
而"场景专属强调"正是锚句被设计出来要干的事。但它能声称的东西已经小了一圈：
不再是"人格靠它进模型"，而是"对已经说过的事再强调一次"。

### 13.5 A4 臂：配对提示词探针，≈1,400 次调用

不用跑整条模拟臂。锚句是提示词层面的干预，配对探针就能直接量它的边际推动，
成本约为 Track F 的 1/20。

**设计**

1. 只取锚句真的会渲染的格子：`routine` 43 人 + `action` 44 人 = **87 格**
   （这两个场景的结构化产出最干净：当天意图、动作选择）。
2. 每格构两版**真实提示词**，唯一差异是锚块在不在（`channels.prompt` 开/关）——
   段落两边都在。这一点是关键：量的是锚句的**边际**推动，不是人格的总效应。
3. 每版按生产温度采 **K = 8** 次，只读结构化字段（活动名、动作名），不读散文。
4. 合计 87 × 2 × 8 ≈ **1,392 次调用**。

**判据（先写死，再跑）**

| | 判据 | 不达标意味着 |
|---|---|---|
| 主 | 结构化选择朝锚句指的方向移动的格子 ≥ 53/87（单侧符号检验 p < 0.05） | 段落已经说完了，锚句是纯开销 |
| 上限 | 效应量不超过 S 档带宽 \|r\| ≤ 0.30（同 `big5_effect_ceiling.py`） | 人格压过处境，是失真不是成功 |
| 判别 | 与该决策无关的维度上不出现同向移动 | 量到的是"多了段文字"，不是"多了这段文字" |

**D5 按结果拍板**

- 主判据过 + 不超上限 → prompt 通道**默认开**，理由从"人格要进提示词"改成
  "场景强调有可测的边际效应"。
- 主判据不过 → **默认关**。段落已经把分数编码进去了，36 tokens × 每次决策是实打实的成本，
  20 句模板的同质化是实打实的风险，而收益量不出来。
- 过但超上限 → 不是简单开关，先调 `max_dims = 1` 或抬 `render_midpoint` 再测。

**还有第三种形态，但不建议先跑**：把 `floor_z` 抬到 0.5，锚句就只补段落没写的
那 31 格（"补空档"而非"再强调"），token 成本降到约 1/10。不先跑是因为它和
`floor_z` 的设计意图相反——那 31 格恰恰是 `|z|` 最弱的维度，
本来就是"这个人在这一维没有偏向，不该硬给他一个"。要跑也该在主臂之后。

### 13.6 本节改动清单

- `gaworld/sim/_action.py`、`_news.py`、`_rag.py`、`cognition/realism.py`、
  `generative_city_sim.py`：9 处改用 `personality_line(agent, scene)`。
- `gaworld/personality/traits.py`：新增 `PROMPT_DEFAULTS`、`prompt_knobs_of()`。
- `gaworld/personality/anchors.py`：`anchor_lines` 五个旋钮默认 `None`，回落到记录。
- `gaworld/personality/plugin.py`：新增 `_prompt_knobs()`，写进 agent 记录。
- `gaworld/settings/personality.py`、`config_docs.py`：新增 `prompt.floor_z` 及中文说明。
- `scripts/big5_prompt_coverage.py`：新增，本节所有数字的生成器。
- `tests/test_personality_big_five.py`：58 → **71** 个用例，新增三组：
  `TestPromptWiring`（旧标签不许再出现，含顶层模块／每个场景接线条数／
  死场景只许有 `social` 一个）、
  `TestPromptKnobsAreLive`（每个旋钮改记录都要看得见变化＋老记录回落）、
  `TestPromptChannelGate`（关掉通道只掉锚句，段落留着）。

按 §13.5 的设计实现为 `scripts/big5_prompt_ablation.py`。判据在脚本里写死，
每次运行**开跑之前先打印**——写在这里的意义就在于它不能事后挑。

### 14.1 实际规模

| | |
|---|---|
| 格子 | **87**（routine 43 + action 44，只取锚句真的渲染的） |
| 条件 | `plain` / `anchor` / `placebo`（反向锚句，30 格子样本） |
| 采样 | K = 8 |
| **调用** | 87×2×8 + 30×8 = **1,632 次** |

`plain` 是把 `channels.prompt` 在记录上关掉——操作员真会用的那条路径；
`placebo` 是在捕获到的提示词字符串上做替换，因为**没有任何配置能产出镜像锚句**，
而为了做实验去 `anchors.py` 里加一个反向渲染模式，等于把研究用的脚手架塞进生产代码。

### 14.2 三条不能省的守卫

**一、两版提示词必须逐字节只差锚句行。** 开跑前强制检查，不过就拒绝跑。
没有这一条整个实验不可证伪：任何别处的差异——重新抽的记忆命中、时间戳、
字典顺序——都会被算到锚句头上。当前 **87/87 通过**。

**二、方向不由我定。** 短语用 `_action_style_tags` 打标签，那是 `choose_action`
自己在决策点上用的同一个关键词分类器；方向用 `STYLE_LOADINGS`，那是驱动 rules
通道的同一张表。用生产分类器是一条**自觉的限制**，也正是这条限制可接受的理由：
**锚句若把模型的措辞推到了 `_action_style_tags` 看不见的地方，rules 通道也看不见，
那它就到不了决策。** 这里的零结果是"对决策循环而言的零"，不是"散文没变"——
后者是 voice 通道和 A3 的事。

**三、正负对照，用假 LLM，零调用**（`--self-test`）。
测不出植入效应的 harness，报零结果时什么也没证明；在纯噪声里造得出效应的 harness，
报阳性时同样什么也没证明。两个方向都得先演一遍：

| 对照 | 主判据 | 上限 | 判别臂 | 是否符合预期 |
|---|---|---|---|---|
| 正（植入 strength=0.9） | 87/87，p<0.0001 | 三维全部越界 | 29/30 反向 | ✅ |
| 负（strength=0，纯噪声） | 46/87，p=0.33 | 全部达标 | 12/30 | ✅ |

### 14.3 自检抓出了我自己写的判据里的一个缺陷

上限判据的第一版是：扫遍 (条件 × 维度 × 风格) 所有组合，取最大 |r|，超 0.30 判失败。
**负对照直接把它打红了**——在按构造完全没有效应的条件下，
`plain/n→avoidant` 在 n=33 时算出 |r| = 0.331。

原因不是数据有问题，是判据有问题：**取 16 个相关系数的最大值，不是效应量，
是多重比较的产物**。n=33 时 r 的标准误约 0.18，扫 16 个再取最大，
超过 0.3 是常事。

改成两条：

1. **预先指定**每个维度载荷最大的那一个配对（c→progress、e→social、n→restorative），
   逐维度报，不扫不取max；
2. 只在**单侧 95% 下界**越过 0.30 时才判超出。判据问的是"效应是否超出带宽"，
   点估计是错的工具；要求下界越界，等于要求这次运行**把超出量证出来**，
   而不是仅仅没能排除。

改完负对照三维全部达标，正对照三维全部越界。判据这才是能用的。

### 14.4 本臂只能回答 C／E／N

routine 是 (c,e)，action 是 (c,n)，并集是 **C/E/N**。**O 与 A 不在本臂范围内**——
它们要靠 goals=(o,c) 或 news=(o,n)，而那两个场景的输出用风格标签读得远没这两个干净。
脚本在 `--dry-run` 和结果表里都会把这句印出来。**D5 若据此拍板，就是按 C/E/N 的证据拍的**，
这句话应当跟着结论一起写。

### 14.5 判据的可检出范围（模拟，不是预测）

n=87 时符号检验判据是 k ≥ 52（59.8%）。以单次采样的 sd 为单位：

| 真实效应 d | 每格判对率 | 检出功效 |
|---|---|---|
| 0.00 | 49.9% | **2.2%**（假阳率，应在 α 附近） |
| 0.15 | 61.6% | 67.5% |
| 0.30 | 72.5% | 99.2% |
| 0.50 | 84.1% | 100% |

即：d ≥ 0.3 几乎必检出，d = 0.15 有约三分之二把握。**低于 0.15 的推动本臂看不见**——
这也是结论要带的限制条件，不是失败。

### 14.6 拍板规则（脚本自己会印）

- 三条全过 → prompt 通道**默认开**，理由改成"场景强调有可测且不过界的边际效应"。
- 主判据过、上限超 → **先别开**，降 `max_dims` 到 1 或抬 `render_midpoint` 再测。
- 主判据过、判别臂不过 → **先别开**，量到的可能是"多了一段文字"而不是"多了这段文字"。
- 主判据不过 → **默认关**。段落已经把分数编码进去（§12，r = 0.79），
  锚句 89.8% 在重复它、只有 20 个模板句，而边际推动在 d ≥ 0.15 的分辨率下量不出来；
  36 tokens／次是实打实的成本。

### 14.7 怎么跑

```bash
python scripts/big5_prompt_ablation.py --self-test   # 零调用，先确认读数链路
python scripts/big5_prompt_ablation.py --dry-run     # 零调用，确认格子与功效
python scripts/big5_prompt_ablation.py               # 1,632 次调用
python scripts/big5_prompt_ablation.py --resume      # 断了续跑
python scripts/big5_prompt_ablation.py --analyse-only  # 只重算，不再调用
```

事后复核证据都不用重花钱。

## 15. A4 结果与 D5 裁定（2026-08-21，1,632 次调用）

| 判据 | 结果 | |
|---|---|---|
| 主判据 同向格数 ≥ 52/87 | **48/87**，p = 0.196 | FAIL |
| 上限 \|r\| ≤ 0.30（下界） | 三维全部达标 | PASS |
| 判别臂 反向锚句推回 | **16/30**，p = 0.428 | FAIL |

delta 中位数 +0.005，均值 −0.002。**D5 → prompt 通道默认关。**

零结果对我的先验是**方便**的（§13.3 里我论证过锚句 89.8% 是重复）。
正因为方便，下面每一步都是在攻它。

### 15.1 21.7% 解析失败：查清了，不是条件相关

自检时解析失败 0%，真跑 354/1632。这个差距不查清，零结果不能要。

查出来的分布很干净：**routine 场景 0%，action 场景 40%**。
354 条全部是 JSON 被**截断**（长度 618–993，中位 914，零个空响应），
没有一条是格式错误。action 的提示词要「4 个活动 × 每个 5–10 个动作」，撞上了输出长度上限。

三个条件的失败率几乎一致：plain 40.1% / anchor 43.5% / placebo 41.7%。
**所以它不会在条件之间造出差异**——但直接丢掉也不是中立的，
那是在按输出长度做选择，而长度和内容并不独立。

改成把截断对象里**前面完整的条目**抢救出来（不跟冒号的完整字符串即为列表元素），
1632 条全部可用。**判据一个字没改**，两套数都留着：

| | 可比格子 | 同向 | p | 判别臂 |
|---|---|---|---|---|
| 丢弃截断样本（原始） | 85/87 | 46/85 | 0.258 | 16/28 |
| 抢救后（全量） | 87/87 | **48/87** | 0.196 | 16/30 |

**结论不变。** 解析器是在看到结果之后改的，这件事本身要当心，所以：
判据未动、改动在构造上对结果盲（三条件等比例恢复）、两套数并列写而不是替换。

### 15.2 与分类器无关的检验：模型**确实读了**锚句

零结果最容易的解释是"模型压根没看那两句"。这个可以不依赖我的风格分类器来判——
直接量文本本身：同条件两次采样之间的字符二元组 Jaccard，对 anchor–plain 跨条件的 Jaccard。

```
同条件（plain-plain、anchor-anchor）：0.1240   n=4872
跨条件（anchor-plain）：              0.1108   n=5568
差 +0.0133，Cohen d = +0.29
```

**跨条件的输出确实比同条件更不像。** 模型读了锚句，输出的措辞变了。

这把结论从"锚句无效"改成了更准确、也更有意思的一句：
**锚句改变了文本，但没有把选择推到决策循环看得见的方向上。**

### 15.3 仪器灵敏度：这是个必须写出来的限制

自检只证明了链路能读**假** LLM。真实数据上的阳性对照是这样的——
plain 条件（只有段落）下，风格标签能读出多少段落里的人格：

| 维度 | 风格 | 载荷 | plain r | anchor r |
|---|---|---|---|---|
| C | progress | +1.00 | +0.091 | +0.166 |
| C | avoidant | −0.80 | −0.131 | −0.336 |
| E | social | +1.00 | +0.208 | −0.305 |
| N | restorative | +0.60 | −0.241 | −0.331 |

段落这个信号已由独立打分器验到 **r = 0.79**，而风格标签只读出 **|r| ≈ 0.09–0.24**，
其中 N 两项还是反号。**本仪器大约只能还原一个阅读型打分器的四分之一到五分之一。**
所以本臂的零结果，严格说是「**在这个分辨率下**量不出来」。

### 15.4 但没有剂量效应，这是零结果站得住的关键

如果只是分辨率不够，至少应该看到**排序**：越突出的居民拿到越强、越具体的锚句
（`strong_z = 1.5` 以上换强句，比如「独处超过两天就会觉得不对劲」），
推动应当越大。实际上（**探索性拆分，未预注册，不套判据**）：

| 拆分 | n | 同向 | 中位 delta | p |
|---|---|---|---|---|
| **强句 max\|z\| ≥ 1.5** | 25 | 12 (48%) | −0.011 | 0.655 |
| **弱句 max\|z\| < 1.5** | 62 | 36 (58%) | +0.007 | 0.126 |
| max\|z\| ∈ [0.25,0.7) | 16 | 10 (62%) | +0.012 | 0.227 |
| max\|z\| ∈ [0.7,1.2) | 30 | 16 (53%) | +0.000 | 0.428 |
| max\|z\| ∈ [1.2,2.0) | 30 | 14 (47%) | −0.010 | 0.708 |
| max\|z\| ∈ [2.0,∞) | 11 | 8 (73%) | +0.125 | 0.113 |
| routine | 43 | 23 (53%) | +0.005 | 0.380 |
| action | 44 | 25 (57%) | +0.006 | 0.226 |

**强句那一档 48%，比弱句的 58% 还低**；按 |z| 分档是 62/53/47/73%，非单调。
最后一档看着漂亮，n=11，而且紧挨着它下面那一档是 47%。这是噪声，不是剂量曲线。

一个仪器要同时藏住效应**和**藏住剂量排序，得瞎得很有针对性。
**没有剂量效应，是零结果不只是分辨率问题的最强内证。**

## 16. 存量缺陷：输出被截断，解析器把它当成"模型什么都没说"（2026-08-21）

§15.7 记的那条。A4 留下的 848 条真实 `actions` 响应正好是这个缺陷的现成数据集，
所以这次不用猜。

### 16.1 实测：生产解析器判死 41.7%，是两个不同的病

对 848 条真实响应跑生产的 `_parse_action_space`：

| 失败模式 | 次数 | 占比 |
|---|---|---|
| 被 `max_tokens` 截断 | 318 | 37.5% |
| 完整但 JSON 语法错 | 36 | 4.2% |
| **合计判死（返回 `{}`）** | **354** | **41.7%** |

**截断**：响应长度直方图在 ~1000 字处断崖（600/848 落在 700–999，1000 以上只有 31 条），
对应 `providers.py` 里 `cfg.get("max_tokens", 512)` 那个默认值。提示词要
「4 个活动 × 每个 5–10 个动作」，装不下。
**生产比这个样本更糟不会更好**：`generate_actions` 传的是一整天日程里所有不重复的活动，
比我探针里的 4 个多。

**语法错**：模型用 ASCII 引号写中文引语——
`"同事提议一起下楼吃时以"来不及"为由拒绝"`——字符串提前闭合，整个对象报废。
和截断完全无关的另一件事，只是后果一样。

### 16.2 后果不是一个"被接住的错误"

`_parse_action_space` 返回 `{}` → 全部活动算 missing → 重试**用同一份活动列表**
→ 撞同一堵墙 → 还是 `{}` → 记一条 warning → 全天每个活动 4 条通用兜底动作。
**两次调用花掉，什么都没拿到。**

（缓存这一层没被毒化：`save_action_space` 的 `strip_fallback_only_activities`
会把纯兜底的条目丢掉。我原先担心的"被永久缓存"这条**不成立**，如实更正。）

### 16.3 三处修复

**一、`repair_inner_quotes`（`_schedule.py`）。**
这个语法里字符串只在下一个非空白字符是 `, ] } :` 时才结束，其余位置的引号都是内容。
这条规则是**可判定的**，不是猜。安全性也是验过而不是假定的：
**494 条本来就能解析的响应，修复后逐字节一致 494/494。**

**二、`loads_tolerant`：先严格解析，失败了才在修复文本上再试一次。**
它**只会跑在 `json.loads` 已经拒绝的输入上**，所以今天能工作的调用一个都不会改变行为——
正因如此才敢放到全部 5 个解析器后面，而不只是量过失败率的那一个
（`_parse_action_space`、`_parse_location_bias`、`_parse_schedule`、
`_parse_structured_schedule`、`realism._parse_json_dict`）。

**三、`_salvage_action_space`：从没写完的对象里取出闭合了的活动。**
只取 `[...]` 真的闭合的那些——半截的列表**丢掉而不是当成短列表交出去**，
因为交出去会让调用方的重试以为这个活动已经有了。

效果（同 848 条）：

| | 0/4 | 1/4 | 2/4 | 3/4 | 4/4 |
|---|---|---|---|---|---|
| 修复前 | **354 (41.7%)** | 0 | 0 | 0 | 494 |
| 修复后 | **0** | 2 | 54 | 262 | 530 |

93.4% 拿到 3 个或 4 个活动，过短碎片 0 条。剩下的 1–2 个活动交给**本来就存在的重试**——
今天它没用是因为 missing 永远是全部；现在它只需要问 1–2 个，短到装得下。

### 16.4 第四处：API 早就告诉我们了，旧代码把这个信息扔了

`providers.py` 只在**文本为空**时才看 `stop_reason`。非空但被截断的响应，
原样当完整答案返回。于是下游解析器根本分不清
「模型说了句读不懂的话」和「模型说到一半被切了」——**318 次，全程无声。**

加了 `_note_truncated`：Anthropic 的 `stop_reason == "max_tokens"` 和
OpenAI 的 `finish_reason == "length"` 都计数，并在第 1、10、100、之后每 500 次
打一条 warning（37% 的发生率下，每次一条读不了，整轮一条又太容易漏）。
`truncation_counts()` 可供工具读取。

**不抛异常。** 截断的答案往往仍然可用（上面的抢救就是证据），
把一个降级的结果变成硬失败是更差的交易。

### 16.5 没做的事

**没有去调 `max_tokens`。** 512 是provider 级的成本/延迟策略，
不该由一个解析缺陷来决定；而且上面的修复对任何上限都成立。
现在它至少是**看得见**的了——真跑一轮看 `truncation_counts()`，再决定要不要抬。

**没有把 `generate_actions` 按活动分批。** 有了抢救 + 短重试，第一次调用的损失已经被接住。
分批是更彻底的预防，但那要先知道真实日程里活动数的分布，等 `truncation_counts()`
的实测数据再说，不凭空拍。

**测试** `tests/test_llm_output_truncation.py`（13 条），fixture 是真实响应的缩短版；
其中最关键的一条是「对合法 JSON 必须恒等」——整个修复都压在这条性质上。

## 17. 更正 §16：那个修复是必要的，但在生产规模上**不够**（2026-08-21）

§16.5 我写的是"有了抢救 + 短重试，第一次调用的损失已经被接住，分批等实测数据再说"。
拿设备上真实跑出来的运行产物一算，**这句话在 N=4 时对，在生产规模上错**。

### 17.1 把两个数放在一起就清楚了

从 848 条真实响应量单个活动块的大小，从 `output/memory/agent_37_schedule.json`
量真实一天有几个活动：

| 量 | 值 | 来源 |
|---|---|---|
| 单个活动块 | 中位 **193** 字，p75 215 | 499 条未触顶的完整响应 |
| 可用输出预算 | 约 **916** 字 | 被截断响应的长度中位（= 512 token 上限） |
| 真实一天的不重复活动数 | **10** | agent_37 的实际日程 |

预测：

| N 个活动 | 预计字符 | 是否触顶 | 首次能救回 |
|---|---|---|---|
| 3 | 585 | 否 | 3 |
| 4 | 778 | 边缘（实测 37.5% 触顶） | 4 |
| 6 | 1164 | **是** | 4 |
| 10 | 1936 | **是** | 4 |

**所以那次不分批的调用从来就不可能成功。** 它最多救回 4 个，
重试再问剩下 6 个——**又是 6 个**——撞同一堵墙。
`generate_actions` 这条批量路径在真实日程下一直是残的。

那缓存为什么看着是好的？因为 `ensure_action_space_for_activity` 在**后面**
一个活动一次地把它们买了回来（单活动永远不触顶）。
系统靠这个瘸着走，代价是把一次批量调用摊成了十几次单活动调用。

（顺带纠正另一个我先前的猜测：agent_37 缓存的 118 个活动**全部**含 3–4 条通用兜底动作，
但这不是损伤指标——`_ensure_behavioral_action_balance` 对**任何**输出都会补齐缺的类别，
包括完全正常的输出。纯兜底条目 0 个。以"兜底动作出现"来判断污染是错的。）

### 17.2 分批：`action_space.activities_per_call = 3`

3 是算出来的：916 ÷ 215（p75）≈ 4，取 3 留一档余量给啰嗦的智能体。

**分批不比原来贵——这是最容易搞反的一点：**

| | 调用次数 | 结果 |
|---|---|---|
| 原来 | 2 次批量（都失败）+ 之后每个活动各补 1 次 ≈ **12 次** | 期间用通用动作 |
| 只有抢救 | 1 次救回 4 + 重试救回 ~4 + 之后补 2 次 ≈ **4 次** | 部分活动短期用通用动作 |
| 分批（3） | **4 次**，全部成功 | 无缺口 |

实测（假 LLM）：10 个活动 → 4 次调用，分组 `[3,3,3,1]`，覆盖 10/10；
单活动路径仍是 1 次调用，未受影响；`seed_actions` 按组裁剪，
每次提示词里只带本组的种子（`[3,3,3,1]`），不把另外七个活动的参考白抬进去。

**§16 的抢救没有因此变成多余**：分批大小是按中位数定的，
一个啰嗦的智能体仍可能撑爆某一组，那时抢救仍然接住它。两层是互补的，不是二选一。
