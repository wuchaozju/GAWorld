## 一、随机裁员的收入损失是永久的

`_check_daily_shocks` 的随机裁员把时薪砍掉 50–85%，再开一个 30–90 天的倒计时。倒计时结束时只有
「失业」人生事件造成的失业会复职（`_rehire_after_unemployment`，按原岗位收入带的 85–100%）；
随机裁员没有 `previous_job`，什么都不发生——倒计时唯一的作用是期间不能涨薪。两份 README 却写着「恢复期 30–90 天」。

按月解释概率之后，默认周期一年里约 11% 的人碰上一次，2000 人测得年末工资 p10 = 0.51 倍。

**改法：** 裁员时记下这一段失业开始前的时薪（`_pre_layoff_hourly`；期间再被裁一次仍记第一次的），
倒计时结束时回到它的 85–100%（与人生事件复职留的「疤」一致），税前月薪同比例调整，`layoff_recovery` 事件带上 `to_hourly`。

- 不会往下调：期间若工资指数化把时薪抬到了更高，保持不动。
- 期间发生换工作或退休事件：那条路径本来就清掉倒计时，现在也一并忘掉旧时薪，不会事后「恢复」。
- 期间发生失业事件：照旧按原岗位收入带复职，不再另行恢复。
- 不改：随机裁员仍不改写职业文本、不计入居民统计的失业率（只有失业事件会）。
  让随机裁员也真的「失业」会改动日程和人设文本，是更大的改动，另议。

**效果（2000 人、默认配置、一年）：** p10 / 中位 / p90 = 0.51 / 1.00 / 1.19 → **1.00 / 1.00 / 1.18**；
一直处在谷底一年：0.23 / 1.00 / 1.00 → 0.87 / 1.00 / 1.00。

改变所有默认 run → **可比性版本 8**。

## 二、需求驱动的通胀把大病自付费当成需求

需求 C 是人均实际消费（不含房租）。医疗急症的自付部分记在 `healthcare` 类里，于是也算进了需求：
3 人一年的测试里，一笔 2.1 万元的急诊让 30 天消费均值猛涨，通胀顶在 15% 上限 30 天。大病不是需求拉动。

**改法：** 急症的自付额另记一份当天的 `_daily_emergency_expense`（日初清零），计算需求时减掉；日常的医疗消费照算。

**效果：** 同一测试里顶到上限的天数 30 → 0。随后两个月通胀落到 0.1% 下限——那户人家大病之后开销收紧
（日消费从 80–96 降到 67–71），3 人的镇子里一户占三分之一。这是真实的需求下降，人口多时会被摊薄。

默认关，不加可比性版本。
