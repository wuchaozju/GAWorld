# 分布式世界：一个开放世界的居民分散在多台机器上运行

日期：2026-10-02
状态：已确认（2026-10-02）：节点用自己的模型密钥；默认宽松同步（60 秒超时）；D1–D5 一次落地
前置：`2026-10-01-multi-user.md`（账号、世界、开放世界共玩，P0–P5 已实现）。该提案第十一节把
「跨机器分布式运行仿真」列为不在范围；本提案补上这一块，并与多用户体系接通。
场景：课堂 / 工作坊。教师服务器（**枢纽**）承载账号、世界与共玩；学生或机房的电脑（**节点**）各自分担
同一个世界里的一部分居民（及其模型调用）；所有人——包括手机——仍通过浏览器以玩家身份参与。
部署：教室局域网（HTTP）与公网（反向代理 + HTTPS）都要支持。

---

## 一、现状核查

| 已有 | 位置 | 缺口 |
|---|---|---|
| 中继：注册居民 / 目录 / 发消息 / 拉消息，纯 HTTP 拉取 | `apps/distributed_comm_server.py`、`distributed/comm.py` | 独立端口、无鉴权（仅 OpenClaw 有令牌）、`cluster` 只是字符串，不认识账号和世界 |
| 仿真只跑部分居民 | `generative_city_sim.py:450` `distributed.local_agent_ids` | 谁跑哪些由手工配置；没有统一启停 |
| 远端居民之间的互动 | 每步按 `send_probability` 给远端居民发「我在做什么」，对方下一次感知看到 | 各节点时钟各走各的，没有同步 |
| 玩家行动 → 仿真 | `play_api._send` → 本机文件队列 `kernel/remote.py` | 只能到达枢纽本机的仿真进程 |
| 现场动态 | Recorder 写 `records/*.jsonl`，`/api/events/stream` 推给浏览器 | 节点的记录留在节点本机 |

**关键事实**：中继协议全部是「节点主动请求」，所以节点在 NAT / 手机热点 / 公网后面都能工作——只要
节点能访问枢纽，就不需要任何入站端口。本提案保持这一点：**所有流量都是节点 → 枢纽**。

## 二、拓扑

```
            浏览器 / 手机（玩家、属主、教师）
                     │ HTTPS（会话 cookie）
                     ▼
 ┌──────────────── 枢纽：dashboard_server ────────────────┐
 │ 账号 · 世界 · 共玩租约 · /api/cluster/*（节点令牌）     │
 │ 每个世界一个中继后端（DistributedRelayBackend，进程内） │
 │ 每个节点一个干预发件箱 · 进度表（tick 同步）            │
 │        │ 本机子进程（node_id = hub）                    │
 │        ▼                                               │
 │   仿真：未分配给节点的居民                              │
 └────────────────────────────────────────────────────────┘
          ▲ HTTPS（Bearer 节点令牌），只有出站请求
          │
 节点 A：python -m gaworld.cluster join <枢纽> --token …
   ├─ 下载世界包（配置 + 居民种子 + 城市 bundle）
   ├─ 仿真子进程：分配给 A 的居民，模型调用用 A 自己的密钥
   └─ 转发线程：拉干预 → 本地队列；本地记录 → 枢纽
```

- **枢纽就是 dashboard**，不再另开 8877 端口：一个端口、一套反向代理 / HTTPS，公网部署只需暴露它。
  旧的独立中继保留，行为不变（单机多进程、OpenClaw 仍可用）。
- **枢纽自己的仿真也是一个节点**（`node_id = hub`），跑所有未分配出去的居民，同样经 HTTP 走中继和同步——
  只是地址是 `127.0.0.1`。这样枢纽和节点只有一套代码路径。

## 三、节点：令牌、分配、加入

### 3.1 属主添加节点

世界属主（或管理员）在「管理世界」里添加节点：填名字（如「302 机房 7 号机」）和**它负责的居民**
（编号列表或「再分 N 位」）。服务器返回一次性显示的令牌和一行命令：

```
python -m gaworld.cluster join https://gaworld.example.edu --token w1a2b3c4d.n3.Xk…
```

- 令牌格式 `<world_id>.<node_id>.<secret>`：前两段用于定位，`secret` 在服务器只存 SHA-256
  （与会话令牌相同：secret 是随机的，慢哈希没有意义，而节点每秒都要验证）。可随时吊销；吊销后该节点的下一次请求得 401，节点进程停下仿真并退出。
- 节点表存在世界目录 `output/worlds/<id>/cluster/nodes.json`，不改账号库 schema；删除世界即删除节点。
- 一位居民同一时刻只属于一个地方（某个节点或枢纽）。枢纽至少保留一位居民——它的运行就是整个世界的
  「心跳」，启停按钮也只有这一个。
- 只在有账号库的部署里提供（世界本身只在那里存在）；单人模式行为不变。

### 3.2 节点能做什么

节点令牌只能访问 `/api/cluster/node/*` 与 `/api/cluster/relay/*`，且只作用于它自己的世界：

| 接口 | 作用 |
|---|---|
| `GET /api/cluster/node` | 我是谁：世界、节点名、分配的居民、世界是否在运行、本次运行的 `run_id` |
| `GET /api/cluster/node/bundle` | 世界包（zip）：世界的有效配置（去掉路径与密钥）、`seed/agents.csv`、`seed/profiles.md`、城市 bundle 目录 |
| `POST /api/cluster/node/heartbeat` | 上报状态（空闲 / 下载中 / 运行中 / 出错 + 最后几行日志）；返回是否应运行 |
| `GET /api/cluster/node/interventions` | 取走发给本节点的干预（玩家行动等），取走即删 |
| `POST /api/cluster/node/records` | 上传本地 Recorder 新增的行（按表），枢纽追加进世界的 `records/`，每行加 `_node` |
| `POST /api/cluster/node/sync` | tick 同步，见第五节 |
| `/api/cluster/relay/{register,directory,message/send,message/poll}` | 与旧中继同协议，后端换成该世界自己的那一份 |

### 3.3 节点进程（`python -m gaworld.cluster join`）

一个前台进程，一直跑到 Ctrl+C 或令牌被吊销：

1. 每 2 秒心跳。枢纽说「世界在运行」且 `run_id` 变了 → 下载世界包到 `output/nodes/<world_id>/`，
   以 `GAWORLD_CONFIG_OVERRIDES`（世界配置 + 本地路径 + 分配的居民 + 中继地址与令牌）启动仿真子进程。
2. 运行期间每秒拉一次干预，写进本地队列（`kernel/remote.enqueue`，仿真每 tick 照常排空）；
   每秒把本地 `records/*.jsonl` 的新增行上传。
3. 枢纽说「停止」→ 终止子进程；子进程自己退出 → 在心跳里报告。断网时子进程继续跑（同步超时后自行推进），
   网络恢复后补传记录。

**仿真代码几乎不动**：只是中继客户端多带一个 `Authorization` 头，再加一个 tick 同步插件。

## 四、玩家行动跨机器路由

`play_api._send` 改为按居民路由：居民在枢纽 → 本机队列（不变）；在节点 → 该节点的发件箱，
节点下一次拉取（≤1 s）后进入它的本地队列，下一个 tick 生效。

| 干预 | 路由 |
|---|---|
| `player_claim` / `player_release` / `player_act` | 发给该居民所在的地方 |
| `player_say`（同一处） | 不变 |
| `player_say`（说话者与听者不在一处） | 说话者那边记「你对 X 说了」（插件接受不在本地的 `target_name`）；听者那边收到新干预 `player_hear`，下一次感知出现「Y 对你说：…」 |

租约仍在枢纽内存里（`play_api._CLAIMS`），节点只是被告知；节点离线不影响租约，节点上线后下一次续租
（30 秒内）就同步到。

## 五、时钟：宽松的 tick 同步

节点各自的仿真速度不同（模型快慢、居民多少）。新内置插件 `cluster`，挂在 `on_time_tick`：

- 每个 tick 开始时上报自己的位置 `(day, time)`，等到**所有在线节点**都到达这一 tick 再继续；
- 「在线」= 本次运行里 30 秒内心跳过；最多等 `cluster.sync_timeout_seconds`（默认 60 秒，属主可改，
  0 = 不同步、各跑各的），超时就自己往前走并记一条 `cluster.sync_timeout`——**一台慢机器或掉线的机器
  不会让整个世界停下**，与「玩家不在线不会让世界停下」同一原则；
- 与 `multiplayer.wait_for_players_seconds` 叠加：先等玩家，再等节点。

没有做严格的锁步：跨节点的影响本来就只经消息传递、下一次感知才生效，晚到一个 tick 不破坏因果。

## 六、看得见：现场、状态与限制

- **现场**：节点上传的记录进入世界的 `records/`，`/api/events/stream` 不改就能推给所有浏览器——
  手机上的「多人共玩」页看到的是全世界的动静，不论居民在哪台机器上。
- **节点状态**：管理世界对话框里列出节点：在线、负责的居民、当前 sim 时间、落后几个 tick、最后错误。
- **模型调用**：节点用自己机器上的密钥与模型设置（世界包不含密钥）；节点的调用**不计入**枢纽的用量
  与配额——这正是把负载分出去的目的，也在界面上注明。
- **不做（本期）**：节点上的状态 CSV、记忆、可视化轨迹不回传，分析页和回放只覆盖枢纽上的居民
  与已上传的记录表；运行中迁移居民；节点之间直连；居民在地图上跨节点「相遇」（仍只经消息）。

## 七、手机

手机始终是**玩家**（瘦客户端），不承担仿真。为了让手机能顺手进入：

- 新增短链 `/play/<world_id>`：登录后设好世界 cookie 并打开「多人共玩」页——教师把链接（或其二维码）
  投到屏幕上即可，不必在手机上操作桌面版的世界切换器；
- 共玩页在窄屏下已是单列；补上「我的居民此刻在做什么」（来自记录流里该居民最近的行动），
  并在页面重新可见时立即续租（手机切到后台会暂停定时器）。

## 八、安全

- 节点令牌只授予自己世界的节点接口；不能读其他世界、不能调用任何会话接口。
- 节点上传的记录只能写进本世界 `records/`，表名经 Recorder 同样的字符清洗，单次上传有大小上限（1 MB）；
  每行强制写入 `_node`，不能冒充枢纽。
- 世界包不含 API 密钥、账号库、其他世界的任何文件。
- 公网部署：枢纽放在 HTTPS 反向代理后（`docs/SERVER_DEPLOYMENT.md` 补一节），节点命令里用 `https://`。
