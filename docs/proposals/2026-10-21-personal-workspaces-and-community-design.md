# GAWorld 公开研究社区与个人工作台设计

日期：2026-10-21  
状态：用户已于 2026-10-21 确认，首版已实现并验证；生产账号初始化与邮件配置由部署者完成。
实现与交付边界见 `docs/COMMUNITY.md` 和 `docs/reports/2026-10-21-community-verification.md`；下文现状核查保留实施前快照。  
已确认方向：公开研究社区，开放注册，游客可浏览公开成果。

## 1. 产品目标与方案选择

让用户完成「注册 → 在自己的工作台开展研究或仿真 → 选择成果发布 → 讨论 → 被他人引用和复现」的闭环。

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 复用现有账号、世界和研究隔离，新增社区发布层 | 保留现有研究与仿真流程，私人权限与公共阅读分开 | 需要发布版本、公共接口和个人首页 | 采用 |
| 给现有研究记录加公开开关 | 初期改动少 | 私有字段容易随内部对象暴露；研究重跑后讨论失去对应版本 | 不采用 |
| 重建独立多租户平台和论坛 | 可独立扩展各服务 | 账号、权限和产物同步复杂，改造范围过大 | 等规模和部署需求明确后再评估 |

首期拆为三个可独立验收的部分：个人空间与账号、成果发布与广场、讨论与社区管理。共同使用下面的身份和权限边界，各部分另写实施计划。

## 3. 页面与导航

公共导航：`首页｜发现研究｜公共广场｜帮助｜登录 / 注册`。

登录后增加：`我的工作空间｜消息｜头像菜单`。用户可在公共区和私人区之间切换。

```text
公共区域
├─ 发现研究：搜索、标签、研究类型、最新发布
├─ 公共广场：成果分享、研究问题、方法讨论
├─ 成果详情：摘要、方法、结果、证据边界、版本、附件、讨论
└─ 用户主页：公开资料、已发布成果、公开帖子

我的工作空间
├─ 总览：最近研究、世界与运行、待处理任务、用量
├─ 研究工作台：方案、正式研究、批次、报告、导出
├─ 仿真工作台：我的世界、参数、运行、日志、回放
├─ 居民与城市：我的素材及被允许使用的公共模板
├─ 我的发布：草稿、公开版本、撤回记录
├─ 我的收藏与消息
└─ 账号与模型设置
```

「工作空间」首期是账号的个人入口，不再引入可共享的 workspace 租户层。一个用户可拥有多个世界、多项研究。

总览可聚合本人不同世界的摘要；进入研究详情或执行操作时，必须指定对应世界。现有研究工作台保留世界筛选，不把其他人的开放世界自动加入私人研究列表。

建议新增路由 `/explore`、`/plaza`、`/publications/<id>`、`/people/<public_id>`、`/workspace`。这些是拟定路由，现阶段尚不存在；现有 `/console` 和旧功能链接继续兼容。

## 4. 账号和首次使用

开放注册采用唯一用户名、公开显示名、邮箱与密码。将稳定的登录用户名与可变的公开显示名分开，旧昵称账号迁移时保留原有登录方式。

注册流程：填写信息 → 验证邮箱 → 进入个人总览 → 选择城市模板并创建第一个私人世界 → 开展研究或仿真。用户可先浏览工作空间，不强制立即创建世界。

- 新账号默认普通用户；验证前可进入空工作空间，完成验证后才可发表评论、发布和提交模型任务。
- 邮箱验证和找回密码复用独立的单次、限时令牌机制；令牌只保存摘要。邀请码注册仍可作为部署配置保留。
- 邮件服务是开放注册上线的必要依赖；开发环境使用测试邮件出口，不伪造已发送状态。
- 支持退出当前会话、退出其他设备、修改密码和账号禁用；公网会话使用 HTTPS 与 Secure Cookie，状态变更请求验证 CSRF/来源。
- 注册、登录、邮件发送、重置密码分别限流；客户端不能提交角色、属主或计算额度。
- 首次进入仅创建轻量账号资料，不自动生成城市、启动仿真或调用模型。

公共资料包括显示名、头像、简介、研究兴趣和公开成果。邮箱、真实用量、模型密钥、私人研究和原始日志不进入公共资料。

## 5. 私人工作台与执行隔离

账号是属主边界；世界是仿真状态和配置的隔离边界。发布物另有公共阅读边界。

- 用户拥有的研究、批次、世界、文件、日志、后台作业和导出均在服务端检查属主及所属世界。隐藏按钮不构成授权。
- 用户切换城市或世界只改变自己的操作上下文。新接口显式绑定 `world_id`；界面切换期间的请求带原世界标识，不因共享 Cookie 变化写入另一世界。
- 旧接口继续兼容，但提交变更时校验预期世界；上下文不匹配返回 409 并要求刷新，不静默退回默认世界继续写入。
- 子进程和后台任务固定创建时的用户、世界、研究版本和模型配置；完成后只更新自己的记录。
- 用户可使用平台模型额度，或配置自己的凭据。凭据在服务端受保护保存，响应、日志和导出只显示脱敏元数据。
- 服务器、用户并发限制及排队机制继续复用；模型任务统一经过额度检查，增加原子预留与实际用量结算，避免并发任务突破软配额。
- 创建研究或复制方案均不自动执行；运行前显示模型、居民数、条件数、重复数、预计调用与排队状态，由用户明确启动。
- 对研究、模型调用、存储容量分别设管理员可调整的限制。取消排队、暂停和停止不被计算额度阻挡。

这是应用级用户与数据隔离；首期不允许用户上传并执行任意服务器脚本。

## 6. 成果发布：独立版本与公开快照

从研究报告或仿真回放点击「发布到广场」，进入发布草稿。可发布研究方案、研究报告、仿真案例；公共广场另支持独立的研究问题与方法讨论帖子。

研究成果表单包含：标题、摘要、研究问题、方法、结果图表、局限、标签、来源引用、复用许可、附件选择。仿真案例可附经过筛选的回放；方案尚未运行也可发布，但必须标为「方案」。

发布前展示最终公开预览、拟公开文件和排除项。作者确认后，从明确的研究版本生成字段白名单快照和附件清单，禁止直接序列化私有研究对象或暴露内部目录。

```text
私人研究修订版 → 发布草稿 → 预览并确认 → 公开成果 v1
私人研究继续修订                         └→ 发布新版本 v2
公开成果 v1 / v2 → 撤回后停止公开访问，保留内部审计
```

- 已发布版本内容不可原位覆盖；修改标题、正文、结果或附件形成新版本，旧链接和讨论保留版本指向。
- 每个版本记录源研究 ID、源修订号、作者、发布时间、内容摘要、协议/配置摘要及产物校验和。快照过程校验源版本未改变。
- 显著展示「方案 / 已完成 / 部分结果 / 运行失败」以及探索运行和正式研究的区别。没有数据的研究不能显示为有实证结果。
- 发布不要求公开居民原始记录。附件逐项选择，默认仅报告、图表和可分享的参数；第三方材料、私有居民和密钥不随包发布。
- 每个版本单独标记「仅供阅读」或具体复用许可；复制功能同时校验该版本的许可与资料依赖。
- 创建过程使用暂存产物与数据库事务；失败不出现半发布页面，重试通过幂等键避免重复发布。
- 撤回立即关闭页面正文、附件、搜索结果及平台缓存的访问；平台不能收回已经被他人下载的副本。
- 删除私人源研究不破坏已发布快照，但页面提示源研究已删除；彻底删除公开成果须另行处理并保留必要审计。

## 7. 广场、讨论、收藏和复制研究

发现研究页面以成果卡片展示标题、作者、标签、研究类型、结果状态、摘要、版本和讨论数。首期提供关键词搜索、类型/标签筛选、最新排序；精选由管理员设置，避免把热度当作科学质量。

公共广场提供「成果分享」「研究问题」「方法讨论」三个分类。成果分享引用发布物，不复制另一份正文。评论入口统一在成果或帖子详情页。

讨论首期支持评论、一级回复、引用公开结果、编辑记录、删除标记、举报和讨论锁定。评论关联发布版本，页面支持查看当前版本或全部版本的讨论；旧版本讨论不自动搬到新结论下。

- 游客可浏览公开成果和讨论；发表评论、回复、收藏、举报或复制研究需要登录。
- 作者可回复和申请锁定自己的成果讨论；内容处置由具备社区权限的管理员或版主执行。
- 删除评论保留占位以维持回复关系；被隐藏内容不通过通知摘要、搜索或附件继续暴露。
- 通知覆盖新评论、回复、版本更新和管理处理；初期采用站内收件箱与轮询。每次读取仍检查目标的当前可见性。
- 暂不做私信、实时群聊、关注动态流或共同编辑研究。

「复制到我的工作台」流程：检查许可与依赖 → 创建属于当前用户的私人草稿 → 记录源发布物和版本 → 选择本人的目标世界、可用城市/居民及模型 → 检查配置 → 用户启动。

不复制他人的密钥、任务状态、运行授权或私有文件。缺少数据许可或依赖时明确显示不可运行原因。替换城市、居民或模型后标记为改编研究，不能自动声称是原研究的严格复现。

## 8. 权限模型

| 操作 | 游客 | 普通用户 | 资源作者 | 社区版主 | 管理员 |
| --- | --- | --- | --- | --- | --- |
| 阅读公开成果、公开帖子及讨论 | 允许 | 允许 | 允许 | 允许 | 允许 |
| 阅读或修改私人研究和世界 | 禁止 | 仅自己的 | 仅自己的 | 不因版主身份获得权限 | 按现有管理权限并记审计 |
| 新建研究、启动私人任务 | 禁止 | 仅本人资源，受额度限制 | 同普通用户 | 同普通用户 | 管理权限 |
| 发布、更新版本、撤回 | 禁止 | 仅自己的来源 | 允许 | 可下架，不改作者结果 | 可下架并审计 |
| 评论、回复、收藏、复制 | 禁止 | 允许，受账号和许可限制 | 允许 | 允许 | 允许 |
| 举报处置、锁定、隐藏内容 | 禁止 | 举报 | 举报、申请锁定 | 允许，记录理由 | 允许 |
| 配额、账号封禁、平台设置 | 禁止 | 禁止 | 禁止 | 禁止 | 允许 |

版主采用社区能力授权，不直接扩展为研究管理员。现有世界的 `open` 仍表示登录成员共玩；成果公开不授予世界访问或控制权限。

公共接口只读取发布层的允许字段，不把 `ownership.visible()` 改成「已公开的私有记录人人可见」。

## 9. 数据与模块边界

核心关系：`用户 → 私人研究 / 世界 → 发布物 → 不可变版本 → 评论`。复制研究额外保留来源版本与派生关系。

建议增量数据结构：

| 对象 | 关键内容 |
| --- | --- |
| 用户扩展与公开资料 | 稳定用户名、显示名、邮箱验证、状态、公开 ID、简介 |
| 验证与恢复令牌 | 类型、摘要、期限、使用时间、用户 |
| 发布物 | 作者、来源类型/ID、状态、当前版本、复用策略 |
| 发布版本 | 源修订号、公开正文、方法/结果状态、清单摘要、发布时间 |
| 发布附件 | 所属版本、存储键、类型、大小、校验和 |
| 广场帖子 | 作者、分类、正文、可选成果引用、状态 |
| 评论 | 目标、发布版本、回复目标、作者、正文、编辑/删除状态 |
| 收藏、通知、举报、社区授权 | 用户与目标、状态、幂等/唯一约束、审计信息 |

先复用 SQLite，使用显式 schema 版本和可回滚备份进行迁移；小事务、索引、分页与并发写测试必须完成后再确定承载量。原始仿真和研究产物继续使用现有文件存储，公开附件单独存放，禁止公共 HTTP 路径直达私有输出。

新增实现放在 `gaworld/`：账号扩展归 `gaworld/accounts/`，发布、讨论、通知和管理归 `gaworld/community/`。社区作为独立子系统提供插件装配入口；HTTP 处理委托到 `gaworld/apps/community_api.py` 等小模块，通过 `routes.py` 接入并登记 `openapi.py`。不在 CLI 或 dashboard 主处理器中堆叠业务分支。

前端复用 `site/` 的控制台、主题和品牌资源。公共页面使用适合游客的壳层，私人工作台沿用控制台功能页，避免把管理员控制台作为注册后的默认首页。

新增接口族建议：`/api/community/publications`、`/api/community/posts`、`/api/community/comments`、`/api/community/notifications`、`/api/community/reports`、`/api/workspace/overview`。只有明确列入白名单的公开读取接口允许匿名，其他接口维持默认拒绝。

## 10. 启用与旧数据

部署账号系统需要明确设置管理员并完成安全初始化，禁止由首个公网注册者自动成为管理员。维护单用户模式与开放社区模式的显式部署边界。

旧单用户研究、城市和产物先保持原路径、管理员可见；管理员通过预览与确认选择要认领或迁移的项目，不能把全部历史记录交给新注册用户。

注册后的个人总览为空是有效状态，提供「创建世界」「新建研究」「浏览公开案例」入口，不复制历史私人数据作为示例。

## 11. 实施顺序与验收

| 阶段 | 范围 | 验收结果 |
| --- | --- | --- |
| A：个人空间 | 账号迁移、开放注册/验证/恢复、个人总览、个人世界与研究入口、配额 | 两个账号可分别完整操作；账号 A 无法读写 B 的研究、日志和导出 |
| B：发布与发现 | 发布预览、不可变快照、附件、版本、撤回、游客公开阅读、检索 | A 发布后游客只见选定快照；A 重跑或修改研究不改变旧公开版本 |
| C：社区闭环 | 帖子、讨论、回复、收藏、站内通知、举报处理、复制研究 | B 可围绕版本讨论并创建自己的草稿；副本不含 A 的私有数据和凭据 |

A、B、C 都属于目标系统；首期完整上线须交付三阶段，不能以注册页面完成代替社区闭环。

每阶段采用受控模型替身测试，不自动运行真实或付费实验。最终验收包括：

1. **账号隔离**：两用户、两世界；覆盖列表、详情、修改、启动/停止、作业状态、日志、SSE、导出、回放、附件及静态文件。
2. **上下文一致**：多标签页切换世界、延迟提交和后台完成不会跨世界写入；伪造属主或世界 ID 被拒绝。
3. **注册可靠性**：重复用户名、过期/重放令牌、登录限流、退出与禁用、邮件失败及初始化失败均有明确结果。
4. **发布一致性**：发布时源记录变更、重复请求、附件写入失败、撤回后访问与搜索缓存均有测试。
5. **社区权限**：游客写入、越权回复/删评、版主访问私人研究、通知越权、Markdown/链接注入均被拦截。
6. **资源治理**：并发注册/任务、额度原子预留、取消返还、暂停恢复、服务器容量与不同用户排队公平性。
7. **复用边界**：无许可、缺失依赖、密钥清除、来源记录、改编标记及复制后不自动运行。
8. **兼容与界面**：历史单用户数据、既有账号、旧路由；桌面与窄屏完成注册到讨论的真实页面流程。

配套运行相关 pytest、前端检查、OpenAPI 校验、核心套件与 lint ratchet。验收报告区分受控流程验证与实际模型研究结果。

## 12. 后续扩展

组织/课题组、联合作者、共同编辑、关注订阅、实时讨论、独立任务 worker 与更大规模数据库，均在首期闭环稳定后另行设计。本方案不把这些功能列为已有能力。
