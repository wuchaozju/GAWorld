## 一、现状核查（全仓 grep，非推测）

**通胀率和物价指数现在对任何东西都没有作用。**

- `macro.inflation_rate` 在周期换相时乘一个 `_rng.uniform`（`_advance_macro_cycle`），
  每天累乘进 `macro.cumulative_inflation`。全仓读这两个量的只有：仪表盘的分析页
  （`apps/analytics.py`）和干预接口（`MACRO_INTERVENTION_FIELDS`）。
- 支出计算 `_estimate_behavior_expenses` 和日初的房租水电用的是
  `_macro_expense_multiplier`——它**只读周期相位的 `expense_mult`**（扩张 1.02、顶峰 1.06、
  收缩 1.04、谷底 0.98），不读物价指数。函数上方的注释写的是「inflation + cycle」，
  实际只有 cycle。
- **文档说的和代码做的不一样**：配置说明（中英）写「它只作用在支出侧——工资不跟涨，
  所以长期跑下来居民会越来越买不起东西」；外部系统教程写「累计物价指数……长模拟里它会
  持续侵蚀实际收入」「你设的通胀率就是那天真正被使用的值」。三处都不成立：
  在面板上把通胀设成 15%，居民的账本一分钱都不会变。
- 和失业率的情况一样（那个已改成从居民统计的读数），但更糟：失业率至少没人声称它有作用。

所以这件事分两步：先让价格水平**真的作用到支出上**，再决定**通胀率由什么驱动**。

## 二、居民这一侧，价格能影响什么

模型里没有「商品」，只有钱的流动。支出 = 月预算（由合同工资、恩格尔系数、储蓄率在月结时
重算）÷ 30 ÷ 16 × 时长 × 倍数 × 噪声；付不起时按 支票 → 储蓄 → 信用额度 → 截断 的顺序付；
流动资产低于一个月支出时，可选类别按收入弹性削减（`_hardship_scale`）。

价格水平 P 乘进支出以后，工资不变的居民名义上多花钱、存得少，储蓄见底后可选消费被削、
借贷上升、经济安全感下降——这就是文档本来声称的「生活成本侵蚀」通道。
**实际消费**（名义支出 ÷ P）只在预算变化（裁员、加薪、税改）或资金约束咬合时才变。

## 三、通胀由什么驱动（**需要拍板**）

| | 规则 | 由什么驱动 | 说明 |
|---|---|---|---|
| A. 只接上价格 | 通胀仍按现在的周期随机游走，只是物价指数真的乘进支出 | 外生 | 改动最小，让文档变真；但仍是外生的 |
| B. 菲利普斯曲线 | π = π\* + κ·(u\* − u)，u 取居民统计的失业率 | 失业缺口 | 教科书形式；只对裁员 / 复职有反应，对税改、消费变化没有 |
| **C. 需求拉动** | π = π\* + κ·(C/C₀ − 1)，C = 人均**实际**消费的 30 天滑动均值，C₀ = 开头 30 天的基线 | 需求缺口 | 裁员（预算降）→ C↓ → π↓；减税（到手工资升 → 预算升）→ C↑ → π↑。正是货币改造当初想测而测不出的「政策乘数」通道 |

**倾向 C。** 它对项目里已有的两类干预（裁员、减税）都有反应；B 只对其中一类有反应；
A 只是把文档修成真的。

C 的两个细节：
- 必须用**实际**消费（名义 ÷ P）。用名义消费会形成 P↑ → 名义支出↑ → π↑ 的自我放大。
- 前 30 天是基线期，π 保持在锚点 π\*；短于 30 天的运行里通胀恒等于锚点（如实标注）。
- π 被钳在现有区间 [0.1%, 15%]；P 按日累乘 `P ×= 1 + π/365`，月/年步长按天数补乘
  （与现在的 `_period_days` 一致）。

## 四、与现有机制的接口

### 4.1 价格水平作用在哪
所有走 `_macro_expense_multiplier` 的支出（行为支出、房租、水电）。商户 / 房东的路由份额
跟着名义金额走，**货币守恒不受影响**（价格只放大金额，钱仍从居民流到对手方）。

### 4.2 周期相位的 `expense_mult`（**需要拍板**）
开启后它与 P 重复计算「周期让东西变贵」。与拥堵层压掉静态高峰倍数是同一个问题
（那次选了「开启时压成 1.0」）。倾向同样处理：开启时 `expense_mult` 按 1.0 计，开关可关。

### 4.3 工资指数化（**需要拍板**）
不跟涨 = 文档原本描述的「越来越买不起」；完全跟涨 = 价格对居民几乎没有实际作用。
倾向**部分、滞后**：每次月结按过去 30 天物价涨幅的 `wage_indexation` 比例（默认 0.5）
上调合同工资。设 0 即不跟涨。
注意它不会造成工资—物价螺旋：C 的驱动量是**实际**消费，工资跟涨只是把实际预算拉回原位。

### 4.4 面板干预
当天的物价累积在周期推进里已经做完，所以面板设定的通胀率从次日起才参与累积；内生驱动下次日会被
重新算出的值覆盖，要直接改物价请改 `cumulative_inflation`。（现状是设了也没用，见 §一。）

### 4.5 实施中确认的口径
- 开启时，月结**按实际收入**（名义 ÷ P）重做预算、恩格尔系数和储蓄率，预算按基期价格保存，
  花钱时乘 P。所以工资跟涨不足 → 实际篮子变小、恩格尔系数上升；完全跟涨 → 篮子不变，
  不会形成工资—物价螺旋（有测试）。
- 已知简化：几处「缓冲」比较（困难削减阈值、借贷缓冲、经济安全感目标）用的是按基期价格保存的
  支出估计去比名义存款，会低估所需缓冲约 P−1（一年 2.5% 通胀时约 2.5%）。
- 快进（按月/年）不逐 tick 记账，量不到当日消费：需求驱动在快进里保持上一次的通胀率。

## 五、配置

```python
"macro": {
    ...,
    "inflation": {
        "enabled": False,           # 默认关：开启后物价真的进账本，旧 run 不可比
        "driver": "demand",         # "exogenous" | "phillips" | "demand"
        "anchor": 0.025,            # π*（年化）
        "sensitivity": 0.5,         # κ：需求缺口 10% → 通胀偏离锚点 5 个百分点
        "baseline_days": 30,        # C₀ 的基线期
        "window_days": 30,          # C 的滑动窗口
        "natural_unemployment": 0.05,   # 仅 phillips 用的 u*
        "suppress_phase_expense_mult": True,
        "wage_indexation": 0.5,     # 月结时工资跟涨的比例；0 = 不跟
    },
},
```

默认关，不新增可比性版本。**另外，不论开不开，先把三处文档改成如实描述现状**
（通胀率目前只是显示用，不影响账本）。

## 六、验证门（机制正确性）

1. 关闭时与现状逐位一致（含 RNG 流）。
2. 开启 + `exogenous`：同样的通胀路径下，支出 = 原支出 × P；守恒审计 drift ≤ 0.01。
3. 开启 + `demand`：基线期内 π = π\*；人为把所有人的预算砍 20% → π 下降；
   预算加 20% → π 上升；方向跨种子一致。
4. 名义与实际：把 P 人为翻倍，实际消费不因此上升（防自我放大）。
5. `wage_indexation = 1` 时，一年后实际工资回到起点 ±2%；`= 0` 时按 P 下降。
6. 减税干预（平行世界）：开启 C 时，减税世界的通胀高于对照世界，方向跨种子一致。

## 七、机制来源

需求拉动 / 菲利普斯曲线的**形式**是 (b) 类；κ、π\*、基线期、指数化比例都是 (c) 类。
在小人口（12–500 人）下需求缺口噪声大，任何关于通胀**水平**的结论都不得单独立论，
只能用跨 κ 取值的方向一致性。登记进 `MECHANISM_PROVENANCE.md`。

## 八、不在本提案范围

- 周期相位本身内生化（仍按计时器换相）。
- 分品类物价（食品与住房涨幅不同）、区域物价。
- 企业 / 商户自主定价，货币与信贷驱动的通胀。
- 利率对通胀的反应（央行规则）。
