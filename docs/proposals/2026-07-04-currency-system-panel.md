# 科学家圆桌:GAWorld 货币系统改进讨论纪要

**日期:2026-07-04**
**议题:如何改进 `gaworld/economy/finance.py` 的货币/经济系统**

## 团队

| 角色 | 视角 |
|------|------|
| 陈教授 · 宏观经济学 | 货币流转、部门核算、政策实验有效性 |
| 林博士 · 行为/微观经济学 | 消费决策、信贷、激励一致性 |
| 王研究员 · 复杂系统/ABM | 涌现性、agent 间交互、校准验证 |
| 赵工 · 金融工程 | 资产回报建模、系统性风险 |
| 吴工 · 计算科学/工程 | 可复现性、数值正确性、测试 |

## 一、共识诊断:现在不是"货币系统",是 N 个独立的记账器

**陈教授**:当前架构里货币不守恒。收入凭空铸造(`_record_income` 直接给 checking 加钱)、支出凭空湮灭(`_record_expense` 直接扣掉)。A 的消费不是 B 的收入,没有企业、政府、银行部门。这意味着 `output/comparisons/` 里已经在跑的"个税减税"实验测不出任何乘数效应——减税省下的钱花出去就消失了,不会变成别人的收入。**只要项目想做政策对比实验,闭环就是第一优先级。**

**王研究员**:同意。后果是财富分布没有涌现性:Gini 系数只是"初始化分布 + N 条独立随机游走"的产物,不会因 agent 交互而演化。50 个 agent 和 1 个 agent 跑 50 次没有区别。

## 二、各自发现的具体问题

### 陈教授(宏观)

1. **宏观周期是脚本**:`_advance_macro_cycle` 按 expansion→peak→contraction→trough 固定顺序轮转,时长随机。`unemployment_rate` 只是一个被更新的数字,从不真正让任何 agent 失业(裁员概率来自 `phase_effects.layoff_risk`,与它无关)。
2. **通胀是自说自话的随机游走**:与货币量、总需求无关;`cumulative_inflation` 价格指数只乘在支出侧,工资不指数化,长模拟中实际收入被任意侵蚀。
3. 建议路线:不必一步做全内生宏观。先加**三个聚合部门账户**(企业池、政府池、银行池):工资从企业池支付,消费回流企业池,税和社保进政府池、可做转移支付。守恒即可核算 GDP,政策实验立即有意义。

### 林博士(行为/微观)

1. **赤字涨薪是永动机**(`on_day_end` 的 `income_growth_when_deficit`):入不敷出 → 时薪自动上涨最高 20%/天,越穷涨薪越快。既违背现实,又系统性压缩贫困尾部,污染任何不平等研究。建议直接删除,或改为"求职行为提高未来收入的概率"。
2. **裁员状态不一致(疑似 bug)**:裁员只砍 `base_hourly_income`,不动 `gross_monthly_salary`;月末结算却用旧的 gross 重算税、社保、预算——被裁员工按原工资纳税、按原预算消费。加薪则两者都更新。
3. **没有信贷与预算硬约束**:checking 可无限变负,无借贷、利息、破产;agent 破产后仍按 `monthly_budget`(基于名义月薪而非现金流)照常消费。建议:现金约束消费(余额不足时按类别弹性削减)+ 简单信用额度 + 逾期状态反馈到 `stress`/`econ_security`。
4. **关键词耦合脆弱**:"学习"同时在 `INCOME_KEYWORDS` 和 education 的 `EXPENSE_KEYWORDS` 里——同一行为既赚钱又花钱。LLM 行为文本与经济后果之间只有子串匹配这一层,应至少去重并加优先级。

### 王研究员(ABM/涌现)

1. **加 agent 间支付路由,成本低收益高**:GAWorld 已有 job 与 location 系统。房租付给房东 agent(或房东池)、餐饮消费路由给在该地点工作的 agent 的收入侧,两条规则就能让货币开始循环,财富分布开始涌现。
2. **经济与其它子系统耦合太弱**:目前唯一反馈通道是 `econ_security`。stress/emotion 不影响消费冲动,社交网络不影响借贷与工作信息传播。至少让"冲动消费 ∝ stress"、"熟人借贷走社交边"进入 roadmap。
3. **校准验证**:GAWorld-Bench 目前偏 schema 校验,应加分布级指标——Gini、分位储蓄率、Engel 系数对国家统计局数据、财富-年龄曲线。模拟 365 天后分布不漂移到荒谬区间,应成为回归测试。

### 赵工(金融工程)

1. **没有系统性风险**:`_simulate_monthly_investment_return` 对每个 agent 独立抽高斯样本——全市场股灾在数学上不可能发生,50 个 agent 的组合风险被大数定律抹平。改法很简单:每月抽一次**共同市场因子**,agent 收益 = α + β·市场因子 + 特质噪声,β 按风险偏好异质。
2. 高斯月度回报无肥尾;若做长模拟建议 t 分布或跳跃项。
3. 公积金只进不出、年终奖固定按 0.85 简化计税——都标注了 simplified,可接受,但公积金若永远不能购房,不如降低其在 `econ_security` 中的权重(现在按 30% 可及计入)。

### 吴工(工程/可复现)

1. **全局 `random` 是定时炸弹**:economy 与其它模块共享全局 RNG 流,任何模块增删一次 `random()` 调用都会改变经济轨迹,seed=42 的"可复现"名存实亡。改为模块持有 `random.Random(seed)` 实例。
2. **浮点货币 + 到处 `round(x, 2)`**:守恒审计在浮点下没法严格做。建议内部以"分"为单位的整数记账,或至少加每日对账测试:`Δ(所有账户总额) == Σincome − Σexpense`,精确到分。这也是引入部门账户后验证守恒的前提。
3. 1707 行单文件,tax/spending/macro/shocks 已有清晰分节,拆成子模块的时机到了(配合现有 `tests/test_economy_module.py`)。

## 三、争论点

**要不要做全内生宏观**(失业率由真实劳动市场决定、通胀由供需决定)?
陈教授认为那是终局;王研究员提醒内生宏观 ABM 校准极难,50-agent 规模下噪声会淹没信号;**共识:保留脚本宏观作为可控实验旋钮,先把微观守恒和闭环做对**——脚本宏观 + 守恒微观是可发表的组合,内生宏观等 agent 数量上千再说。

## 四、优先级路线图

> **状态(2026-07-04):P0-P3 已全部实现并通过测试**(62 个 economy 测试,含 370 天守恒审计;bench --synthetic Track A PASS)。测试文件:`tests/test_economy_module.py`、`test_economy_conservation.py`、`test_economy_credit_market.py`、`test_economy_routing_loans.py`。注意:税/社保改为真实代扣后,agent 现金流低于旧版 15-25%,2026-07 之前的 run 不可直接对比。

| 级别 | 事项 | 验证方式 |
|------|------|----------|
| **P0 正确性** | 裁员同步更新 `gross_monthly_salary`;删除/重设计赤字涨薪;economy 独立 RNG 流 | 单测:裁员后月结算税基下降;固定 seed 下增删无关 random 调用轨迹不变 |
| **P1 守恒闭环** | 分单位整数记账 + 每日对账测试;企业/政府/银行三个聚合部门账户,工资-消费-税收闭环 | 守恒审计测试进 GAWorld-Bench;个税减税实验重跑,可观察到二阶效应 |
| **P2 微观真实性** | 现金约束消费 + 简单信贷;共同市场因子;关键词表去重 | 破产 agent 消费收缩;跨 agent 投资收益相关性 > 0 |
| **P3 涌现** | 消费/房租路由到 agent;借贷走社交网络;分布级校准指标 | Gini 随时间内生演化;对标统计年鉴分布 |

## 五、一句话总结

先让每一分钱有来源、有去向、可对账(P0-P1),再让钱在 agent 之间流动起来(P2-P3);宏观脚本保留为实验旋钮,不急于内生化。
