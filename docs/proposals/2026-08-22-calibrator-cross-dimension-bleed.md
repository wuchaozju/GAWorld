# 标定器的跨维度串味：为什么输出端修不好，以及应该改哪里

2026-08-22 · 由 `docs/proposals/2026-08-21-personality-corpus-rewrite.md` §12.5 另开

## 1. 这件事对谁有影响

**对 51 位居民没有影响。** 他们的 OCEAN 分数是采样出来的，
`scripts/calibrate_big5.py` 只是个读者，读错了也不改变真值。

有影响的是它的**另一个生产用途：给外部导入的 agent 打分**（社交媒体导入那条路）。
那里没有真值兜底，标定器说什么就是什么。

## 2. 缺陷

对照臂（765 次调用）让一个独立打分器重读 51 份 `人格与行为倾向` 段落。
生成器**刻意写进去 155 格**，打分器把 **225 格**标成"有证据"。
多出来的 70 格：

- 与真值相关 **r = −0.01**（刻意写的那 153 格是 **+0.79**）
- 打分绝对值均值 0.59–0.85——**不是中点**，是看起来很确定的值
- 重标 sd **1.49**，而这些格子的真值 sd 只有 **0.31**：在真值最窄的地方给出最宽的分布
- 系统性偏移（Pearson 看不见）：宜人性 **+0.39**、开放性 **−0.33**、神经质 **−0.29**

**先排除了统计假象。** 这些格子按定义 |z| < 0.5，取值范围被截断，截断本身就会把相关往零压。
用 Thorndike Case II 修正算过：已知 [0.5,1) 档 r = 0.83、真值 sd = 0.76，
把 sd 压到 0.31 后**单靠截断**预期 r ≈ 0.52。实测 −0.01，差 0.53。
**截断解释不了这个差距。**

## 3. 四种输出端修法，全部失败

| 规则 | 判有证据 | 真的写了 | 凭空 | 精确率 | 真信号保留 |
|---|---|---|---|---|---|
| 现状（任一次 stated） | 225 | 153 | 72 | 68% | 100% |
| 证据自称「未涉及」则否决 | 223 | 152 | 71 | 68% | 99% |
| 多数票（2/3） | 201 | 142 | 59 | 71% | 93% |
| 一致票（3/3） | 181 | 134 | 47 | 74% | 88% |
| **证据须逐字出现在原文（新测）** | 97 | 86 | 11 | **89%** | **20%** |

前三种在 §12.4 记过。**第四种是这次补的**——它比关键词否决强得多，
所以在提出任何昂贵方案之前先免费试了一遍。

它把精确率抬到了 89%，代价是**丢掉 80% 的真信号**。而且接地度本身几乎不区分真假：
真写了的证据接地度中位 **0.43**，凭空的 **0.36**——因为模型在两种情况下都在转述，
不是照抄。**接地度测的是引用风格，不是真假。**

## 4. 为什么输出端一定修不好

上面四种都在用**输出的属性**去区分"真证据"和"串味证据"。
这条路走不通，因为串味的证据**本来就是原文里真实存在的句子**，
只是那句话是为**另一个维度**写的。

实测：在**没写**的维度里，有 11 条证据的接地度是 **1.00**——逐字照抄原文。
它们恰恰是最糟的几条：

| agent | 维度 | 真值 | 打分 | 逐字引用的证据 | 那句话其实是为谁写的 |
|---|---|---|---|---|---|
| 49 | A | −0.44 | **7.0** | 「朋友喊聚餐他基本不推辞，哪怕刚盯完十个小时」 | E（该人只写了 o/e） |
| 28 | O | −0.12 | **1.0** | 「不太顺着，宁可把约好的行程往后推」 | A（该人写了 e/a/n） |
| 47 | C | +0.30 | **6.0** | 「排期拉出来一项项过」 | N（该人只写了 n） |

**逐字接地度在最严重的编造上取到最大值。** 任何以"这句话是不是真的在原文里"
为判据的过滤器，在这里都会给出相反的答案。

另一个可直接观测的串味签名：**同一句话被当成两个不同维度的证据**。
400 个维度对里 34 对（8%）的证据 4-gram 重叠 > 0.15，最高的：

```
agent 11   o（写了）: 心血来潮拐进新开的小馆子，菜单都没翻就先坐下
           c（没写）: 心血来潮拐进新开小馆子，菜单都没翻就先坐下   ← 同一句
agent  6   e（写了）: 新同事加微信先搁置几天，社交不主动
           a（没写）: 新同事加微信先搁置几天，考虑后再加           ← 同一句
```

投票也救不了：255 格里 **181 格是 3/3 票**。**模型是自信地过度声称，不是在犹豫。**

## 5. 病因在输入端

现在的提问方式是：**给整段材料，问一个维度**。
材料里同时躺着为五个维度写的句子，而问题只指定了一个维度——
模型必须在"这段话里有没有关于 C 的证据"上做判断，
而它面对的是四句都在描述这个人的具体行为的话。
**"这句话算不算 C 的证据"没有硬边界**，于是它选择回答"算"。

`stated` 是**模型的自我报告**，而自我报告正是这里最不可信的东西。

## 6. 提议：逐句归因，让 `stated` 变成结构性事实

不再问"这段话里有没有 C"，改成对**每一句**问：

> 这一句话，落在五个维度里的哪一个（或哪些，或都不落）？方向和强度是多少？

然后**按维度聚合**：某个维度的分数，只由声称落在它上面的句子决定；
**没有任何一句落在它上面的维度，就是 unstated**。

这不是换个提示词。它把"有没有证据"从**模型的自我报告**变成
**聚合过程的结构性事实**——和语料重写那次是同一个动作：
把独立性做成采样器的构造性质，而不是事后去测的东西。

**为什么这能切断串味**：模型一次只看一句话，
没有"另外四个维度的材料"可供借用。agent 49 那句「朋友喊聚餐他基本不推辞」
仍然可能被归到 A，但那时它是**一次公开的归因**，会在聚合里和
它同时被归到 E 这件事一起显示出来——而不是藏在"A 有证据"这个断言背后。

### 6.1 成本：比现在便宜

51 份段落共 **160 句**（中位 3 句/人，句长中位 45 字）。

| 方案 | 调用数 |
|---|---|
| 现状（整段 × 5 维 × 3 次） | **765** |
| 逐句 × 1 次 | 160 |
| 逐句 × 2 次 | 320 |
| **逐句 × 3 次（建议）** | **480** |

### 6.2 验收判据（先写死）

有真值可比，这是这件事难得的地方——判据可以量化：

| | 判据 | 现状 |
|---|---|---|
| 主 | 刻意写了的 155 格上 r ≥ **0.79** | 0.79（不许变差） |
| **关键** | `stated` 的精确率 ≥ **90%** | **68%** |
| 召回 | 真信号保留 ≥ **85%** | 100%（一致票 88%） |
| 偏移 | 每个维度的系统偏移 \|bias\| ≤ **0.20** | A +0.39 / O −0.33 / N −0.29 |

主判据不许变差这条是必须的：逐句看会丢上下文，
**换来精确率却赔掉相关，是把一个问题换成另一个问题。**

### 6.3 零成本预演（跑之前必做）

沿用本项目已成惯例的做法：
用真值直接算出"每个维度有多少句可归"，预测 unstated 的应有比例；
再用假打分器（按句子里的关键词随机归因）跑一遍聚合，
确认 harness 在植入效应时测得出、在纯噪声下不假阳。

## 7. 待拍板

- **D1 归因是单选还是多选？** 一句话可以合法地同时说明两个维度
  （「朋友喊聚餐基本不推辞」既是高 E 也可能是高 A）。
  单选能把 8% 的重叠压到 0，但会强迫模型在合法的双关上二选一。
  倾向：**多选，但要求给出每个维度的强度**，让重叠变得可见而不是被禁止。
- **D2 要不要给模型"以上都不是"？** 必须要，否则每句话都会被塞进某个维度。
  倾向：**要**，且在提示词里把它写成一个正常答案而不是失败。
- **D3 句子怎么切？** 现在按 `。；！？` 切得到 160 句（min 1，max 6）。
  只有 1 句的段落（短的那几份）逐句等于整段，串味风险照旧。
  倾向：**接受**，并在结果里把"只有 1–2 句的人"单独标出来。
- **D4 先在 51 人上验，还是直接上导入路径？**
  倾向：**先在 51 人上验**——只有这里有真值，是唯一能判死判活的地方。

## 8. 不在本提案范围

- 不改 51 位居民的分数（采样出来的，标定器只是读者）。
- 不改生成器。§12 已验证 traits→text 成立（r = 0.79）；
  有问题的是反方向的读者，不是写者。
- 不碰 `max_tokens`、不碰导入路径的其他部分。

## 9. 已实现：`scripts/calibrate_big5_by_sentence.py`（2026-08-22）

按 §6 建好了，判据写死在脚本里、每次开跑前先打印。零调用的两步先做完了。

### 9.1 预演

| | |
|---|---|
| 居民 / 句子 | 51 / **160**（中位 3，min 1，max 6） |
| **调用数** | 160 × 3 = **480**（一次性打分器 765） |
| 只有 1–2 句的居民 | **14 位**（D3 里说的那批，结果表会单独标） |

### 9.2 自检：正负对照，用假打分器，零调用

| 对照 | 精确率 | 召回率 | 写了的格子 r | 是否符合预期 |
|---|---|---|---|---|
| 正（干净打分器） | **100%** | 95% | 0.962 | ✅ 四条判据全过 |
| 负（串味 leak=0.5） | **65%** | 95% | 0.963 | ✅ 只有精确率挂 |

负对照只在精确率上挂、r 和召回照过——**这正是要抓的那个缺陷的形状**：
串味不伤害"写了的格子"，只污染"有没有证据"这个判断。判据分得开。

### 9.3 自检又抓出了我自己写的对照里的一个毛病

第一版假打分器每句**只挑一个**真实维度（`rng.choice(real)`）。
每人平均 3.1 句、3.0 个写了的维度，随机挑覆盖不全，
于是**正对照的召回率只有 72%，判据 85% 判它 FAIL**——
一个本该通过的方法会被我的对照判死。

改成"每个真实维度以 0.7 概率被注意到"之后，正对照召回 95%，四条全过。
和 A4 那次上限判据的毛病是同一类：**对照本身也得先被证明是对的**，
否则它给出的"未达标"不知道是在说方法还是在说对照。

### 9.4 怎么跑

```bash
python scripts/calibrate_big5_by_sentence.py --dry-run     # 零调用
python scripts/calibrate_big5_by_sentence.py --self-test   # 零调用
python scripts/calibrate_big5_by_sentence.py               # 480 次调用
python scripts/calibrate_big5_by_sentence.py --resume      # 断点续跑
python scripts/calibrate_big5_by_sentence.py --analyse-only
```

逐条样本落 `output/traits/by_sentence.jsonl`。
**未全部通过就不要切换导入路径**——脚本自己会这么印。
