# 组织智能：比较组织方式并用于合作任务

入口：控制台 → 研究工作台 → **组织智能**，或 `/site/dashboard/research.html?tab=organization-intelligence`。

## 六步操作

1. **提供组织材料**：上传有可提取文字的 PDF、TXT、Markdown，或粘贴组织方式描述。选择模型，点击“分析组织方式”。核对分工、通信、决策、审阅及其原文来源，再点“采用这份组织方式”。没有材料时可以使用明确标注的可编辑示例。
2. **选择对照方式**：随机网络、全员互联、层级组织或独立作答后汇总。默认自动识别是比较通信结构，还是比较包含分工、审阅、决策的整套方式。只比较结构时可以明确选择让其他规则保持一致。
3. **选择问题**：使用分散信息整合、约束资源分配题库，或导入自己的 benchmark。系统检查字段、重复编号、局部信息数量和评分要求，并显示预览。
4. **设置对比实验**：选择与角色数量相同的居民，设置每题重复次数和资源上限。先点“保存实验设置”，再点“开始实验”。保存本身不会调用实验模型。材料解读会调用模型，实际实验和开放题评审也会调用模型。
5. **分析结果**：查看两组成绩、配对差异与区间、完成率、实际调用、耗时和探索性题型比较。可以暂停、继续、终止，下载报告、逐题 CSV、实验设置和完整调用记录。
6. **用于合作任务**：保存组织方式名称，进入“合作任务”，在“组织方式”中选择它并匹配人数。未出现新保存的方式时点击“刷新组织方式”。组织规则已确定分工和汇总方式，不再使用默认流程的负责人和角色覆盖设置。

研究运行使用两份隔离状态，不写回居民记忆。组织库只保存规则与证据范围，不保存题目答案或实验聊天记录。修改规则需要另存版本，历史实验和已经开始的任务保留原有快照。

## 导入 benchmark

支持 JSONL 和 CSV，文件不超过 2 MB，每个题库 1–1000 题。每题至少包含 `id`、`category`、`prompt`；编号是唯一的字符串。

精确匹配题的 JSONL 示例：

```jsonl
{"id":"q1","category":"逻辑判断","prompt":"如果所有A都是B，且x属于A，x是否属于B？answer只填是或否。","reference":"是"}
{"id":"q2","category":"信息整合","prompt":"选择总收益最高的方案。answer填A或B。","options":["A","B"],"observations":["A的第一项收益10，B的第一项收益2","A的第二项收益1，B的第二项收益12"],"reference":"B"}
```

第二题声明了两份局部信息，必须用两位成员的组织方式运行。没有 `observations` 时所有成员看到相同的公开题干。每份局部信息只能由其对应角色看到；最终汇总与审阅依据组织规则开放相应成果。

CSV 示例：

```csv
id,category,prompt,reference
q1,逻辑判断,请输出字母A,A
q2,逻辑判断,请输出字母B,B
```

字段名称不同可以填写映射，例如 `{"prompt":"question","reference":"answer"}`；未改名的标准字段继续使用原名称。CSV 中的 `options`、`observations`、`constraints` 采用 JSON 单元格，按 CSV 规则转义引号。

评分方式：

- **精确匹配**：最终 JSON 中的 `answer` 与 `reference` 按 JSON 值精确匹配；不会自动把错误格式修成正确答案。
- **选择题**：`options` 为选项 ID 列表或以 ID 为键的对象，`reference` 必须是其中一个选项。提交其他选项、对象或空答案均不能计为正常完成。
- **约束与目标值**：`answer` 是从 0 开始的项目编号列表。`constraints` 提供 `costs`、`values`、`capacity`、`optimum`；系统重新计算有界背包问题的最优值，拒绝伪造的 `optimum`。成绩为可行解收益除以最优收益，违反约束为 0。题干或局部信息必须提供成员解题所需的成本、收益和预算；评分数据不会被自动放入成员提示词。
- **固定量表的模型评审**：每题提供 `rubric`，说明 0–1 的评分标准。使用实验固定的模型评审，不透露候选/对照标签；评审请求单独记录并计入总调用上限。缺失最终答案直接记为失败，不向评审模型索取高分。

参考答案、最优值等评分数据只交给评分端。上传文件不支持 Python 脚本或任意代码评分器。

## 怎样解读结论

默认主指标为 0–1 成绩，越高越好。系统在同一道题、同一次重复内比较候选与对照，再按题目聚合；同题多次调用不能当作更多独立题目。95% 区间使用固定种子的题目簇 bootstrap。

- 少于 30 道独立题，只给探索性结果。30 是最低报告门槛，不是统计功效保证。
- 数据完整且差异区间下界超过预设最小改善幅度，才报告有优势证据；区间上界低于负的该幅度，报告更差。
- 其余完整结果显示“尚无充分证据表明更有效”，不能解释为两组等效。
- 数据不完整、评分缺失或协议不一致时，暂不判断。无效答案和任务预算耗尽按预先声明的失败分计入，网络等基础设施中断保留证据供继续。
- 调用次数和字符不是 token 或金额。模型未返回可靠计量时明确标为未知。成绩高但开销大，也必须分别判断。

组织库会附带原实验的模型、人数、题库及结论状态。换用题型、模型或人数时，原来的优势证据不自动适用。保存规则不代表认证其优越性。

## 首版范围

支持固定角色、按通信图交换上一轮消息、交叉审阅、有限修订、投票或指定成员汇总，以及按轮数或预算停止。每道题重置状态；跨题学习、成员更替、规则自我演化等机制需要专门协议，当前会明确提示不支持。

历史 OI-1 大模型实验和 OI-2 固定程序实验仍在“专题与历史实验”中查看，不能与新对照实验合并为同一项研究。固定程序、模拟模型测试和真实模型实验的证据必须分别解读。


## 自定义对照与运行控制

在“选择对照方式”选择“自定义输入”，填写组织如何分工、交流和作决定，点击“生成对照规则”。生成会调用当前模型；系统要求对照与候选人数相同。核对卡片及可展开的完整规则后，点击“采用此对照方式”，再选择题库并保存实验。修改描述或规则后需要重新采用。选择“只比较通信结构”时，两组的分工、轮数、决策和审阅会统一，右侧卡片显示统一后的实际规则。

实验运行中可以点击“暂停”。页面先显示“正在暂停”，当前已发出的请求结束并保存回答后变为“已暂停”；此时可继续或终止。暂停不会撤销已发出的模型请求。点击“继续实验”会复用已经保存的回答，只执行后续步骤。

请求出错时保留进度，结果页显示“重新运行（保留进度）”。对于 HTTP 429，页面显示服务限制类型和最早可重试时间；等待期间按钮不可点击，达到时间后仍需手动点击，且服务商可能尚未恢复额度。系统不会自动重试或切换模型。新实验相邻实际请求至少间隔10秒；其他应用共用模型额度时仍可能触发限流。

右侧记录可直接打开，包括保存了历史错误的实验。记录显示创建时间、状态和完成数量，当前实验会高亮；打开、保存和重试时按钮显示处理中，防止重复提交。刷新已保存实验的链接会恢复该记录。

执行版本变化时，仅对已验证兼容的版本创建恢复副本，先核对已有提示词、回答和成绩，保留原记录。尚未启动的恢复副本遇到再次更新时，会重新核对原实验。成员、题目、模型或关键规则改变时不能把原回答混入新实验。开放题的无效评审回答保留在审计中，手动重试仍受原先每单元2次评审请求上限约束；达到上限后页面提示另建实验。
