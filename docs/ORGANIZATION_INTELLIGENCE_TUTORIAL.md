# 组织智能实验模板

研究工作台 → **组织智能**，或 `/site/dashboard/research.html?tab=organization-intelligence`。

当前默认模板为 **OI-2《组织如何保存决策能力？》**，纯规则、零外部模型调用。旧《人换了，组织还会吗？》保留在历史 OI-1 区域。两者均为独立研究任务，不会改写城市的组织账户、规则或居民记忆，也不混合数据。

## OI-2 操作与研究边界

1. 页面先核对服务地址、PID、引擎版本、执行构建与工作区构建。源码改变后，创建按钮停用；重启实际使用的服务并刷新。冻结研究的worker从其已校验源码字节加载，不读取工作区代码或未校验字节码。
2. 设置种子数（默认10）与起始种子，点击「生成并冻结 OI-2 协议」。冻结后仍未启动。点击「启动冻结研究」开始零外部调用的机制实验。
3. 每个种子有4份训练状态，各训练10题，再克隆为原成员/全员更替两支，各测试20题。共八个测试条件、200个任务/种子；默认400道训练与1600道测试，共2000个任务。人工角色分别掌握需求、道路与资源；没有调用乌镇居民或LLM。
4. P0是等权提案表决，P1是带来源的证据汇集、去重与有限核验；M0无跨任务组织来源计数，M1保留；T1清空私人经历。当前任务沟通与长期组织记忆分开。来源可靠率、局部噪声、核验价格和成本定义全部冻结。
5. 训练只根据所选方案公开的分项结果更新有限Beta计数；测试记忆冻结且不提供反馈。真值只用于付费核验与环境评分。每题至多6条符号消息和2次核验；净收益扣通信、核验和延迟成本。
6. 「暂停」在原子任务提交边界生效。「继续同一研究」保留原ID、图依赖、已提交动作和状态，不另建样本。服务重启后首次读取该世界研究页会接续持久化的运行意图；暂停研究不会被自动启动。已在运行的独立worker可跨Dashboard重启继续执行。
7. 数据不完整时只显示进度。完整后给出八条件均值和按独立种子配对的效应；主比较为全员替换、证据程序下M1−M0净收益，bootstrap区间不以任务数冒充独立组织样本。便宜/昂贵核验、可靠/误导共同信息的分层结果全部保留。

默认产物：`output/research/organization_intelligence/v2/<id>/`；多用户沿当前世界研究目录隔离，并校验所有者。

- `tasks.sqlite`：冻结协议、依赖任务、租约、逐动作证据、得分和组织状态；一次事务提交完整任务，防止状态重复应用。
- `bundle/manifest.json` 与 `bundle/engine/*.py`：实际执行的冻结构建；源码完整性逐文件校验。
- `protocol.json`：预注册参数、主比较、成本、规则与结论边界。
- `results.json`：完整性判定、条件统计、配对差与逐任务动作证据；`report.md` 为中文说明。
- `worker.log`：隔离执行器诊断。完成任务但发布报告前中断时，可幂等补齐产物。

API前缀 `/api/research/organization-intelligence/v2`：GET上下文、POST冻结（必须携带`expected_build`）；GET `/<id>`、`/<id>/protocol`、`/<id>/results`、`/<id>/export`；POST `/<id>/run`（同样核对冻结构建）、`/<id>/pause`。此引擎不经过provider配额门，所有权与世界权限仍生效。

本轮研究的是研究者指定规则在人工任务中的机制效果；制度自主形成、环境突变下的旧记忆损害、语言协商与真人外部效度都尚未验证。记录的报告数、去重数是流程结构计数，不能冒充证据的因果贡献。未来接入LLM须另立能力探测、远端请求未知交付与调用预算协议；当前离线队列不声称已解决远端“恰好调用一次”。

## 历史 OI-1 操作

1. 选择模型、运行组数与种子。页面显示当前世界/城市，居民从当前世界文件读取；城市变更在控制台完成。
2. 点击「生成并冻结实验协议」。这一步不调用模型；保存模型指纹、六位成年居民的小档案、任务真值、随机种子、评分和调用预算。每组独立抽样，组间可能重用居民。
3. 检查协议后点击「按冻结协议启动研究」。模型和代码若已变化，将拒绝启动；请新建研究。每份协议只运行一次。
4. 在研究卡查看实际请求/HTTP数量、原始提示词和回答、活动/日历时间、进度及粗略ETA。停止在模型请求边界生效，在途调用仍可能完成。
5. 全部完成后下载报告、冻结协议。原始日志保留在研究目录。失败、中止、进程退出都保留已有数据，不自动重试、补零或切换模型。

## 预注册设计 OI-1.2

OI-1 的首批真实请求暴露了未标注数组的任务理解歧义，已停止并单独保存为接口诊断。OI-1.1 把所有模型可见观察、反馈改为带 `plan_id` 的对象，并明确属性名、编号和消息来源；随机任务、评分及实验条件保持原设计。两版数据不混合。

每组由三个原成员和三个替换成员构成。每人掌握需求、道路、物资中的一种属性；四个救援方案的真实效用是这三个属性的加权和。权重由程序随机分配为1、3、7的一个排列，模型只能通过训练反馈推断。三道训练题给出方案真实得分，三道新题不给结果反馈。

训练分别执行组织通信、独立判断汇总、单智能体集中信息。每题均四次模型调用。组织通信中前三次为独立角色报告，第四次由角色0作决定；独立汇总第四次仅让角色0私下复核，再对三人票数取多数，同票取较小方案编号；集中单智能体用相同居民小档案作四次连续推理，掌握全部属性。

组织训练结束后用一次调用形成共享档案。测试六个条件：原成员有/无档案、全员更替有/无档案、独立汇总、集中单智能体。原成员保留训练时各自实际收到的观察、消息和反馈；替换成员不获得这些私人经验。测试期间每道题都是从同一冻结训练状态开始，不把测试结果加入记忆。

每组109次请求，默认三组327次，每次输出上限2048 token、温度0.3，无模型回退或自动重试。OI-1.2 的请求开始间隔至少10秒，串行执行；327次仅按间隔计算约需54分钟，实际耗时会受推理、限流与手动等待影响。实际输入长度因信息与记忆条件而异；本模板没有宣称严格等输入token。档案归纳的额外调用单列。

主指标是选择效用/本题最优效用；次指标为最优选择率。按运行组计算配对差异：组织通信相对独立汇总/集中单智能体（均无共享档案）、更替后的档案收益、有档案的更替效应、档案与更替交互。三个任务不是三个独立组织。默认三组只做描述性比较，不输出显著性判定或“证明组织更聪明”。

## 产物与边界

单人默认世界：`output/research/organization_intelligence/<id>/`。多用户世界：当前世界目录下 `research/organization_intelligence/<id>/`，另校验用户与世界所有权。

- `protocol.json`：冻结输入与任务真值；仅供研究者审计，模型按角色得到局部观察。
- `study.json`：状态、评分、组织档案、私人训练历史、时间与遥测。
- `events.jsonl`：每次请求开始与响应结束事件，含提示词、回答和格式错误。
- `providers.sqlite`：实际HTTP和provider尝试统计。
- `report.md`：完成/失败/停止时生成，也可通过API实时导出。

API 前缀 `/api/research/organization-intelligence`：GET列表和模板上下文，POST冻结；GET `/<id>`、`/<id>/logs?offset=0`、`/<id>/export`；POST `/<id>/run`、`/<id>/stop`、`/<id>/recover`。所有路径均列入OpenAPI；真实调用启动受成员配额限制。

模型权重不训练；所谓学习是上下文中的经验与共享档案。此版不模拟组织自发形成、制度竞争、环境突变或真实救援动力学。结果只适用于这个受控人工任务，推广到现实组织需要额外验证。模型服务未返回的实际token数和金额记为不可用，不用字符数替代。


## 限流、格式与断点恢复（OI-1.2）

- **HTTP 429 / MiniMax 2062**：服务商拒绝了请求，程序将研究标为「等待配额恢复 · 断点已保存」，不再提交下一次请求。2062 是 Token Plan 限制，延长等待不能保证套餐马上恢复。页面显示的是本地退避下限，不承诺服务商重置时间。
- 普通429的本地退避至少60秒，2062至少300秒；服务商 Retry-After 更长时遵循更长时间。同一世界同一冻结模型的其他新研究也受该退避限制。等待后仍需显式启动恢复，不会后台自动重试、升级套餐、切为按量付费或改模型。其他工具/世界对同一账户的用量仍可能使服务商继续拒绝。
- 点击「从断点生成恢复协议」只创建一份关联的新记录，不调用模型。它保留原模型、居民、题库、种子和评分，冻结有效回答快照及其哈希；启动后按原提示词逐步复用这些回答来重建记忆，只请求尚未完成的步骤。原研究文件保持原样，恢复链是同一次研究的延续，不计作新的独立重复，也不汇总其他失败记录的结果。旧OI-1任务接口有歧义，不能续跑。
- 模型配置或断点校验不一致会拒绝恢复。旧OI-1.1协议仍按旧规则判定；恢复协议明确升级到OI-1.2。代码变更后需要重新生成恢复草稿。恢复时若再次停止，原快照中尚未重放的有效回答仍保留。
- OI-1.2 允许一种**不调用模型的保守格式恢复**：只处理完整的 `choice`+`message` 对象里未转义的引号或换行。方案编号必须明确，消息边界必须可确定；缺字段、额外字段、重复字段、无效编号和截断对象均拒绝。不改选择或补写推理，原始回答和格式恢复标记写入审计。不会回头修改旧版失败记录。
- 进度和有效回答包含复用部分；HTTP/失败统计只计当前记录实际新提交。字符数包含复用回答，不是新增费用。ETA依据新调用的速度加上未来请求间隔估算；等待计入暂停时间。最终报告写明来源、复用数和本地格式恢复次数。传输层不提供实际token/金额，仍不作推算。

本地断点机制不能解除服务商套餐限制。先确认账户额度恢复，再从已有回答继续，通常比重复创建并从头执行更节省调用。
