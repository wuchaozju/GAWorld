# 组织智能实验模板

研究工作台 → **组织智能**，或 `/site/dashboard/research.html?tab=organization-intelligence`。

首个模板《人换了，组织还会吗？》检验分散信息如何汇集，以及共享档案是否能帮助新成员保留任务能力。它是独立研究任务，不会改写生产城市的组织账户、规则或居民记忆。

## 操作

1. 选择模型、运行组数与种子。页面显示当前世界/城市，居民从当前世界文件读取；城市变更在控制台完成。
2. 点击「生成并冻结实验协议」。这一步不调用模型；保存模型指纹、六位成年居民的小档案、任务真值、随机种子、评分和调用预算。每组独立抽样，组间可能重用居民。
3. 检查协议后点击「按冻结协议启动研究」。模型和代码若已变化，将拒绝启动；请新建研究。每份协议只运行一次。
4. 在研究卡查看实际请求/HTTP数量、原始提示词和回答、活动/日历时间、进度及粗略ETA。停止在模型请求边界生效，在途调用仍可能完成。
5. 全部完成后下载报告、冻结协议。原始日志保留在研究目录。失败、中止、进程退出都保留已有数据，不自动重试、补零、修复答案或切换模型。

## 预注册设计 OI-1.1

OI-1 的首批真实请求暴露了未标注数组的任务理解歧义，已停止并单独保存为接口诊断。OI-1.1 把所有模型可见观察、反馈改为带 `plan_id` 的对象，并明确属性名、编号和消息来源；随机任务、评分及实验条件保持原设计。两版数据不混合。

每组由三个原成员和三个替换成员构成。每人掌握需求、道路、物资中的一种属性；四个救援方案的真实效用是这三个属性的加权和。权重由程序随机分配为1、3、7的一个排列，模型只能通过训练反馈推断。三道训练题给出方案真实得分，三道新题不给结果反馈。

训练分别执行组织通信、独立判断汇总、单智能体集中信息。每题均四次模型调用。组织通信中前三次为独立角色报告，第四次由角色0作决定；独立汇总第四次仅让角色0私下复核，再对三人票数取多数，同票取较小方案编号；集中单智能体用相同居民小档案作四次连续推理，掌握全部属性。

组织训练结束后用一次调用形成共享档案。测试六个条件：原成员有/无档案、全员更替有/无档案、独立汇总、集中单智能体。原成员保留训练时各自实际收到的观察、消息和反馈；替换成员不获得这些私人经验。测试期间每道题都是从同一冻结训练状态开始，不把测试结果加入记忆。

每组109次请求，默认三组327次，每次输出上限2048 token、温度0.3，无模型回退或自动重试。实际输入长度因信息与记忆条件而异；本模板没有宣称严格等输入token。档案归纳的额外调用单列。

主指标是选择效用/本题最优效用；次指标为最优选择率。按运行组计算配对差异：组织通信相对独立汇总/集中单智能体（均无共享档案）、更替后的档案收益、有档案的更替效应、档案与更替交互。三个任务不是三个独立组织。默认三组只做描述性比较，不输出显著性判定或“证明组织更聪明”。

## 产物与边界

单人默认世界：`output/research/organization_intelligence/<id>/`。多用户世界：当前世界目录下 `research/organization_intelligence/<id>/`，另校验用户与世界所有权。

- `protocol.json`：冻结输入与任务真值；仅供研究者审计，模型按角色得到局部观察。
- `study.json`：状态、评分、组织档案、私人训练历史、时间与遥测。
- `events.jsonl`：每次请求开始与响应结束事件，含提示词、回答和格式错误。
- `providers.sqlite`：实际HTTP和provider尝试统计。
- `report.md`：完成/失败/停止时生成，也可通过API实时导出。

API 前缀 `/api/research/organization-intelligence`：GET列表和模板上下文，POST冻结；GET `/<id>`、`/<id>/logs?offset=0`、`/<id>/export`；POST `/<id>/run`、`/<id>/stop`。所有路径均列入OpenAPI；真实调用启动受成员配额限制。

模型权重不训练；所谓学习是上下文中的经验与共享档案。此版不模拟组织自发形成、制度竞争、环境突变或真实救援动力学。结果只适用于这个受控人工任务，推广到现实组织需要额外验证。模型服务未返回的实际token数和金额记为不可用，不用字符数替代。
