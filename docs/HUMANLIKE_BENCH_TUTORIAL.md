# 人类相似度基准（HumanLike Bench）教程

> 测一件事：**GAWorld 的居民像不像真人。**
>
> 库：`gaworld/humanlike/`（**设计已定稿，实现未落地**）｜CLI：`benchmark/humanlike_bench.py`（目标接口）｜
> 锚点清单：`gaworld/humanlike/anchors.json`｜结果：`benchmark/results/humanlike_scorecard.{json,md}`
>
> 与既有基准的关系：**并列，不替代**。
> `benchmark/GAWORLD_BENCH_DESIGN.md` 测"群体统计 / 因果引擎"（Track A–E）；
> `benchmark/GAWORLD_RUBRIC_BENCH.md` 测"内部自洽与 rubric 合规"（Track R1–R4）。
> 本套件测的是**第三件事**：仿真行为与**真实人群的统计规律**是否对得上。

## 0. 这是什么

一个**对照真实人群统计规律**的评测基准。

做法很直白：从一次仿真 run 里，把每个居民的行为序列抽成可比的观测量
（几点睡、事件间隔多长、情绪多黏、移动多远、计划落空几次、关系对不对称……），
再拿这些观测量去对**已发表的真人研究**给出的参考值与参考分布。

```
run 产物 ──► 观测量 ──► 带内判据(J1) ─┐
   │            │                       ├─► 签名通过/不通过 ─► 族 ─► Track H
   │            └──► 分布判据(J2) ─────┘        ▲
   │                                     真人对照流(H 型)
   └──► 机器型对照流(M 型) ──► 尺子自证 ────────┘
```

**关键点：这套基准不请真人参与，也不调 LLM 判分。**
全部签名都是对仿真产物做的规则计算；"真人"一侧由文献锚点参数化生成。
所以它可以在 CI 里跑，也可以在不同模型、不同城市、不同版本之间反复比。

## 1. 为什么不能直接问"像不像"

直接让一个模型看一段仿真日记，打个 1–5 分，会得到一堆没法用的结果：
分数挤在 3.8–4.2 之间、对文笔好的系统性偏高、换个模型排序就变。
原因是这个问题**没有可验证的判据**，模型只能输出语感。

`benchmark/GAWORLD_RUBRIC_BENCH.md` 已经把这件事做了一半（rubric-as-reward：拆 checklist、
证据绑定、消融判别力），但它留下一条明确的缺口：

> 消融是必要不充分。通过判别力检验只证明 judge 能识别人为损坏，
> **不证明它能识别"生成式模型特有的、结构完好的假"**。

本套件正面补这个洞：**M 型对照流就是"结构完好的假"**——它不是被打乱的样本，
它是一个"太完美、太规律、太一致"的合成人群。如果一把尺分不出它，这把尺就没有分辨率。

## 2. 这套基准测的是哪个命题

分三层，一层比一层硬：

| 层 | 命题 | 证据强度 |
|---|---|---|
| **结构层** | 单个居民的行为序列，统计形状像不像真人 | 强：真人规律是独立发现，不是 GAWorld 的参数 |
| **分布层** | 一群居民合起来，分布落在真人分布的哪个位置 | 强：带 W1/KS 距离与效应量 |
| **判别层** | 这把尺能不能把"结构完好的假"分出来 | 最强：尺子无效 = 所有分数作废 |

**它不测什么**（必须先讲清楚，否则会误用）：

- ❌ 不测"这段文字读起来像不像人写的"——那是 Track R1 与真人盲测（`谁是真人`游戏）的地盘。
- ❌ 不测仿真在宏观统计上像不像真实城市——那是 Track A，且 Track A 有"回显参数"的循环风险。
- ❌ 不测因果推断对不对——那是 Track C。
- ❌ **不判定"这个 agent 是人"**。它只回答"这批仿真行为的统计形状，和真人文献值差多远"。

## 3. 五个签名族、十五条签名

每条签名声明四件事：**观测量**（从哪个产物算什么）、**真人锚点**、
**判据组合**、**provenance**（这一条是否被 GAWorld 直接参数化）。

### 3.1 provenance：先分清"证据"和"卫生检查"

| 级别 | 含义 | 读法 |
|---|---|---|
| **低** ✅ | **没有被直接参数化**，真人值是独立发现 | 通过 = **真有证据** |
| 中 | 部分被参数化 | 通过 = 弱证据 |
| **高** ⚠️ | **基本被模型参数决定**（如日程表、恩格尔曲线） | 通过 = **只是实现没 bug**，不构成"像人"的证据 |

这条纪律来自 `benchmark/MECHANISM_PROVENANCE.md` 的教训：拿自己写进模型的数去验证，
量的是回显，不是模型。**分项报告里低 provenance 与高 provenance 必须分栏，不许混进同一个均值。**

### 3.2 签名表

| ID | 族 | 看什么 | 观测量（数据源） | 真人锚点（**待核**，见 §15） | 判据 | prov |
|---|---|---|---|---|---|---|
| **A1** | 节律 | 昼夜活动形状 | 每小时活动强度曲线 → 峰谷比、双峰指数（episodes `time` + 活动类型） | time-use 调查的典型 hourly profile：双峰（早/晚）、午间低谷 | J1+J2 | **高** ⚠️ |
| **A2** | 节律 | 几点睡、睡多久 | 每人睡眠窗起点 / 时长 / 跨人离散度（**代理量**） | actigraphy / 时间利用调查：onset 集中 23:00–01:00，时长 6.5–8.5h，SD≈1h | J1+J2 | 中 |
| **A3** | 节律 | 醒着多久 | 非睡眠活动时长合计 ÷ 24h | 醒着约 15–17h | J1 | 中 |
| **B1** | 统计结构 | 事件节奏重不重尾 | 相邻事件间隔序列 → Fano factor、lognormal σ | 真人活动片段间隔重尾，Fano ≫ 1 | J1+J2 | 中 |
| **B2** | 统计结构 | 一件事做多久 | 活动片段时长分布 → 中位、长尾指数 | time-use 活动片段：中位约 30–45min，长尾到数小时 | J1+J2 | 中 |

| **B4** | 统计结构 | 行为够不够不均 | 活动类型频次 → Zipf α | 活动频次 Zipf，α≈1 | J1+J2 | **高** ⚠️ |
| **C1** | 情绪 | 情绪黏不黏 | `emotion` 序列 lag-1 自相关 ρ | affect inertia ρ≈0.6–0.8 | J1+J2 | 中 |
| **C2** | 情绪 | 情绪稳不稳 | var_within（个体内日间）÷ var_between（跨个体） | 个体内方差远小于跨个体 | J1+J2 | **低** ✅ |
| **C3** | 情绪 | 冲击多久才过去 | 事件后情绪差衰减 → 半衰期（天） | 重大事件情绪影响持续数周–数月 | J1+J2 | 中 |
| **D1** | 自述—实做 | 计划落空几次 | `scheduled_activity` ≠ `final_activity` 的比例 | 意向—行为鸿沟：约 1/3 行为未按计划执行 | J1+J2 | **低** ✅ |
| **D2** | 自述—实做 | 落空有没有理由 | 偏离时 `change_reason` 具体（非模板）的比例 | — | J1 only | **低** ✅ |
| **E1** | 社会 | 关系对不对称吗 | `social_partners` 双向匹配 → 单向边占比 | 人际非对称关系约 10–20% | J1+J2 | **低** ✅ |
| **E2** | 社会 | 互动集中在谁身上 | 互动数分布 → Gini | 真实互动高度不均 | J1+J2 | **低** ✅ |
| **E3** | 社会 | 有没有摩擦 | 含负向 `outcome` / `valence` 的互动占比 | 冲突率有限但非零 | J1 | 中 |

### 3.3 三条最尖锐的签名

**D1（计划—实做偏离率）** —— 真人**系统性地**不按计划活；
而"完美执行计划"是 AI 最强的气味信号之一。M 型对照流在这里就取 p = 0。
GAWorld 恰好有 `scheduled_activity → final_activity` 这条管道，把"生活的不完美"
变成一个可以数的数。

**C2（幸福适应方差比）** —— 个体内的日间情绪波动，真实世界里远小于个体之间的差异。
仿真 agent 常犯两个相反的错：剧情化（个体内方差过大）或麻木（方差为零）。
这一条两个方向都能抓。

**E1（单向关系占比）** —— 现实里存在相当比例的单向关系（照护、追随、单恋）；
过度对称的社交网络是 AI 味。

## 4. 真人锚点从哪来

**只用已发表的真人研究，不用自采样本**（至少 v1 不用）。每个锚点是一条**带出处**的记录，
存在 `gaworld/humanlike/anchors.json`：

```json
{
  "id": "C2",
  "statistic": "var_within / var_between（个体内日间情绪方差 ÷ 跨个体方差）",
  "value": null,
  "tolerance": null,
  "source": null,
  "population": null,
  "n": null,
  "uncertainty": null,
  "provenance": "low",
  "surrogate": { "generator": "emotion_ar1", "params": {} },
  "status": "TODO_VERIFY"
}
```

### 4.1 锚点纪律（硬约束）

> **`source` / `population` / `n` / `statistic` 四项缺任一 → 该签名记 `UNVERIFIED`，不参与计分。**

理由与仓库既有规矩一致：缺产物不是模型的失败，**缺证据也不是模型的失败**。
把一个没核实的数字写进评分，等于用"我们查了个数"冒充"我们查清了"。

同时要记 `uncertainty`（文献给的 CI，或显式标注的 ±x%）——
它不只是元数据，§6 的阈值与 §7 的敏感度分析都要用。

### 4.2 一个锚点，两个用途

H 型对照流的参数与 J1 的参考带**来自同一条 anchor 记录**——单一真相源。
锚点错了，两处一致地错；靠敏感度分析暴露，而不是靠两处不一致自曝。

## 5. 真人对照流与"机器型"对照流

每个签名声明 `surrogate_spec{generator, params, n_individuals, n_days}`。
生成的每个"合成个体"产出一串**与观测量同构**的观测
（C1 是一条 emotion 序列，不是一个数）。

### 5.1 H 型：参数取自锚点的真人

H 型的**参数不在代码里写死**，而是从锚点条目的 `surrogate.params` 读出来——
和 J1 的参考带同源（§4.2）。这样改一个锚点，判据与对照流一起变，不会出现两处打架。

**走通一个例子：C1（情绪惯性）**

```
观测量     : 一条 emotion 序列的 lag-1 自相关 ρ
H 型生成器 : emotion_ar1
  params   : { rho: <锚点值>, daily_amplitude: <锚点值>,
               event_rate: <锚点值>, shock_half_life: <锚点值> }
  产出     : n_individuals 个合成个体 × n_days 天的 emotion 序列
观测量同构 : 对每条序列算 lag-1 自相关 → 得到 n_individuals 个 ρ
```

注意 H 型产出的不是"一条标准曲线"，而是**一批有离散度的个体**——
τ 正是从这批个体的两两比较里取 95 分位，所以阈值自带"真人之间本来就有差别"这一层。

> **H 型不是"合成真人"**：它不模拟一个人怎么活，只生成**满足文献统计约束的观测序列**。
> 因此 "与真人不可区分" 这句话的真实含义是 **"与文献描述的真人不可区分"**（见 §13.3）。

### 5.2 M 型：同接口，参数取"AI 味的典型值"

| 签名 | H 型（真人） | M 型（机器） |
|---|---|---|
| A1 昼夜曲线 | 双峰、午间低谷 | 平坦或单峰 |
| A2 睡眠 | onset ≈ N(23.8h, σ=1.0h) | onset ≈ N(24.0, σ=0.15h)（人人同刻） |
| B1 事件间隔 | 对数正态，Fano ≫ 1 | 固定 4h，Fano ≈ 1 |
| B3 移动半径 | Lévy α≈2.6 | 截断高斯（非幂律） |
| B4 活动频次 | Zipf α≈1 | 均匀 |
| C1 情绪惯性 | AR(1) ρ≈0.72 | iid 噪声 ρ≈0.1 |
| C2 方差比 | var_within ≪ var_between | var_within ≈ var_between（剧情化） |
| C3 冲击半衰期 | ~21 天 | 0 天（当天归零）或 ∞（永久不变） |
| **D1 计划偏离率** | p≈0.35 | **p=0（完美执行＝回声）** |
| E1 单向边占比 | ~0.15 | 0（过度对称） |
| E2 互动 Gini | ~0.5 | 0（互动完全均匀） |

> 表中的**数值同样是待核锚点**（§15），此处先写形状与量级，值待核。

## 6. 怎么判：带内 + 分布双判据

每个签名出**两个独立判据**，各自报告，合并判定取 **AND**：

- **J1 带内**：仿真值是否落在真人参考带内。
- **J2 分布**：仿真观测 vs H 型对照流观测，报 Wasserstein₁ / KS / 均值差 / **方差比 sd_ratio**。

> **J1 过而 J2 不过 = "中心对、形状错"**，那正是要抓的失败模式
> （仿真人群的中心位置像真人，但离散程度、尾部形状不像——AI 味最重的一类失败）。
> 所以不能只留 J1，也不能用 OR 把 J2 放松掉。

### 6.1 阈值是数据定的，不是拍脑袋的

```
sep(S) = W1(H_S, M_S)            # 这把尺的分辨率上限：真人 vs 结构完好的假
gap(S) = W1(candidate_S, H_S)    # 被测对象离真人多远
τ(S)   = quantile₀.₉₅( W1(H_S^A, H_S^B) )   # 阈值 = H 型对自身的抽样波动 95 分位
判定   = gap(S) ≤ τ(S) →「与真人不可区分」
```

**τ 用"真人对真人"的距离定**：有限样本下真人之间本来就有波动，
阈值不能定得比这还严。这与 Track D「用真人自己的通过率做分母」是同一个思路。

距离计算复用仓库现成实现，**不重写**：
`gaworld/group/metrics.py` 的 `wasserstein1` / `ks_statistic` / `distribution_gap`
（后者已含 `mean_gap` 与 `sd_ratio`）。

### 6.2 锚点敏感度分析

每个 H 型参数带不确定度（§4.1 的 `uncertainty`），做 M 次扰动重算 `gap_ratio`，
输出 `flip_rate(S)` = 结论翻转比例。**flip_rate 高的签名标 `锚点脆弱`，不进 headline**，只作参考。

这是对"文献错了整套跟着错"的直接缓解：把结论的脆弱程度显式报出来，而不是默认它稳。

## 7. 尺子自证：M 型必须判不合格

> 每条有 surrogate 的签名必须满足 `sep(S) > 0`，
> 且 **M 型自身必须被判为"可区分"**（`gap(M) > τ`）。
> **M 型都能过 → 这条签名没有分辨率 → 作废**，从计分中剔除并进入功能缺口清单。

这与 Rubric-Bench 的消融检验同构，但**对象从"随机破坏"换成"结构完好的假"**——
正是 `GAWORLD_RUBRIC_BENCH.md` §7.2 点名的那个洞。这是 Track H 相对 Track R 的**主要增量**，
也是它能独立成立的根据。

### 7.1 Track H 的三态 gate

| 状态 | 条件 |
|---|---|
| `OK` | 锚点清单完整且已核 + 每条签名的 M 型负对照均判不合格 + 敏感度分析通过 |
| `UNVERIFIED` | 锚点缺必填字段 / 未跑负对照 / 样本量不足 → **不给分**，不是"记 0" |
| `UNTRUSTWORTHY` | 任一签名的 `sep(S) = 0`（尺子对该签名无分辨率） |
| `FIXTURE` | `--synthetic` 模式的结果。**永不覆盖真实 scorecard**（照抄现有规矩） |

## 8. 三档运行

| 档 | 触发 | 数据来源 | 新增 token | 用途 | 结论强度 |
|---|---|---|---|---|---|
| **夹具** `--synthetic` | CI 每次 | H/M 对照流自己造假 run 产物 | 0 | 管线自检 + 尺子自证 | `FIXTURE`，**永不进对外材料** |
| **快档**（门禁） | CI / 日常 | 已存在的 run 产物 | 0 | 回归监测：防止某签名从"过"掉到"不过" | 仅趋势，必须标"样本不足" |
| **慢档**（定论） | 手动 / 周期 | **专门受控 run** | 烧 LLM | 出对外分数、跨版本比较 | 可下结论，带 CI 与效应量 |

### 8.1 澄清：token 花在造数据，不在评分

**评分器本身零 token**——五族签名全是规则计算。
token 成本全部在**造数据端**。所以两档的区别是**样本量与结论强度**，不是"要不要调 LLM"。

### 8.2 受控评测 run 规格（慢档）

- cohort ≥ 12 agent（按 persona × 生命周期分层抽，**固定名单**写进 `run_meta.json`）
- 天数 ≥ 14 天，**全保真 tick loop**
- seed 固定；provider 固定并记录（混模型的分数不可比）；记录 git commit 与 `comparability_epoch`
- 产物落 `output/humanlike_runs/<run_id>/`；`run_meta.json` 记 seed / agent_ids / days / provider / epoch / 产物清单
- 实现：设 `CONFIG["random_seed"] / ["agent_ids"] / ["sim_days"] / ["run_output_dir"]` 后调 `run_simulation()`
  ——**与 `compare-event` 同一套路**（它就是靠 `--agent-id/--seed/--sim-days` 这么生效的），新增薄封装即可

> ⚠️ **已核实的硬约束**
> 快进 run **一条 episode 都不写**。`--fast-forward` 走 `generative_city_sim.py` 的
> `_run_fast_forward_step`，而 episode 的组装与落盘在 `gaworld/sim/_stages.py` 的 tick 阶段
> → **A/B/D/E 四族直接不可评**；月/年步长走同一分支，同样不可评。
> 所以慢档**必须**是 tick loop，**不能拿快进 run 充数**。

### 8.3 覆盖度与弃权

- 覆盖度 = 可评签名数 / 目标签名数；`score_H = mean(族通过率) × coverage`（沿用 Track A3 的覆盖度折扣）
- 缺产物 → **弃权**（不记 0 分）；锚点缺必填字段 → **UNVERIFIED**（不给分）；
  样本量不足 → 报 n 与 CI，**不给点估计结论**

> **现状警告**：仓库现有 `output/` 只有 11 个 agent 有 episodes、9 个有日记
> → **快档覆盖率会很低**，快档分数只能当回归信号，不能当"像不像真人"的结论。

## 9. 读分指南

### 9.1 scorecard 长什么样

```
HumanLike Bench Scorecard
  夹具 / 快档 / 慢档：<模式> ｜ 数据：<run 路径> ｜ 锚点版本：<hash>
  Trust gate: OK / UNVERIFIED / UNTRUSTWORTHY / FIXTURE
  覆盖度: 0.42  (可评 7/15)  ·  headline（最弱族）: <族>

  族分（按 provenance 分栏）
  低 provenance（真证据）
    R-C 情绪          0.50   (2/4)   ✅ C1 C2 C3 E2
    R-D 自述—实做    0.67   (2/3)   ✅ D1 D2 E1
  中/高 provenance（卫生检查）
    R-A 节律          n/a    (数据不足)
    R-B 统计结构      0.33   (1/3)   ⚠️ 高 provenance
```

### 9.2 四条读分规矩

1. **不塌缩为单一标量。** 输出分项 + 雷达图；headline = **最弱的族**（木桶原理），不是均值。
2. **先看 provenance 分栏，再看分数。** 高 provenance 的族过了，说明实现没 bug，不说明像人。
3. **先看 trust gate，再看分数。** gate 不 OK 时，上层分数仅供参考。
4. **看覆盖度，不要只看分数。** 只跑到 1/3 的签名时，那个 0.67 不代表什么。

### 9.3 一句话结论模板

> 在受控 run（12 agent × 14 天，seed 42，MiniMax-M3）下，**低 provenance 的 4 条签名通过 2 条**：
> 情绪方差比与计划偏离率与真人文献一致；情绪惯性与互动集中度不通过。
> 锚点 gate `UNVERIFIED`（C3 锚点缺 `n`），结论仅供内部参考。

## 11. 加一条签名

四步，**缺一步都不算完成**：

1. **写观测量提取器**（`features.py`）：纯函数，输入 run 产物片段，输出标量或序列。
   自带单测：已知输入 → 已知输出。
2. **写锚点条目**（`anchors.json`）：出处、人群、样本量、统计定义、值、容差、不确定度。
   **四要素缺一 → 这条签名上线即 `UNVERIFIED`。**
3. **写 H/M 参数**：H 型参数取自锚点；M 型参数取"这种失败模式的典型形态"。
   两者必须能产生**可测的差异**，否则第 4 步会把它作废。
4. **写单测**（这是关键一步）：
   - 正样本（合成的"真人样本"）必须**通过**；
   - **M 型必须不通过**；
   - 两者都做不到 → 观测量没有分辨率，重写。

---

## 12. 加一条锚点

1. 找到原文，确认**统计量定义**与你算的观测量**是同一个东西**
   （"平均通勤时长"和"单程通勤时耗中位数"不是一个东西）；
2. 记人群（哪国、哪年龄层、哪年）、样本量、统计量定义、值、不确定度；
3. 填进 `anchors.json`，把 `status` 从 `TODO_VERIFY` 改成 `VERIFIED`；
4. 跑 `--anchors-status` 与 `--self-check`，确认这条新锚点没有把 M 型放过；
5. 若新锚点改变了某条签名的结论，在报告里注明"锚点版本变更"——
   **锚点变更即断代**，跨锚点版本的分数不可比（与 rubric 版本断代同理）。

## 13. 局限与已知风险

1. **测不出"写不下来的"。** 真人的不可名状之处，这套方法系统性测不到。
   分数高不等于像人，只等于"没被这批签名抓到破绽"。
2. **文献口径是最大的风险源。** 锚点一旦误读，整条签名跟着错。
   缓解手段只有三条：出处必填、敏感度分析、锚点变更断代。**没有第四条。**
3. **H 型对照流是合成的。** 它由文献参数化生成，因此"与真人不可区分"这句话的真实含义是
   "与文献描述的真人不可区分"。**这不是图灵测试。**
4. **样本量是硬约束。** 12 agent × 14 天能支撑组级分布检验，撑不住细尾部分位；
   长尾签名（B2/B3）在这个规模上只能报区间，不能报结论。
5. **provenance 分栏会让 headline 很难看。** 这是对的，不是 bug。
6. **本套件与 Track R 不合并。** 两者判据体系不同（规则+文献锚点 vs LLM judge+消融），
   合并会让 Track R 的 `UNVERIFIED` 传染过来。

## 15. 待核清单

以下每一项都必须在 H4 阶段核实，**核实前不写进评分**。本表是 §4.1 锚点纪律的工作清单。

| 签名 | 需要核的东西 | 候选出处方向（**均未核实**） |
|---|---|---|
| A1 | 典型 hourly activity profile 的形状与峰谷比 | 时间利用调查（time-use survey）方法学文献 |
| A2 | 睡眠 onset 分布、时长分布、跨人离散度 | actigraphy 方法学文献；群体时间利用调查 |
| A3 | 每日清醒时长 | 同上 |
| B1 | 活动片段间隔的重尾程度（Fano / lognormal σ） | time-use "activity episode" 方法学文献 |
| B2 | 活动片段时长分布（中位、长尾） | 同上 |
| B3 | 人体移动半径的幂律指数 α | 人类移动网络文献（Lévy walk / Truncationless random walk 系列） |
| B4 | 活动类型频次的 Zipf 指数 | 行为频次 Zipf 文献 |
| C1 | 情绪惯性（相邻观测自相关 ρ）的典型范围 | affect inertia / 情绪稳定性研究 |
| C2 | 个体内 vs 跨个体情绪方差的比值 | 主观幸福感可测性研究（Deaton 一系） |
| C3 | 负面事件后情绪影响的持续时间 / 半衰期 | 情绪适应与事件影响持续性研究 |
| D1 | 意向—行为鸿沟（计划执行率） | intention–behavior gap / 自我报告时间使用准确性（Robinson 一系） |
| D2 | 偏离时给出具体理由的比例 | （可能无直接文献，需降级为"仅报告"） |
| E1 | 人际网络中非对称（单向）关系的比例 | 社会网络结构研究 |
| E2 | 互动/活动集中度（Gini） | 网络不平等研究 |
| E3 | 日常冲突/拒绝的发生率 | 冲突与亲密关系研究 |

**核对要求**：每条至少记下 —— 原文出处、人群、样本量、统计量定义、中心值、不确定度。
**拿不准口径的，宁可让这条签名 `UNVERIFIED`，不要估一个数填进去。**
