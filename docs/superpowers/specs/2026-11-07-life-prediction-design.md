# 人生预测（Life Prediction）— 设计说明

日期：2026-11-07
范围：Agent Studio 第 1 步（身份）的两张长文卡 —— 迁移「生成自传」+ 新增「人生预测」。

## 1. 目标

在 Agent Studio 里给一位居民写出**他的一生**：已经发生的那一半（自传），和还没发生的那一半
（人生预测）。两者用同一个人、同一种口吻，前者向后看，后者从终点向前看。

具体两件事：

1. 把「生成自传」从第 7 步（复核·部署）移到第 1 步（身份）。
2. 新增「人生预测」：用**未来时间的自传体**描述这位居民此后的一生，直至死亡，并提供三个可选输入：
   人生大致走向（文本）、人生随机性（程度）、时代动荡性（程度）。

## 2. 关键决策（含理由）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 人生预测放在哪一步 | 第 1 步（身份），与自传上下两张卡 | 自传是「已经发生的我」，预测是「将要成为的我」；并排才构成完整叙事。拆开则对照不可见。 |
| 两个「程度」的刻度 | 0–100 滑杆 + 两端定性说明 | 光给数字，读者不知道自己在调什么；服务端再把数字翻译成一段话交给模型。 |
| 正文篇幅 | 约 2 万字，与自传同等 | 两篇并排读，篇幅相当才有对照关系。 |
| 是否写进长期记忆 | **不写** | 自传是过去的事实，摘要进记忆是稳定的自我认知；预测是关于未来的假设，写进去居民会当成既定事实并照着演 —— 仿真便从「被检验的假设」变成「自己实现的预言」。 |
| 生成方式 | 一次模型调用（异步任务） | 交付物是文本本身，不是第二条仿真轨迹；三个参数只用来塑形，不用来产生可比较的对照实验。 |
| 代码归属 | 新模块 `gaworld/apps/life_prediction_api.py`；共用证据抽到 `gaworld/apps/resident_dossier.py` | 两个写作者看到的证据形状必须一致，但各自的提示词、任务名与落盘位置必须分开。 |

## 3. 架构

```
site/dashboard/studio.js
  stepIdentity()  ──►  autobiographyCard()   生成自传
                   └─►  lifePredictionCard() 人生预测（走向 + 两个滑杆）
        │  POST /api/agents/<id>/autobiography        → {job_id}
        │  POST /api/agents/<id>/life-prediction       → {job_id}
        │  GET  /api/agents/<id>/life-prediction/jobs/<job_id>
        └  GET  /api/agents/<id>/life-prediction[/download]

gaworld/apps/dashboard_server.py      路由分支（与自传同款）
gaworld/apps/life_prediction_api.py   compose / enqueue / job_status / handle_*
gaworld/apps/resident_dossier.py      gather() + format()：两个写作者共用的「居民档案」
gaworld/apps/autobiography_api.py     改为调用 resident_dossier（私有名字保留，测试不受影响）
```

### 3.1 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/agents/{id}/life-prediction` | body `{direction?, randomness?, turbulence?}` → `202 {job_id}`；同一居民已在跑 → 409 |
| GET | `/api/agents/{id}/life-prediction/jobs/{job_id}` | `{status, progress, message, result}` |
| GET | `/api/agents/{id}/life-prediction` | 盘上最新文档（404 = 从未生成） |
| GET | `/api/agents/{id}/life-prediction/download` | `text/markdown` 附件 |

任务模型与 `autobiography_api` 完全一致（模块级 `_JOBS` 表、`ownership.spawn` 起后台线程、
`ownership.visible` 按用户隔离、每居民一把运行锁）。

### 3.2 三个输入如何进入提示词

* `direction`（人生大致走向）：可选自由文本，原样进入提示词；为空时写明「使用者未指定 —— 请依据
  档案里的性格、目标与现状自行推演」，不留空白指令。
* `randomness` / `turbulence`：0–100，先钳到区间（越界值取边界，非法值回落到中位 50），再映射成
  五档之一，每档一句定性描述 + 一个区间：

  | 区间 | 人生随机性 | 时代动荡性 |
  | --- | --- | --- |
  | 0–20 | 几乎一条直线：计划大体兑现 | 平稳年代：宏观环境温和 |
  | 21–40 | 小幅偏转：整体仍在掌控之中 | 略有变动：行业与政策小有调整 |
  | 41–60 | 有明显的岔路：方向被悄悄改过 | 起伏明显：周期性波动或行业震荡 |
  | 61–80 | 高度不确定：方向多次被改写 | 剧烈动荡：政策转向或经济危机 |
  | 81–100 | 几乎不可预测：计划不断落空 | 时代巨变：战争、灾荒、制度断裂 |

  区间本身也进入提示词（`73/100（偏高）`），以便模型同时拿到精确值和解释。

### 3.3 提示词骨架

系统提示把「未来自传」定义成**站在人生终点回望**的第一人称长文：现在时是回顾的语气
（「后来我才明白」「那时我以为」），既要写「我做了什么」也要写「我原本想做什么、结果如何」，
一路写到死亡与身后。正文建议章节：写下这些字的时候 / 我出发的那些年 / 中年 / 晚年 / 最后的日子 /
我留下的。档案部分复用自传的那份材料（身份、大五、状态、目标、记忆、关系、财务、生命事件）。

## 4. 前端

* 卡片状态与自传一致：未生成（开始）／盘上有文档（重新生成）／任务在跑（进度行）。
* 三个输入存在 `store.predictDraft` 里，重绘（滑杆拖动、语言切换、文档到达）都不会吃掉半截输入。
* 切换居民时 `predictDraft` 重置 —— 走向属于某一个人，不能跟着编号漂到下一个人身上。
* 输出区的下载链接指向服务端端点，不用 Blob URL（重绘即失效）。

## 5. 错误处理

* 同一居民并发 → 409「已在为该居民生成人生预测」；面板直接显示。
* 模型返回空 → `RuntimeError`，任务状态 `error`，不落空文件。
* 模型把正文包在 ``` 里 → 去围栏后落盘。
* 轮询 12 分钟仍未完成 → 停止轮询并提示重试（与自传同一上限）。
* 断网 → 继续轮询，等看门狗兜底。

## 7. 不做的事

* 不把预测写进记忆或目标树（理由见 §2）。
* 不为预测单独跑一条仿真轨迹去和文本对照 —— 那是另一个功能（预测 vs 仿真结果），不在本次范围。
* 不给自传加参数 —— 只有预测需要这三个输入。
