# 模型 HTTP 连接复用

用户要求继续上一阶段的工程优化。此前分析已提出连接复用，本轮落实该路径；初始化并发和认知频率调整分别涉及顺序、机制变化，不混入本轮。

## 已确认的开销

`gaworld.llm.providers._post` 调用 `requests.post`。本地 requests 2.34.2 的实现每次创建 Session，并在返回 Response 前关闭 Session/adapter。连续模型调用因此不能共享底层连接池。

## 设计

使用线程内所有的 HTTPAdapter，只缓存连接池；每次请求仍建立新的轻量 Session、CookieJar、认证与请求头状态。适配器不做自动重试，维持现有 provider 的重试、限流、研究账本和调用次数语义。HTTP/HTTPS 原点池数及每池闲置连接缓存有界；不阻塞等待池空位，活动连接由调用方并发数及响应生命周期决定。阻塞和流式请求共用同一传输入口；流关闭仍由原有 with Response 管理。

线程退出销毁其适配器，进程退出关闭仍存活的适配器；显式关闭后下一次请求重新创建；PID 改变时不使用继承的连接池。TLS verify/cert 或本次 URL 实际选用的代理（含认证）变化时关闭并替换适配器，避免代理管理器无界增长。保持 requests 的 TLS、代理、超时、重定向处理，不缓存模型凭据或用户输入。不增加根模块和主运行函数逻辑。

## 验证

先写本地 HTTP/1.1 服务器测试：验证连续请求只接收一个 TCP 连接、跨请求不回传 Cookie/认证、线程隔离、关闭与重建、流正常/提前关闭、429 不自动重试。provider 的 mock 从 requests.post 移到新传输入口，保留账本统计测试。

执行相关 provider/credential/研究重试/核心测试和 lint。使用仅环回的 TLS 服务器、临时证书并开启证书验证，比较旧 requests.post 与新传输的连接数、请求内容、耗时；不能把本机传输基准当作真实模型整体提速。

流式响应在完整读尽 HTTP body 后可以归还连接。现有 OpenAI/Ollama 在结束标记处提前停止时可能关闭未完成的 HTTP body，本轮保留该行为，不为复用连接额外等待服务端结束；完整读尽的流式基准不能泛化到所有模型流。
