调查采用当前 checkout、已有本地产物及不调用真实模型的测试。工作区有大量既有改动，尤其人口模块和研究页面，本次均保留。截图是问题证据，不是修改研究协议的指令。

## 2. 可选路径

1. **推荐：补齐完整流程，但分三步交付。** 在现有实现上依次完成可解释评估、预算与模式预检、人口及研究任务诊断恢复。每步有独立验收，沿用同一研究来源与协议快照。
2. **只修提示与恢复。** 工作量较小，先改善报错和连接，但评分仍缺少可比标准，超预算方案仍缺少合理的规划入口。
3. **扩大调用限制并强制允许快速指标。** 表面上减少阻拦，却不解决实际成本和测量缺失；不采用。

## 3. 方案评估：原文保留和执行检查分开呈现

### 3.1 可核对的论文资料

- 保留原材料引用、内容哈希、输入字符数、实际使用范围和截断状态；PDF 抽取保留页码边界及空文本页提示。扫描页没有抽出文字时明确提示，不能声称已读完整论文。本轮不引入新的 OCR 服务。
- 扩展现有论文解读，增加结构化原设计：研究对象、样本与招募、组别和分配、刺激/干预、测量题项与量表范围、时间点、分析方法、原文已报告结果。字段附可定位的页码/节名及短依据。
- 文本中没有页码时使用段落编号；无法核对的模型引用标记未验证。原文未报告的内容保存为“未说明”，不补写数值。
- 继续使用研究者可编辑确认的解读；编辑字段保留来源和人工修订标志。原材料超限时不能将前缀解读标为全文完整覆盖。

### 3.2 对每个备选设计解释取舍

- 分别展示“原设计保留情况”“平台执行检查”“模型方法建议”。编译前，执行检查为待检查；编译后由代码给出通过/阻断及原因。
- 原设计逐项映射为保留、近似替代、缺失、待确认，并列出替代指标、原量表变化、样本变化及其后果。机制探索可与忠实复现同时存在，但必须显示与原设计的差异。
- 如保留 0–100 的方法建议分，采用公开且版本化的五维量表：机制表达 25、测量映射 25、对照与识别 20、原设计约束保留 20、验证与复现安排 10。每维有 0–4 档锚点，模型提供档位、依据和缺口，代码按权重求和；模型仍是建议者，不将总分描述为确定性可行性或成功概率。
- 通用锚点：0 为已知无法满足；1 为仅有构想且核心机制或测量需新增；2 为可近似表达但存在重要替代；3 为基本满足且差异明确；4 为该维要求逐项有据、无未解决的必要缺口。资料不足属于待确认，不等同于 0 或 4；各维要求与依据同时保存，总分取加权和四舍五入。
- 任一维缺乏必要资料时显示“待确认”，暂不计算总分；简短输入不能靠省略限制获得完整评分。对于研究想法，“约束保留”核对用户已明确的设计要求，不与论文忠实复现分数直接比较。
- 高分不能覆盖执行阻断；历史分数保留并标注“旧版模型总评，无统一量表”，不自动改写或跨版本排序。

## 4. 运行：先检验指标，再计算和审阅预算

### 4.1 明确三种模式

| 模式 | 当前主体粗估 | 含义与限制 |
| --- | --- | --- |
| 完整日内 tick | 198 次/居民/天 | 日内过程及对应细粒度机制 |
| 精简日内 lean_tick | 100 次/居民/天 | 仍然运行日内循环，不等于每天一次调用 |
| 按天简报 daily_brief | 1 次/居民/天 | 跳过日内过程，只更新支持的状态；属于近似探索 |

这些是现有估算系数，实际调用量可能不同；页面同时列启动、环境、问卷、解读，指出重试与插件额外开销。估算不能直接转换成承诺耗时或费用。

模式选择前由后端统一返回指标、假设、事件、插件兼容结果。遇到 social_need 等核心指标不支持，默认推荐兼容的日内模式和缩小样本/天数的预算方案；不会自动删除假设或更换指标。用户明确选择简化探索时，创建独立子研究，保存差异并重新审阅，沿用已有父研究和协议修订机制。

### 4.2 统一预算策略

- 新增统一预算解析入口，供上下文、编译预检、编辑、批准、启动及批次复用。默认仍为 50,000。
- 每份协议允许请求研究预算，保存批准时的有效上限、策略版本和批准者；管理员可配置部署最大上限。普通成员的请求受部署和账号限制，不能通过请求参数、force 或旧协议绕过。
- 批准和启动使用同一有效策略。若策略、人口、协议、模型或相关输入变化，回到重新检查与批准，而不是沿用旧批准或在另一处突然切回固定 50,000。
- 保留已有规模与成本明细，并提供若干预算内候选；用户选择后生成待审修订。不得默默删掉条件、种子、必要观察窗口或核心指标。
- 引入独立的运行请求硬预算，明确单位为实际 HTTP 尝试，包含失败重试；它与规划估算分开。使用现有共享 SQLite 账本，在真正发出请求前原子预留，不允许多个世界同时越界。
- 新协议的实际请求硬预算默认取此次有效的研究预算上限，可由有权限的研究者在部署/账号限制内另设更低值，批准时明确展示。旧版已批准但未运行的协议若没有硬预算字段，要求补充审阅后再启动；正在运行的旧尝试不热改策略，已完成记录不迁移。
- 达到硬预算时结束后续提交，保留已完成产物并记录 budget_exhausted；已有在途请求可能返回，但不自动补齐失败世界或宣称研究完成，旧研究不自动扩容。

## 5. 稳定性：定位阶段，恢复同一任务

### 5.1 可执行的诊断信息

在现有任务记录和日志上补充标准字段：错误码、任务/研究/尝试标识、阶段、provider/model、HTTP 状态、重试次数、最后活动时间、已完成进度、能否恢复及下一步操作。敏感凭据、Authorization、私密请求和未经脱敏响应不返回浏览器。

至少区分：配置/密钥缺失、认证拒绝、模型不存在、连接/DNS、限流、配额耗尽、单次等待超时、输出格式错误、子进程非零退出、信号终止、服务重启、用户停止、实际请求预算耗尽。退出码只能证明退出方式，不能单凭 SIGKILL 断言内存不足。

开始大任务前检查实际任务路由，分别显示“配置存在”“已验证真实生成”。真实生成探测复用现有 provider probe，用户点击测试才调用，计入用量，并标明测试时间；不能将端口可达或模型列表可读当作生成成功。通过测试也不保证后续长任务稳定。

### 5.2 恢复与有限重试

- 研究面板已有的 POST 幂等、持久化、GET 退避和刷新恢复保留，并补充错误分类。人口任务采用等价机制，任务记录/结果分开存储，以免反复保存大人口结果。
- 人口任务以用户及世界隔离，取状态与取结果都检查权限；后台继续通过 ownership.spawn 启动。服务重启后标为中断，提供新的尝试入口，不将旧线程伪装成仍在运行。
- 浏览器网络错误和部分临时服务器错误按有界退避重连同一任务；401/403/404 停止自动追踪并给出解释。达到重连次数上限后显示连接中断和手动重连，不能显示任务执行失败。
- POST 回包丢失时用原提交标识查询/幂等恢复，禁止无标识重复启动。轮询超时不自动重跑模型或人口生成。
- 短暂连接错误、可恢复的服务端错误与限流复用现有 provider 重试；遵循 Retry-After，纳入总等待和请求预算。认证、缺失模型、确定配额耗尽不盲目重复。
- 任务级失败不自动重跑整个实验。本轮恢复范围为连接、状态和结果；不声称支持任意 tick 断点续跑。重新运行采用新的尝试目录，保留旧产物与输入快照。

## 6. 代码边界与兼容

核心逻辑增加在 `gaworld/research/`、`gaworld/llm/` 和现有应用模块；不增加根模块，不扩大 `generative_city_sim.py`。前端只展示后端计算的检查和建议；模式能力和预算规则不复制到 JavaScript。

新增 API 复用 delegate 路由并登记 OpenAPI、账号策略。新增持久化字段保持旧计划可读；不改旧报告或原研究协议。不会用模式名称变化掩盖执行语义变化。若实现改变默认仿真产物可比性，按仓库规则追加 comparability Epoch；单纯展示、预检和任务恢复不改仿真引擎。

## 7. 验收

1. 同一原论文解读可生成忠实复现和机制探索，逐项显示差异；缺失证据不生成完整总分。覆盖超长文本、空文本 PDF 页、人工确认、历史评分读取和中英文展示。
2. social_need 在按天简报下阻断，日内模式可选择；原假设、样本及事件不被静默删除。确认精简日内不会被当成一天一次调用。
3. 高于 50,000 的协议在部署和账号允许的已批准预算下可启动；越权请求仍拒绝。覆盖编译/批准/启动/批次一致性及策略改变后重新批准。
4. 多进程争用实际请求硬预算不会超发，重试消耗预算；终止原因和已完成产物仍可查。
5. 模拟 POST 回复丢失、连续 GET 断连、刷新、服务重启、认证失败、429、配额、超时、格式错误、子进程退出和用户停止；不产生重复模型任务，并验证跨用户/世界拒绝访问。
6. 新行为先写失败回归，再做最小实现。运行研究、人口、凭据和 OpenAPI 的定向测试、Node 测试及 core suite；变更文件 lint ratchet 与 diff 检查。浏览器使用受控 fixture 验收，不依赖付费实验。
