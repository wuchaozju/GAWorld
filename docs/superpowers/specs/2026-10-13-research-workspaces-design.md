# 研究工作台：编辑、历史、多用户与并行运行设计

## 已核实的问题

1. `S20261013-163758-4977` 等快速版本因 `risk_preference` 不受按天简报支持而未通过检查；此指标没有被任何假设使用。前端因此禁用批准按钮，但“待批准”没有明确区分“可批准”和“需修正”。再次创建快速版本只会复制同一阻断项。
2. 实施方案没有编辑接口；运行协议只能修改少量成本参数。
3. 删除研究接口存在，但列表入口不明显，且必须补齐删除前的所有者验证。
4. 实施方案仍保存在磁盘；进入研究详情后没有清晰的来源方案入口，也没有保存编译时的方案版本快照。
5. 实施方案有所有者过滤；研究列表和运行权限仍按管理员设计，研究摘要缺少所有者字段。尚不能作为普通用户的完整私人工作台。
6. `_ACTIVE_STUDY` 只有一个全局句柄，阻止并行研究；直接去掉繁忙检查会造成暂停、停止、样本、模型和日志串线。

## 处理选择

- 完整方案（推荐）：统一修复工作台状态与编辑，并把每项研究的运行句柄、数据权限和来源版本一起隔离。覆盖用户提出的六项要求。
- 分步方案：先修按钮、编辑和历史记录，再处理权限与并行。交付较快，但普通用户仍不能拥有完整工作台。

## 设计与验收

### 1. 可操作的快速版本

创建快速版本时只自动排除“没有被任何假设引用”的不兼容指标，记录排除清单，不改变原研究。若假设依赖不兼容指标，保留明确的阻断原因和修改入口；不得强行通过科学质量门槛。已有待批准快速版本可以重新检查，应用同样规则。状态显示为“待批准·可运行”或“需修正”，阻断原因靠近操作按钮。

### 2. 两种方案的编辑与版本

实施方案可编辑标题、摘要、研究问题、假设及实验设计，保存时生成新的 Markdown 并保留原版本。已用于研究的来源版本通过研究内的快照保留。

运行协议可编辑条件/事件、假设/指标、问卷、人口、种子、天数、模型、并发与运行模式。未运行的草稿直接保存并重新检查；保存会撤销批准。已经运行或正在运行的研究通过“复制并修订”产生新的待审研究，不修改已有结果。服务端校验结构、范围、指标与条件引用；前端显示错误，不静默丢弃编辑内容。

### 3. 历史和删除

实施方案与研究分别有长期历史列表。每项研究可打开来源实施方案，以及查看编译时的来源快照。运行结束不隐藏实施方案。历史研究和方案均可删除；正在运行的研究须先停止。删除前校验所有权和世界，删除研究不会顺带删除来源实施方案或其他研究。

### 4. 私人工作台

以已登录用户和当前世界为隔离边界，计划、研究、后台任务、导出、日志、编辑、复制和删除统一验证权限。共享存储的全局唯一 ID 不构成读取权限。列表包含所有权与世界字段，并按调用者过滤。后台线程保持用户/世界上下文。旧无所有者记录仅管理员可见；单用户模式继续读取原历史。普通用户可以创建和运行自己的研究，模型配额沿用账号计数。

### 5. 并行研究

将全局单句柄改为按研究 ID 管理的运行记录。每项研究拥有独立 runner、stop、pause、job、冻结配置、provider ledger 与日志。运行前原子检查同一研究重复启动与研究并发上限；默认允许服务器同时运行 4 项、每个普通用户 2 项，限制可配置。世界子进程继续遵守已有服务器容量限制和每研究 max_parallel。达到研究上限时返回明确繁忙原因，不影响其他运行。

不同研究可同时运行；暂停/停止 A 不改变 B。当前选中研究显示自己的进度和日志，历史列表更新其他研究的状态。研究完成只释放自己的句柄。不会通过扩大并发掩盖 provider 配额不足。

## 验证

- 回归：复现未使用 risk_preference 阻断，确认快速版可批准、原协议未变、真正不兼容假设仍被阻断。
- 编辑：有效编辑持久化、结构错误明确返回、保存撤销批准、运行后修订保留旧报告和来源快照。
- 权限：两个用户和两个世界的列表、详情、计划编译、日志、导出、编辑、删除和任务互不可见；管理员旧历史及单用户兼容。
- 并行：两个受控研究同时推进，暂停/停止一个另一个继续；并发上限与重复启动原子检查；仅使用 mock/受控子进程，不启动付费实验。
- 浏览器：新快速版、两种编辑器、历史来源与删除、并行状态，验证桌面与窄屏。
- 相关 pytest、核心套件、前端测试与变更 lint 检查；保留无关脏工作区改动。

用户已确认“按完整方案实施”。实现和验证不删除用户现有研究，也不自动启动真实模型实验。

## 实施证据

六项能力已接入。后台按用户/世界过滤计划、研究、任务与研究世界；平行世界报告、回放列表、静态轨迹与归档均验证实验清单身份。运行句柄按研究隔离，修改/批准/启动/重置/删除采用同一原子锁。模型调用身份在世界和问卷子进程中保留。

受控浏览器使用真实 API、编辑器和子进程：保存实施方案与运行方案；创建快速版本后批准按钮可用；A 暂停后保持 16 次受控请求，B 独立完成 24 次受控请求并生成报告；删除一个历史研究不影响来源方案；390px 页面无横向溢出，方案与研究同时可见。受控数据不构成真实模型性能或科学证据。

当前实际部署未创建 `output/accounts/accounts.sqlite`，仍为单用户模式。新增多用户权限通过两个用户、两个世界及中央权限策略测试验证；账号初始化仍需部署者提供管理员身份和密码，不在本轮悄然开启登录门槛。

最终验证：核心 485 passed、1 skipped；相关回归 273 passed、1 skipped、700 subtests；前端 8 项测试通过。跳过项为未安装的可选 OpenAPI 校验库。全工作区 lint 仍有既有无关失败，本轮任务文件未新增检查失败。

实际部署更新后，三个既有待批准快速版本（S20261013-163706-ec71、S20261013-163717-d1e5、S20261013-163758-4977）重新检查通过；仅排除未被假设引用的 risk_preference，保留所有假设与原版研究，不启动模型调用。实际浏览器确认批准、批准并运行均未禁用，运行方案编辑与来源实施方案同时可见。
