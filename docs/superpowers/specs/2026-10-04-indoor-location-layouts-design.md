# 按地点用途选择室内布局

用户要求：室内模式随地点性质使用不同布局，可预先生成不同类型。沿用已确认的精细像素风及运行/回放接入方式。

## 设计

使用现有 spatial-tree 的预设蓝图库，扩展用途分类。纯大类模板成本低，但无法区分诊所/医院或咖啡馆/餐厅；逐地点调用模型生成布局有延迟且回放不稳定。采用预设类型 + 用途识别 + 地点 ID 确定的镜像变体。运行、回放、村庄共用同一个解析器，不调用模型。

优先 interior_type 明确指定，其次 amenity/shop/office/tourism/leisure 及 tags 的具体用途，再考虑 building_type 和建筑结构标签，其次具体名称，最后地图 category；未知类型用公共空间，不默认生成卧室。住宅名称要避免 Park/Garden 误判，细分用途优先于泛化 category。

蓝图包括住宅、公寓、旅馆、学校、图书馆、医院、诊所、药店、商店、咖啡馆、餐厅、办公、政务、工厂、车站、健身房及公园。工厂/车站不再复用商店/政务布局。适配新家具种类与房间标签，显示地点布局类型。

所有实际地点进入建筑选择器，包括 kind=place 和空置建筑；自动跟随使用当前帧居民的实际地点。按地点标识选择稳定镜像布局，家具及房间一同变换，不改变共享蓝图或仿真数据。

## 验证

分类优先级、中文/英文名称、无元数据地点、避免 Park Cafe/Park View Apartments 误判、几何完整与无重叠、稳定变体、共享数据不被修改、实际地点可选、渲染及活动席位、0尺寸黑屏回归。浏览器验证两个控制台页签切换不同用途地点并截图；仅读取已有轨迹或离线展示数据。
