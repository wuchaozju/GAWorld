# 严肃游戏：角色匹配、开放协商与结果可比性改进设计

日期：2026-11-10  
状态：用户已确认，已实施；实际交付和验证见 `docs/reports/2026-11-10-serious-games-validity.md`。  
范围：用户六项反馈；同居模式只改互动连续性、调度与可观测性。

## 1. 已确认的原因及证据边界

| 用户反馈 | 当前实现 | 可以确认的结论 |
|---|---|---|
| 角色身份不协调 | `gaworld/research/serious_game.py:resident_persona` 随机取居民；`suggested_player` 仅用于展示 | 无资格校验，也没有角色适配预览 |
| 动作重复 | `agent_prompt` 带公开历史，无结构化议题/提案追踪，无重复诊断 | 存在重复诱因；附件中具体词语的发生率尚未复测 |
| 预设协商走向 | `design_prompt` 一次生成全部回合事件；`apply_resolution` 轮数耗尽直接复盘 | 系统没有独立的协议、延期、搁置、退出状态；代码没有强制达成协议 |
| 利益与干预固定 | 只有公共指标和文字目标、私密背景，主持模型调整数值 | 缺少可执行私人收益、风险和外部干预；代码未强制指标负相关 |
| 命名及字段模糊 | 模型自由生成指标名；`public`、`private` 为文本 | 缺少指标定义版本与可比性约束；已有私密视图隔离 |
| 结局→四轮→一轮 | 前端 `historyBlock` 使用 `reverse()`；复盘先于历史渲染 | 是前端明确排序造成 |
| 同居缺少实质互动 | `_interact_prompt` 无近期具体对话；触发须公共房间共处和概率命中 | 存在对话失忆与长时间无碰面的条件，慢模型排队也需覆盖 |

本地未检索到附件所示保障房/黑水河原始对局。本设计以附件反馈和当前源码为依据，不将源码调查写成对具体历史对局的完整复现。

## 2. 方案比较与推荐

- A：修排序、字段说明和提示词。成本小，能改善阅读，不能解决资格、结局、收益和干预缺失。
- B（推荐）：保留现有严肃游戏入口和同时行动机制，增加可校验的角色匹配、协商状态、收益规则、回合边界干预；同居单独补上下文与调度。按三批实施和验收。
- C：重建连续时间、多主体自治的谈判引擎。变动大，难兼容现有真人座位与历史记录，本次不采用。

本次采用 B 的设计作为待审阅方案。机制能力的先后依赖清晰，不把顺序修复与完整引擎重写捆在一起。

## 3. 角色与居民匹配

### 3.1 区分居民本人的身份与情境角色

新增两种显式安排方式：默认“按居民背景匹配”；可选“角色扮演”。前者用于希望居民背景与情境一致的研究；后者允许跨职业演绎，开局和导出都标明，不能与前者无说明地混合比较。

退休者并非天然不能当未来住户或业主代表；资格来自情境的住房权益、居住计划、职业权限等条件。年龄仅在研究者明确指定资格时使用，不以年龄代替住房资格，也不凭职业推断是否有房。

### 3.2 可编辑的资格与匹配预览

角色增加 `eligibility`（必须满足的字段条件）、`preferences`（软偏好）、`required_facts`（须补充的情境事实）。支持有限的字段和操作符，不执行任意表达式。模型只提出条件，研究者可在开局前编辑。

从真实居民数据中做全局一对一分配，先满足硬条件，再按软偏好排序，使用局部固定种子解同分。优先保证所有角色都有可行安排，避免逐角色贪心挑人导致后续角色无候选。同一居民不重复入座，手选也校验。

预览显示居民年龄、职业、相关证据、匹配理由和未知事实。缺少必要证据时不视为满足，提示补充“本局情境假设”、换人或改条件。无候选不得静默回退到随机抽人。情境假设只落本局，和真实档案明确分开。

开局冻结资格、居民摘要与版本、种子、角色安排；提示词中明确人格与角色职责的边界。

## 4. 行为连续性与重复控制

### 4.1 严肃游戏

行动在现有 `action/choice/thought` 基础上增加结构化决策：`intent`（提出方案/询问/回应/拒绝/延期/退出/维持立场）、`target_role_id`、`proposal_id`、`proposal_version`、`terms`、`disclose_fact_ids`。各字段按游戏类型和行动类别校验，允许没有提案的普通发言。

每次行动上下文含上轮对方尚未回应的问题、本人承诺、现存提案及版本、已公开事实与近期本人发言。要求优先说明对象、条件和可执行后果；肢体动作可省略，不靠动作凑内容。

重复检测保存诊断：区分重复措辞、重复提案和合理坚持立场。只对连续近乎照抄且没有新信息的模型输出最多纠正一次，保留原始与纠正记录；不能为了多样性强迫让步，也不把重复直接判为无效研究数据。自动重试新增的模型成本计入用户用量。

### 4.2 同居模式

将当前两人的最近实质对话、未完成约定和相关事件传入下一次互动，按固定条数/字数限制。先判断已有记录，不凭空补出承诺。

保留作息、空间和独处的作用。清醒且长期无实质互动时，可安排合理共同事务或邀请碰面；收到邀请仍可拒绝。睡眠、忙碌、拒绝不触发强制聊天。以虚拟时间记录无互动时长，参数和触发原因可见，并记录调度策略版本。

异步调度增加每居民的在途任务占用、每对冷却、每会话队列上限。任务携带 session/interaction id、发起 tick 和截止时间；迟到结果不能重复更新关系或覆盖已终止会话。超时只标明失败/等待，不能生成被当作真实互动的对话。UI区分暂无碰面、正在生成、模型失败三种状态。

## 5. 从预设回合剧本转为受规则约束的协商

### 5.1 场景类型与回合

增加 `game_type`：协商型使用下面的提案与结局规则；非协商型保持情境推演，不强加签约或谈判破裂。

协商型的每轮由当前议题和行动后果推进。设计阶段可设置初始议题、条件事件和预算上限，不能先写“最终签约”“危机后和解”等确定结果。条件事件须有可检查的触发条件，不能在已发生破裂后继续播出和解剧本。

轮数是资源/时间上限，UI称“最多 N 轮”。达到上限仅表示观察结束，不表示同意；不把剩余轮次作为必须妥协的指令。研究情境确有真实期限时，期限作为全体知悉的外部约束另行登记。

### 5.2 提案、结局与阶段状态

保存带版本的共同提案。接受某版本须明确引用该提案与条款；“原则赞同”或主持人的叙述不能替代签署。协议门槛、必需主体和退出权限在开局前登记，由代码按有效接受记录判断。提案更新使旧版本接受失效；缺席不算同意。

将运行阶段（行动中、裁定中、回合间等待、复盘中、完成、失败）和实质结果分开。结果支持：达成协议、部分达成、延期、搁置、协商破裂、到达上限仍未解决、主持提前结束。缺少证据时为未确定，不由复盘模型补判。

延期：记录下一次议题/条件并进入回合间等待，主持可继续或结束观察；继续消耗剩余预算，增加预算须主持明确登记。搁置和有权限的退出按预注册规则判断；单一主体不当然有权结束所有议题。部分达成须记录达成与未达成的议题及签署人。

复盘展示分歧和未解决问题。学习目标评价允许合理拒绝、退出或延期得高分，不以签约作为默认优秀标准。

## 6. 利益、风险与外部干预

### 6.1 私人状态和收益

在公共指标外新增按角色隔离的资源、成本、收益、风险、底线与外部选项。数值须注明单位、来源和性质：真实资料、研究者设定、待确认的模型建议。无依据不自动声称是真实经济参数；缺失概率不能被当成已知概率。

收益和指标更新规则使用有限声明式操作（加减、按已批准条款转移、阈值、固定种子抽取），进行类型、边界、资源守恒和引用校验，禁止任意代码。明确哪项为确定性计算、哪项为主持模型的叙述性判断。模型解释不能修改已计算的收益。

不同指标默认无固定相关关系。每次变化记录触发行动、规则及计算前后值。正和、负和、分配冲突或风险分担取决于本局规则；需要真实社会机制支持的关系必须有依据或标为设定。

### 6.2 回合边界干预

开局可选自动推进或每轮暂停；运行中可请求在下一回合边界暂停，不能在某些角色已行动后偷偷改变本轮条件。主持可在暂停时提交政策/资源/信息事件，或新增有明确权限的外部角色（监管者、媒体、专家等），选择真人或匹配居民。

干预写入唯一 id、提交者、应用轮次、可见范围、条件变化与版本。结算中的干预排队到下一轮；幂等应用，重启不重复。新增角色只看到其获准访问的历史，资格、信息权限及是否参与表决要显式登记，不能隐式改写已经冻结的签约规则。

新接口遵循现有 ownership/world 路径、后台任务上下文和 OpenAPI；参与者座位链接不能调用主持干预接口。

## 7. 指标命名与信息边界

### 7.1 指标字典

指标采用稳定 `concept_id`、显示名、定义、单位、范围、方向、计算方法和 `definition_version`；所有表格、图表、导出使用相同字典。游戏特有指标允许保留，须完整定义，不能强塞进通用概念。

“社区融合度”“社会融合度”只有定义、测量范围和计算方法一致时才映射同一概念；“社会和谐度”不能仅凭字面相近自动合并。字面相同但定义不同同样不可比较。跨实验对比检查定义版本、尺度、规则、角色匹配模式和机制版本，不能仅凭都是 0–100 就平均。

旧记录保留原名与原定义；可添加显式人工映射，但不自动重写原始结果。历史数据无法判断的字段标为“未建立可比定义”。

### 7.2 用户可读名称和权限

- `public` 显示为“对外身份与已知背景”，说明所有参与者可见。
- `goal` 显示为“本角色目标”，是否公开须显式设置。
- `private` 显示为“仅本角色知悉的信息与约束”，说明本人及主持可见。
- `thought` 显示为“未公开的决策记录（模型生成）”，不把它解释为可验证心理真相。

私密事实附可披露/受限制标记；智能体需选择披露事实及理由，默认不原样复述角色卡。合理自愿披露可以改变谈判，记录在公开事实账本；公开发言一旦透露，其他角色之后可以使用。

服务端继续执行字段级权限过滤，并覆盖新增私人收益、干预、回合得失、复盘和导出。参与者只见自己的私密结果，主持能看到全部。自由文本可能间接泄露语义，提示词和披露标记不是完整防泄漏证明；需单独检查已知秘密的原文复述和语义样本，报告残余风险。

## 8. 时间顺序与阅读

默认按回合 index 升序显示：第一轮→第二轮→……→最终结果与复盘。进行中为已完成回合→当前回合；当前指标摘要可保留在顶部，注明截至第几轮。

每轮显示编号、事件、各方行动、裁定、指标变化、提案状态、干预及未解决事项。结局与复盘放在完整过程之后；提供“跳到当前轮”“跳到复盘”，避免轮询时重绘拉走阅读位置或清空真人草稿。Markdown 导出同序。

## 9. 架构与兼容

复用现有 `serious_game.py` / `serious_game_api.py` / `serious-game.js` 入口。匹配、协商规则、指标字典和状态校验拆成 `gaworld/research/` 内职责单一的模块，不往 CLI 入口塞逻辑。它们属于研究应用能力，不接入主仿真的 tick 插件链。

新增 spec/session 的 schema_version、机制版本和冻结快照。v1 设计/对局保持可读、可导出和旧规则续跑，不因新默认值静默更改已开始实验；用户显式升级设计产生新版本，不能覆盖既有 session。

新设计默认按背景匹配和中性的协商机制；非协商推演走独立路径。既有城市/居民数据不改写。两种机制生成的结果应分组比较，不合并成同一批实验。主仿真默认行为若未改，无须追加其 comparability Epoch；若实施时触及该范围，按仓库规则追加。

## 10. 分批交付与验收

### 第一批：身份、信息、连续性、顺序

角色条件编辑与匹配预览；字段说明；升序记录与末尾复盘；严肃游戏重复诊断与上下文；同居近期对话、在途限额和状态提示。

测试：有资格/无资格/未知资格、年龄不误杀、全局可行匹配、重复入座、固定种子、手选校验；自身秘密与他人秘密的可见性；连续维持立场不被强制改变；多轮 DOM 顺序、真人输入和滚动保持；同居无碰面、睡眠、邀请拒绝、慢调用/超时/迟到/重复回调。所有测试使用假模型与可控时钟。

### 第二批：协商结局、私人收益、指标定义

实现结构化提案、版本化签署、运行阶段和结果分离、回合预算、规则计算、指标字典和历史兼容。

测试：双方一致才签、不同条款不算协议、改版后旧签署失效、缺席非同意、合理拒绝/延期/搁置/破裂、预算耗尽仍未达成、部分协议、非协商游戏；指标不被隐式绑定、资源守恒、未知概率处理、名称映射拒绝、旧会话恢复。

### 第三批：外部干预与完整验收

实现回合边界暂停/继续、事件排队、新角色及权限、导出与跨实验定义检查。

测试：结算中干预只落下一轮、幂等与重启、无权限干预拒绝、新角色不看旧秘密、签约门槛变更明确登记；相关 pytest、前端 node 测试、OpenAPI、core suite 和 lint ratchet；浏览器检查中英文、深浅色、移动宽度和时间顺序。

三批最终一起覆盖六项反馈，不能只交第一批后宣称完成。自动测试证明规则与权限行为；行为自然度和协商走向需另用固定情境、多个种子与模型版本做后续真实模型评估，不能由假模型测试推出真实行为改善。评估报告呈现重复率、有效回应/提案比例、披露情况、结局分布和调用成本，不预设“协议率越高越好”或“必须出现某种结局”。

本次设计阶段不调用付费模型。后续真实模型评估需明确批次与预算后开展。
