## 0. 这是什么，什么时候该用

社会仿真里最值钱的一类问题是**反事实**的：

> 如果那件事没发生，这群人会过成什么样？

GAWorld 一直能回答它的最简形式——`compare-event` 分叉出两条支线（有事件 / 无事件），
跑完，比较**最后一行**。但这只回答了"有没有影响"，没回答另外两个同样重要的问题：

| 问题 | 只看终值 | 平行世界 |
|---|---|---|
| 有没有影响？ | ✅ | ✅ |
| **从哪一步开始**有影响？ | ❌ | ✅ 逐步偏离度 + 分叉点 |
| 影响落在**谁**身上？ | ❌（人群均值把个体抹平了） | ✅ 逐人偏离度 |
| 两种强度哪个更狠？ | ❌ 只能跑两次再手工比 | ✅ 一次实验里放 N 个世界 |
| 事件 vs 政策 | ❌ 只能加事件 | ✅ 世界还能带 `config` 补丁 |

平行世界把这个分叉一般化：**一次实验最多 8 个世界**，每个世界带自己的事件表，
共用同一批居民、同一个随机种子、同一个天数和同一个模型。除了"发生了什么"，
其它条件全都一样——所以终局的差异才归得到事件头上。

### 什么时候用它

| 场景 | 用平行世界？ |
|---|---|
| 一个事件到底有没有用 | ✅ 基准 + 事件世界，最简用法 |
| 同一个事件的不同强度，找剂量反应 | ✅ 基准 + 轻度 + 重度，一次跑完 |
| 想知道政策生效需要几天才显形 | ✅ 看分叉点和偏离曲线 |
| 想找出被政策真正影响到的那几个人 | ✅ 「谁被改变了」表 |
| 想比较税制/环境参数而不是某个事件 | ✅ 用世界的 `config` 补丁 |
| 想在跑着的仿真里临时制造一次冲击 | ❌ 用[外部系统面板](EXTERNAL_SYSTEMS_TUTORIAL.md)的干预队列 |
| 想改某一个居民的状态 | ❌ 用 Agent Studio |
| 想跑 500 人 × 30 天 × 8 个世界 | ⚠️ 先算成本：这是 8 次完整仿真（见 [§12](#12-常见问题)） |

## 1. 五分钟跑通

```bash
python generative_city_sim.py dashboard --port 8766
# 浏览器打开 http://127.0.0.1:8766/console，切到「平行世界」页签
```

最短路径：

1. 点一个模板（**裁员冲击** / **交通限行强度** / **安慰剂对照**），左边就填好了 2–3 个世界。
2. 把「仿真天数」调到 `2`、勾上「**快速模式**」——先用最便宜的配置跑通流程。
3. 点右下角「**运行平行世界**」。底部会逐个世界显示进度（`排队中 → 运行中 D1 → 完成`）。
4. 跑完自动载入报告，右边四块图表就有数了。

跑完之前不想干等，可以先点历史下拉里任意一次带数据的旧实验，先熟悉图怎么读。
仓库里已有的 `compare-event` 结果会自动出现在这个列表里（见 [§9](#9-与-compare-event-的关系)）。

## 2. 面板导览

页面是**左边设计、右边观测**：左边定义"世界之间差什么"，右边回答"于是差出了什么"。

### 左：世界设计

| 区域 | 说明 |
|---|---|
| **实验设置** | 对所有世界都一样的东西：天数、随机种子、参与居民、统一模型、快速模式。**保持一致才能归因**——所以这些不在单个世界里出现 |
| **并行世界数** | 同时最多跑几个世界的进程（1–4）。不是世界总数，是并发度；8 个世界、并发 2，就是分 4 批 |
| **平行世界** | 每个卡片是一个世界：名字、是否作为对照基准、事件列表。`⧉` 复制一个世界（连事件一起），`✕` 删除 |
| **事件** | 第几天 / 几点 / 事件名称 / 描述。描述就是居民当天会"看到"的那段话，写得越具体，反应越有依据 |

**基准世界**是所有差异的参照系。不手动指定时，默认取第一个**没有事件**的世界；
如果每个世界都带事件（比如三种强度互相比），就取第一个。

### 右：观测

| 卡片 | 回答的问题 |
|---|---|
| **分叉图** | 这几段历史长什么样、在哪儿分开的 |
| **走向对比** | 某个具体指标（情绪 / 压力 / 经济安全感…）在各世界怎么走 |
| **偏离基准的距离** | 每一步离基准多远，什么时候真正分叉 |
| **终局差异** | 跑完之后，各世界每个指标相对基准差了多少 |
| **谁被改变了** | 同一个居民在两个世界里的终局差距，按大小排序 |

图例上的每个世界都可以点掉——四张图会同时把它藏起来，用来在一堆世界里只看某两个。

底部还有**逐帧回放**链接：每个世界都是一次完整仿真，它的轨迹可以在「仿真回放」页里
逐帧看居民当天走到哪、想了什么。

## 3. 三张图怎么读

### 3.1 分叉图

一条虚线主干，每个世界一条线。**线离主干的远近 = 它偏离基准的程度**；
上下方向只是为了把世界岔开，不代表"变好"或"变坦"。

- 空心圆点 = **分叉点**：这段历史第一次稳定地离开基准的那一步。
- 实心小点 = 事件发生的位置，旁边是事件名。
- 基准世界自己就是那条主干（按定义偏离恒为 0）。

一眼能看出来的三件事：谁分得早、谁分得远、事件发生和分叉之间隔了多久（滞后）。

### 3.2 走向对比

选一个指标，看它的**人群均值**在各世界随时间怎么走。竖着的虚线是事件发生的位置，
颜色对应触发它的那个世界。鼠标移上去，下面会读出这一步各世界的具体数值。

勾上「**只看与基准的差**」，每条线会减去基准世界的同一步——绝对水平被抹掉，
只剩差异本身。指标本来变化就不大时，这个视图能把差异放大到看得见。

> 曲线断开 = 那一步没有居民上报数据（比如有人提前退出），图上留缺口而不是掉到 0。

### 3.3 偏离基准的距离

每一步，该世界所有指标与基准世界同一步的**平均绝对差**，一条线一个世界。
横着的红色虚线是**分叉阈值**（默认 `0.02`）。

判定分叉点的规则是"**越过并且待住**"：某一步越过阈值、且随后连续几步都在阈值之上，
才算分叉。只越一步就掉回去的，那是 LLM 的随机性，不是两段历史真的分开了。

## 4. 世界之间还能差什么：config 补丁

事件回答的是"**发生了什么**"。但有一类实验问的是"**规则变了会怎样**"——
个税起征点、通勤成本、环境事件的生成频率。这些不是事件，是配置。

所以一个世界除了 `events`，还可以带一个 `config` 补丁：

```json
{
  "label": "低起征点世界",
  "events": [],
  "config": {
    "economy": {"tax": {"monthly_exemption": 3000}}
  }
}
```

补丁**只影响这一个世界**，并且是**深合并**的：上面这段只把个税起征点从 5000 改成 3000，
`economy.tax` 下的税率级距、专项扣除都原样保留。所以只写你要改的那一片叶子就行。

配置项叫什么、改了会怎样，在控制台「配置」页签（`/site/dashboard/settings.html`）里逐条有
中文说明，也可以直接查 `gaworld/settings/config_docs.py`。

### 有几个键是不能改的

```
random_seed · sim_days · agent_ids · policy_events · stateful · distributed
memory_dir · log_dir · vector_db_path · state_output_dir
network_output_dir · environment_output_dir · diary_output_dir · visualization
```

前半截是**对照基准**：世界之间如果种子或天数都不一样，报告里的差异就没法归因了。
后半截是**磁盘隔离**：每个世界有自己的记忆、日志、状态、日记目录，两个世界共用任何一个，
都会互相污染——而污染的表现形式是"这个干预看起来没效果"，正好是实验本该诚实给出的结论。

写了这些键不会被悄悄忽略，会直接报错并指出是哪一个。

## 5. 一个完整实验：限行强度的剂量反应

**问题**：交通管制的强度和居民状态的恶化是线性的吗，还是有个拐点？

### 5.1 设计

三个世界，同一天同一时刻，只有强度不同：

| 世界 | 事件 |
|---|---|
| 基准世界 | 无 |
| 轻度限行 | Day 2 07:00「临时交通限行」— 早晚高峰单双号，通勤时间小幅增加 |
| 重度限行 | Day 2 07:00「全面交通管制」— 主干道全面管制，部分居民无法到岗 |

面板上点「交通限行强度」模板就是这三个世界，直接改描述即可。
或者写成 spec 走 CLI：

```json
{
  "name": "限行强度剂量反应",
  "sim_days": 4,
  "seed": 42,
  "agent_ids": [1, 2, 3, 4, 5],
  "max_parallel": 2,
  "worlds": [
    {"label": "基准世界", "events": []},
    {"label": "轻度限行", "events": [
      {"day": 2, "time": "07:00", "name": "临时交通限行",
       "description": "早晚高峰单双号限行，通勤时间小幅增加。"}]},
    {"label": "重度限行", "events": [
      {"day": 2, "time": "07:00", "name": "全面交通管制",
       "description": "主干道全面管制，通勤时间显著增加，部分人无法到岗。"}]}
  ]
}
```

```bash
python generative_city_sim.py parallel-worlds --spec worlds.json
```

### 5.2 读结果

按顺序问四个问题：

1. **分叉了吗？** 看偏离曲线有没有稳定越过阈值。两个世界的分叉点都在事件之后不久，
   说明事件确实推动了系统。
2. **剂量单调吗？** 比较两个世界的 `divergence_final`。重度显著大于轻度 = 单调；
   两者接近 = 存在饱和，管制加码没有换来更多变化。
3. **变在哪个维度？** 「终局差异」表按绝对差排序，第一行就是最被推动的指标。
   轻度和重度的第一行是不是同一个指标？如果不是，说明强度变化改变了**作用机制**，
   而不只是幅度。
4. **落在谁身上？** 「谁被改变了」选重度世界，看排在最前面的居民是谁——
   通常是通勤距离最长、或者工作最不能远程的那几个。点开他们的 profile 验证这个解释。

### 5.3 值得警惕的读法

- **不要只看终值。** 事件当天猛跳、第三天就回到基准，和一路走低到最后，
  终值可能一样，但结论完全不同。这正是偏离曲线存在的理由。
- **不要跳过第 0 步。** 如果两个世界在事件发生**之前**就已经有明显偏离，
  说明你看到的差异里混着噪声，先做 [§6](#6-先跑安慰剂把噪声底噪量出来)。

## 6. 先跑安慰剂：把噪声底噪量出来

这是这套工具**最重要的一条方法论提醒**。

GAWorld 的认知由 LLM 驱动，除非开确定性认知，否则**两个配置完全相同的世界也不会跑出完全相同的历史**。
也就是说，偏离度里天然含有一份与事件无关的噪声。不先量它，你会把噪声读成效果。

做法：加一个**安慰剂世界**——一个真实发生、但对居民生活没有实质影响的事件。

```json
{"label": "安慰剂世界", "events": [
  {"day": 2, "time": "10:00", "name": "市政通告",
   "description": "市政部门发布一则例行通告，不涉及任何居民的实际生活。"}]}
```

面板上就是「**安慰剂对照**」模板。它给出的偏离度就是**噪声底噪**：

> 真实干预的偏离度必须明显高于安慰剂的偏离度，结论才成立。

一个真实例子：仓库里旧的 `compare-event` 结果在面板上打开时，
有些在**第 0 步**就有 0.045 的偏离——事件还没发生，两条支线已经分开了。
那 0.045 就是这次运行的底噪，任何小于它的"效果"都不能当结论。

想把底噪压下去，有两个办法：

- 勾**快速模式**（`fast`）：感知、计划、反思都走确定性模板而不调模型，日总结与日记也跳过，
  随机性大幅下降——但**不为零**（日程生成、动作选择等环节仍可能调用 LLM），代价是保真度。
- 加长天数、加多居民：噪声是随机的，会被平均掉；效果是系统性的，不会。

无论压到多低，**安慰剂世界仍然该跑**：它给的是这次运行、这个模型、这套配置下的实测底噪，
比任何先验假设都可靠。

## 7. 输出文件与目录结构

```
output/parallel_worlds/<时间戳>_<实验名>/
├── experiment.json           ← 清单：spec + 每个世界的路径 + 运行状态
├── report.json               ← 完整报告（面板读的就是它）
├── divergence_metrics.csv    ← 逐世界 × 逐指标的 baseline / 本世界 / Δ 明细
├── divergence_summary.md     ← 人读的结论摘要（最先看这个）
└── worlds/
    ├── <world_id>/
    │   ├── run.log           ← 这个世界的完整运行日志（进度和报错都从这读）
    │   ├── reset.log
    │   ├── state/agent_state_history.csv    ← 分析的原始输入
    │   ├── memory/ logs/ network/ environment/ diaries/ life_events/ intervention/
    │   └── visualization/simulation_trace.json   ← 可在「仿真回放」里逐帧看
    └── <world_id>/ ...
```

每个世界都是**一棵完整的仿真产物树**——它和一次普通 `run` 的产物结构完全一样，
所以任何针对单次运行的分析工具都能直接对着它跑。

`divergence_summary.md` 长这样：

```markdown
## 结论

- 基准世界：基准世界
- 轻度限行：第 6 步开始分叉，终局距离基准 0.0350（峰值 0.0350），最大变化为情绪下降 0.0500
- 重度限行：第 4 步开始分叉，终局距离基准 0.0700（峰值 0.0910），最大变化为压力上升 0.1000
```

## 8. CLI 用法

```bash
python generative_city_sim.py parallel-worlds --spec worlds.json
```

| 参数 | 说明 |
|---|---|
| `--spec`（必填） | 实验定义 JSON，格式见 [§5.1](#51-设计) |
| `--sim-days N` | 覆盖 spec 里的天数 |
| `--seed N` | 覆盖随机种子（所有世界共用） |
| `--llm-provider NAME` | 强制所有世界用同一个 provider |
| `--fast` | 快速模式：确定性认知 + 跳过日总结/日记 + 3 人队列 |
| `--output-root DIR` | 输出根目录，默认 `output/parallel_worlds` |

命令行参数会**覆盖** spec 文件里的同名字段，所以同一个 spec 可以先 `--fast --sim-days 2`
跑通，再原样跑正式配置。

面板和 CLI 用的是同一个引擎和同一套 spec 格式：面板上设计好的实验可以照抄成 JSON 走 CLI，
CLI 跑出来的实验也会出现在面板的历史列表里。

## 9. 与 compare-event 的关系

`compare-event` **没有被替换，也没有改动**——它的输出布局被 benchmark 依赖，保持原样。

| | `compare-event` | `parallel-worlds` |
|---|---|---|
| 世界数 | 固定 2（有事件 / 无事件） | 2–8 |
| 每个世界的事件数 | 1 | 任意 |
| config 差异 | ✗ | ✓ |
| 比较方式 | 终值 + 均值 | 逐步偏离 + 分叉点 + 逐人 |
| 并发控制 | 两个一起跑 | 进程池，1–4 并发 |
| 界面 | 仅 CLI | 面板 + CLI |
| 输出目录 | `output/comparisons/` | `output/parallel_worlds/` |

**旧结果不用迁移。** 面板会把每个
`output/comparisons/<时间戳_事件名>/{without_event,with_event}` 目录**当场适配**成一个两世界实验，
用新的图表打开，磁盘上什么都不改。历史下拉里带「（旧）」标记的就是它们。

跑到一半死掉、没留下状态数据的旧目录会被标成「（无数据）」列出来，而不是藏起来——
`output/` 里这类空壳不少，默认打开最新一个的话会看到一片空白，那不是页面坏了。

## 10. API 速查

面板用的全部接口。所有响应中的 `NaN` / `Infinity` 都已转成 `null`（否则 `JSON.parse` 会整个拒收）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/parallel-worlds/overview` | 默认值、provider 列表、居民名单、模板、历史实验、当前任务 |
| GET | `/api/parallel-worlds/experiments` | 历史实验列表（含 `has_data` 标记） |
| GET | `/api/parallel-worlds/experiment?root=<路径>` | 某次实验的完整报告 |
| GET | `/api/parallel-worlds/job[?id=<job_id>]` | 任务状态；运行中时带每个世界的实时快照 |
| POST | `/api/parallel-worlds/preview` | 只校验 spec 并回显执行计划，**不跑任何东西** |
| POST | `/api/parallel-worlds/start` | 建目录、分叉世界、返回 `job_id` |
| POST | `/api/parallel-worlds/stop` | 停掉当前实验 |

**同一时刻只允许一个实验在跑。** 第二次 `start` 会拿到 `409`，而不是让机器被超额占用。
spec 不合法返回 `400`，错误信息里会指出是哪个世界的哪一项。

`report.json` / `GET experiment` 的主要字段：

| 字段 | 内容 |
|---|---|

## 12. 常见问题

**Q：跑一次要多久？花多少钱？**
N 个世界就是 **N 次完整仿真**，没有任何共享或折扣。5 人 × 4 天 × 3 个世界 ≈ 3 次 5 人 4 天的
普通运行。先用 `--fast --sim-days 2` 跑通流程，再上正式配置。`max_parallel` 只影响墙钟时间，
不影响总调用量。

**Q：某个世界失败了，其它世界会跟着挂吗？**
不会。每个世界是独立进程，一个失败不影响其它世界跑完，报告照常生成，
失败的世界标成「无状态数据」。失败原因（比如 LLM 配额 429、Ollama 没启动）会原样显示在面板上，
完整日志在 `worlds/<world_id>/run.log`。

**Q：为什么两个世界在事件发生前就已经分开了？**
LLM 的随机性。这是正常的，也正是要跑安慰剂世界的原因——见 [§6](#6-先跑安慰剂把噪声底噪量出来)。

**Q：横轴的"步"是什么？跟天怎么换算？**
步是仿真器的**日内时刻推进单位**（每个 agent 每 tick 记一次状态）。
报告里的 `steps_per_day` 就是换算比例，面板上的 `D1 / D2 / D3` 网格线也是据此画的。

**Q：能中途停吗？停了的实验还能看吗？**
能。「停止」会终止所有在跑的世界进程；已经跑完的世界仍会被分析并写进报告，
所以一个跑了一半的实验依然是可读的，只是没跑完的世界标着「已停止」。

**Q：`reset` 会不会清掉我正在跑的主仿真的记忆？**
不会。每个世界的记忆、日志、状态、日记、人生事件目录都被重定向到自己的目录下，
和 `output/` 主树完全隔离。

**Q：能同时跑两个实验吗？**
不能，第二次会返回 `409`。一个世界就是一次完整仿真，同时跑两场实验只会让机器和
模型配额一起打架。

**Q：想改分叉阈值怎么办？**
`build_report(..., split_threshold=…)` 支持传参；面板目前用默认值 `0.02`。
判断某个阈值合不合适，最靠谱的依据仍然是安慰剂世界的偏离度。

**Q：一个世界能带多个事件吗？**
能，数量不限。事件会按 `(day, time)` 自动排序。这样可以做"连续冲击"实验——
比如第 2 天裁员、第 5 天补贴，看第二件事能不能把第一件事的影响拉回来。
