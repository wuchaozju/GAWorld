## 0. 这是什么

游戏场是一组**交互式小游戏**的集合：对手不是脚本，而是某座城市里的真实居民档案——
职业、性格、日常、价值观都进了 prompt，所以同一个问题问两个人会得到两种答案，
同一套说辞对一个人管用、对另一个人一点用没有。

和其它面板的分工：

* 想跑完整仿真 → `python generative_city_sim.py run`；
* 想给一群人发问卷并聚合 → 群体采访（`docs/GROUP_INTERVIEW_TUTORIAL.md`）；
* 想玩一局、当场看到胜负 → 游戏场。

游戏状态**只在内存里**。重启 dashboard，对局记录就清空；游戏永远不会写回城市 bundle。

## 1. 已有的游戏

| 游戏 | 玩法 | 页面 | 后端 |
| --- | --- | --- | --- |
| 斗兽场 | 一组居民同台答题，按正确率 + 中位耗时排座次，留存 Top-K，其余淘汰，再补人 | `arena.html` | `/api/arena/*`（[斗兽场教程](ARENA_TUTORIAL.md)） |
| 说服游戏 | 问一个居民一个问题，限定轮数内聊天说服他，复问时答案改变即胜 | `persuade.html` | `/api/games/persuasion/*` |
| 灾害模式 | 一批居民经历同一场灾难，分幕推演，看行动分布、恐慌值与互助率怎么变 | `disaster.html` | `/api/games/disaster/*` |
| 谣言扩散局 | 一条传闻沿着熟人关系往外走，看传播树、信任度、谁放大了它、谁挡住了它 | `rumor.html` | `/api/games/rumor/*` |

斗兽场仍然走它自己的 `/api/arena/*` 命名空间——游戏场只是把它收进了同一个入口，
接口一个都没动。新游戏统一挂在 `/api/games/<game>/` 下。灾害模式和谣言扩散局体量较大，
逻辑分别放在 `gaworld/apps/disaster_api.py` 和 `rumor_api.py`，`games_api` 只做一层转发，
并提供两样公共件：`persona_block()`（档案前言）和 `first_json_object()`（把结构化回复从模型的话里抠出来）。

## 2. 说服游戏：五分钟跑通

1. 打开大厅，点「说服游戏」。
2. 左边选**城市**和**对手**（下拉里带年龄 / 性别 / 职业，方便挑一个你觉得好说服的）。
3. 写一个**有立场可选**的问题——「支持还是反对」「搬还是不搬」。
   开放式问题（「你怎么看城市化」）复问时判不出改没改口。
4. 设**最大聊天轮数**（默认 5，上限 20）。一轮 = 你说一句 + 他回一句。
5. 点「开始这一局」。他的第一答案会显示在对话区顶部，**整局都以它为基准**。
6. 聊天。`Ctrl/⌘ + Enter` 发送。右上角显示剩余轮数。
7. 最后一轮用完会**自动复问并结算**；想提前收手，点「复问并结算」。
8. 结算面板给出：最初的回答、复问的回答、裁判的一句话理由，以及胜负。

左下「最近对局」列出本次 dashboard 运行期间的所有对局，点一条可以回看。

**一局要几次 LLM 调用**：1（开局）+ 聊天轮数（每轮 1 次）+ 2（复问 + 裁判）。

## 3. 说服游戏是怎么判的

三个 prompt，都在 `gaworld/apps/games_api.py` 里：

* **开局**（`_opening_prompt`）：档案 + 「按你自己的立场回答，先给答案再给理由，120 字以内」。
* **每轮回应**（`_reply_prompt`）：档案 + 最初的问题与答案 + 完整对话记录 +
  一句明确的态度约束——「只有理由真正贴合你的处境、价值观、利害关系才松口，
  否则坚持己见并说清为什么不认同，不要为了客气而附和」。
  没有这句，模型会一路顺着玩家说，说服游戏就没有难度了。
* **复问 + 裁判**（`_final_prompt` / `_judge_prompt`）：重新问一遍最初的问题，
  再由裁判比较首尾两个答案，只输出 `{"changed": bool, "reason": "..."}`。
  判定规则写死在 prompt 里：**核心结论变了**才算改（是→否、支持→反对、选 A →选 B）；
  只是措辞、语气变了，或者让步但结论不变，一律不算。

温度是分开的：居民说话 `0.7`（要像人），裁判 `0.0`（要稳定）。
裁判返回的 JSON 解析失败时**判为未说服**——宁可漏判，不可白送一局。

档案来自 `gaworld.interview.roster`：`load_population()` 给身份行，
`profile_block()` 给 profiles.md 里那个人的整段档案（截断到 1500 字，
性格和价值观正好在前面——它们决定了这人好不好说服）。

## 4. 灾害模式：五分钟跑通

1. 打开大厅，点「灾害模式」。
2. 左边选**城市**，再勾**参演居民**（最多 12 人；点「🎲 随机 6 人」也行）。
   人挑得越杂越好——退休老人、带孩子的、做小生意的，反应会差得很远。
3. 选一场**灾难**：地震 / 疫情 / 战争 / 洪水 / 大停电，每场都写好了三幕；
   或者选「✍️ 自定义灾难」，自己写名称和情境（**一行一幕**，最多 3 幕）。
4. 选**推演几幕**（默认 2）。一幕 = 每个人一次模型调用。
5. 点「开始推演」。这是个后台作业，进度条按 `人数 × 幕数` 走。
6. 跑完右边给出：**城市简报**（一段整体观察）、四个总览指标，以及每一幕的
   情境原文、行动分布条、每个人的卡片（行动标签 / 具体做法 / 原话 / 恐慌值 / 是否顾得上别人）。

左下「最近推演」列出本次 dashboard 运行期间跑过的场次（最多 20 场），点一条可以回看。

**一场要几次 LLM 调用**：`人数 × 幕数 + 1`（最后那次是城市简报）。6 人 2 幕 = 13 次。

---

## 5. 灾害模式是怎么推的

**一次调用拿结构化结果，不设裁判。** 每个人每一幕只问一次，要求只输出一个 JSON：

```json
{"action": "避险逃离", "detail": "摸黑叫醒家人往楼下跑", "panic": 4, "help": true, "say": "快起来，别拿东西了！"}
```

`action` 必须落在固定的六类里——**避险逃离 / 囤积物资 / 救助他人 / 求助求援 / 照常生活 / 打探消息**——
所以行动分布图不需要再花一次钱去分类。返回值解析不了（模型讲了一堆话、JSON 坏了）时，
这一条降级成 `其他` + 恐慌值 3，**只毁一格，不毁整场**；原文留在卡片上，你能看见模型到底说了什么。

**第二幕起，周围人的选择进提示词。** 每一幕结束后已经有了行动分布，下一幕就在提示词里加一句
「你看到身边的人：4 人囤积物资、2 人避险逃离」——不额外调用模型。没有这句，每一幕都是独立抽样，
灾难里最值得看的东西（从众、跟风抢购，或者偏偏有人不跟）根本不会出现。
同时每个人还会看到**自己**前几幕做过什么，所以行为是连贯的，不会第一幕逃了第二幕又在家做饭。

**档案决定反应。** 和说服游戏用的是同一份 persona（`games_api.persona_block()`）：
身份行 + profiles.md 里那段档案。提示词里明确写了「不要给一个『正确』的标准答案，
给你这个人真的会做的事」——所以 6 岁的孩子会写「妈妈我害怕，拉着我别松手」，
而做小生意的会先想店里的货。

**城市简报**是最后一次调用：把行动分布、平均恐慌、互助率和几个人的原话交给一个「社会学观察者」，
让它写 150 字以内的整体观察。这一步失败不影响整场结果（`summary` 留空，其余照常返回）。

温度：居民 `0.7`（要像人），简报 `0.3`（要稳）。

## 6. 谣言扩散局：五分钟跑通

1. 打开大厅，点「谣言扩散局」。
2. 左边选**城市**，点「🎲 随机两个小区」。居民列表按**小区**分组，点组标题可以整组勾上。
3. 右边立刻画出这批人的**关系网**——这一步不花任何模型调用，勾人的时候就能看见图。
   下面会写「N 条关系」，有人没有任何关系也会直接告诉你（消息传不到他们那儿）。
4. 选一条**传闻**：自来水污染 / 银行要倒闭 / 粮价翻倍 / 学校要搬 / 台风瞒报，
   或者「✍️ 自己写一条」——像在群里传的那样写一句话。
5. **最先听到的人**可以不选：默认挑一个关系最多的，再挑一个**不是他熟人**的，
   这样两个小区都会被点着。
6. 点「放出这条传闻」。跑完右边给出：关系网（叠上传播箭头，可按轮次筛）、
   触达 / 相信 / 平均信任度 / 最大传播者四个指标、逐轮的扩散条、每个人的卡片和原话，
   以及一段传播简报。

**一场要几次 LLM 调用**：**上限是 人数 × 2 + 1**，和轮数无关——每人最多开口一次，
只有「信了之后被人当面辟谣」的人能再开口一次。7 个人最多 15 次。

---

## 7. 谣言扩散局是怎么传的

**关系图是推导的，不是仿真长出来的。** 城市包里只有身份，没有居民之间的边：
熟人关系是仿真跑起来之后才在内存里长出来的，落盘在 `output/memory/` 的多半还是 ghost
（城外的亲友），而且没有城市归属——agent #13 在两座城里是两个人。所以这里按档案重新推：

| 条件 | 关系 | 亲密度 |
| --- | --- | --- |
| 同小区 + 同姓 | 亲属 | 0.9 |
| 同小区 | 邻居 | 0.55 |
| 都是学生且年龄差 ≤ 3 | 同学 | 0.5 |
| 同职业（不含「无业 / 退休 / 学生」这几个大桶） | 同行 | 0.5 |
| 年龄差 ≤ 3（跨小区） | 同龄熟人 | 0.25 |

每人最多留 6 条（按亲密度、年龄差、id 排序后裁剪），否则「同一个小区的人互相都认识」
会让图变成一团，一跳就传遍。**同一批人永远画出同一张图**，两局之间可比。
「无业 / 退休 / 学生」不算同事——不然一个典型城市包里四分之一的人会变成同一个办公室的。

**模型决定传不传，图决定传给谁。** 每个人只回一个小 JSON：

```json
{"belief": 72, "action": "转发", "say": "听说那家小银行下周就要关门了，有存款的赶紧去取。"}
```

`action` 只能是**转发 / 私下求证 / 辟谣 / 不管**，然后由图决定落到谁头上：

* **转发** → 亲密度最高的、**还没听说**的最多 4 个熟人；
* **私下求证** → 最亲近的、还没听说的那**一个**人（所以"求证"本身也是一种扩散——
  被问的人就此知道了这件事）；
* **辟谣** → 所有熟人；
* **不管** → 链条到此为止。

让模型自己点名字只会带来编造的人名和一层只会丢信息的映射；这样拆开之后，
传播树是这座城的性质，不是模型记名字的能力。

**每人只开口一次，例外只有一个**：信了这条、随后被人当面辟谣的人可以再开口一次。
没有这个例外，「辟谣」就是一个不会产生任何后果的选项。开销因此封在 `人数 × 2 + 1`。

**提示词要顶住"得体"的默认答案。** 中性地问，七个人会给出七个一模一样的
「我先问问在银行上班的朋友」——和说服游戏里模型一路附和玩家是同一个毛病。
所以提示词里明写着：**不是每个人都会先去核实**，有人看到就顺手转了，有人划过去懒得管，
请按你这个人的性格选，不要因为「谨慎求证」听起来得体就选它。加上这句之后，
同一批人里才会同时出现「信 72% 直接转发」的和「不管，群里天天有」的。

**社会证明是免费的。** 提示词里那句「在你认识的人里，已经有 3 个人在传这条、1 个人说这是假的」
直接从已有的计数拼出来，不额外调用模型。

**解析容错**：回复读不出来的那个人降级成「其他」、信任度 0、**不往下传**——
谣言不会从一次解析失败里传出去。模型多打一个 `}`、或者在 JSON 后面接着说话，
都能正常解析（`games_api.first_json_object()` 扫括号深度，不是正则）。

## 8. 程序化调用：HTTP API

### 8.1 `GET /api/games/agents?city=<slug>`

可选对手列表，`city` 留空 = 默认世界。响应 `{"agents": [{id, name, age, gender, job}, ...]}`。

### 8.2 `POST /api/games/persuasion/start`

```bash
curl -s -X POST http://localhost:<port>/api/games/persuasion/start \
  -H "Content-Type: application/json" \
  -d '{"city": "wuzhen", "agent_id": 3, "question": "社区要在你家楼下建垃圾中转站，你支持吗？", "max_turns": 5}'
```

响应是一份完整的 session：

```json
{
  "id": "persuade-c1f281be",
  "city": "wuzhen", "agent_id": 3, "agent_name": "闫然",
  "question": "…", "initial_answer": "不支持，…",
  "max_turns": 5, "turns_used": 0, "turns_left": 5,
  "messages": [], "final_answer": "", "outcome": "", "reason": "",
  "status": "open", "created_at": 1790329878.02, "finished_at": null
}
```

`max_turns` 会被夹到 `[1, 20]`。问题为空 → `400`。

### 8.3 `POST /api/games/persuasion/say`

`{"session_id": "...", "message": "..."}` → 更新后的 session。
`messages` 里按 `player` / `agent` 交替追加。**用完最后一轮时这一次调用会连带结算**，
返回的 `status` 直接是 `settled`。会话不存在 → `404`；已结算或空消息 → `400`。

### 8.4 `POST /api/games/persuasion/settle`

`{"session_id": "..."}` → 复问 + 裁判，返回带 `final_answer` / `outcome` / `reason` 的 session。
`outcome` 是 `success`（说服成功）或 `failed`。重复调用是幂等的，不会再花一次钱。

### 8.5 `GET /api/games/persuasion/sessions[/<id>]`

列表（进行中的在前）或单局详情。内存存储，最多保留 50 局，超出时先丢已结算的。

### 8.6 `GET /api/games/disaster/catalogue`

灾难库 + 各种上限：`{"disasters": [{id, name, emoji, summary, stages}], "max_agents": 12,
"max_stages": 3, "default_stages": 2, "actions": [...]}`。

### 8.7 `POST /api/games/disaster/run`

```bash
curl -s -X POST http://localhost:<port>/api/games/disaster/run \
  -H "Content-Type: application/json" \
  -d '{"city": "wuzhen", "agent_ids": [3, 7, 19], "disaster_id": "earthquake", "stages": 2}'
```

返回 `{"job_id": "disaster-1a2b3c4d"}`——一场要几十次调用，不可能同步等。
自定义灾难把 `disaster_id` 留空，改传 `custom`：

```json
{"custom": {"name": "化工厂爆炸", "stages": ["凌晨起火…", "六小时后要求下风向撤离…"]}}
```

`stages` 也接受一整段文本（按换行切幕）。没选人 → `400`；灾难 id 不认识 → `400`（在开作业之前就挡掉）。

### 8.8 `GET /api/games/disaster/jobs/<job_id>`

运行中返回 `{status: "running", progress, message}`；跑完 `status: "done"`，`result` 是整场推演：

```json
{
  "run_id": "9f2c81ab", "city": "wuzhen",
  "disaster": {"id": "earthquake", "name": "地震", "emoji": "🌍"},
  "stages": ["凌晨 3 点 17 分…", "12 小时后…"],
  "agents": [{"agent_id": 3, "name": "闫然", "job": "美发店员",
              "reactions": [{"stage": 0, "action": "避险逃离", "detail": "…",
                             "panic": 4, "help": true, "say": "…"}],
              "avg_panic": 4.0, "helped": true}],
  "stats": {"per_stage": [{"stage": 0, "n": 3, "actions": {"避险逃离": 3},
                           "avg_panic": 4.0, "max_panic": 5, "help_rate": 0.67, "text": "…"}],
            "overall": {"n": 6, "actions": {...}, "avg_panic": 3.5, "help_rate": 0.5}},
  "summary": "两人都本能地冲向开阔地带…",
  "created_at": 1790329878.02
}
```

### 8.9 `GET /api/games/disaster/runs`

本次运行期间跑完的场次（最多 20 场，和作业表同一份内存），按时间倒序，
每条带 `job_id`——回看就是拿它再查一次 `/jobs/<job_id>`。

### 8.10 `GET /api/games/rumor/catalogue`

传闻库 + 上限：`{"rumors": [{id, title, emoji, text}], "max_agents": 14,
"max_rounds": 5, "default_rounds": 3, "actions": ["转发", "私下求证", "辟谣", "不管"]}`。

### 8.11 `GET /api/games/rumor/graph?city=<slug>&agent_ids=1,2,3`

**不花模型调用**的关系图预览——前端每次改勾选都调它。

```json
{
  "nodes": [{"agent_id": 7, "name": "侯香野", "age": 28, "job": "后端研发工程师",
             "residence": "Avondale·改造社区", "degree": 3}],
  "edges": [{"a": 7, "b": 56, "role": "neighbor", "label": "邻居", "closeness": 0.55}],
  "isolated": [14]
}
```

`isolated` 是一条关系都没有的人——消息传不到他们那儿。名单里有人不在这座城 → `400`。

### 8.12 `POST /api/games/rumor/run`

`{"custom": {"title": "菜场要拆", "text": "听说…"}}`；`seeds` 不传 = 自动挑
（关系最多的一个 + 一个不是他熟人的）。少于两个人 → `400`；传闻 id 不认识 → `400`。

## 9. 加一个新游戏

1. **后端**：在 `games_api.handle_get` / `handle_post` 里加一个 `/api/games/<game>/…` 分支。
   照说服游戏的样子：LLM 入口做成可注入的参数（`answer_fn=` / `judge_fn=`），
   这样测试不碰网络；状态放内存，不写城市 bundle。
   逻辑超过百来行就单独开一个模块，分支里只转发——灾害模式就是这么做的
   （`disaster_api.py`，`games_api` 里只有两行 `if path.startswith(...)`）。
   要跑很多次调用的游戏别做成同步接口，照 `disaster_api` 开个后台作业 + 进度。
2. **前端**：加一个 `site/dashboard/<game>.html` + `.js`，样式复用 `games.css`。
3. **入口**：在 `games.html` 里加一张 `.game-card`，中英文案写进
   `site/dashboard/locales/{zh-CN,en}.json`。
4. **测试**：`tests/test_games_api.py` 里加一个 TestCase，或单独一个 `tests/test_<game>_api.py`。

大厅是静态页面，没有 catalogue 接口——加游戏就是加一张卡片，不需要再改后端注册表。

## 10. 排查清单

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 对手下拉「这座城市暂无居民」 | 该城 `agents.csv` 为空 | `python -m gaworld.city add-agents <city> --size 100`，或换城市 |
| 开局报错、状态栏变红 | LLM 调不通（key / DNS / provider 没配） | 检查 `dashboard_config.json::llm.providers` 与 `output/logs/` |
| 对手回答像客服而不是居民 | 那个人的 profiles.md 档案缺失，只剩 CSV 行 | 补档案，或换一个有完整 profile 的居民 |
| 明明被说动了却判「没说动」 | 问题太开放，复问答案里没有可比的结论 | 问题改成二选一的形式重开一局 |
| 「最近对局」空了 | dashboard 重启过 | 正常：对局只在内存里 |
| 聊天轮数用完还想继续 | 一局的轮数上限是开局时定的 | 换个更大的 `max_turns` 重开一局 |
| 灾害模式里一堆人被标成「其他」 | 模型没按 JSON 输出（小模型常见） | 换个更听话的 provider；原文还在卡片上，可以先看它说了什么 |
| 灾害模式跑得很慢 | 开销是 `人数 × 幕数`，顺序调用 | 少选几个人，或先跑 1 幕试试 |
| 每一幕的行动分布几乎一样 | 灾难情境本身没升级 | 内置灾难三幕是递进的；自定义灾难要让后面的幕**真的更糟** |
| 自定义灾难只推了 1 幕 | 情境框里只写了一行 | 一行一幕，写够几行再跑 |
| 谣言局「0 条关系」 | 勾的人分散在不同小区，又没有同行 / 同龄的巧合 | 点「🎲 随机两个小区」，或按小区分组整组勾 |
| 传闻一跳就传遍了 | 只勾了一个小区——同小区的人互相全认识 | 勾两个小区，看它能不能跨过去 |
| 所有人都选「私下求证」 | 传闻对这批人不痛不痒，没人有动机转 | 换一条跟他们利害相关的（钱 / 孩子 / 饭碗），或换一批人 |
| 有人显示「没听说」 | 他在关系图上是孤立的，或者链条没走到他 | 正常：这正是这个游戏要看的东西；想让他听到就把他设成种子 |
| 传播树只有一两跳 | 轮数够了，但没人选「转发」 | 正常结果——多数传闻确实传不动；换传闻或换人再看 |
