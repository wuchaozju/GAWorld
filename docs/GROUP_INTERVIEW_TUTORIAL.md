# 群体采访教程（Group Interview）

> 跨城市选一群智能体，问同一套问题，把回答统计成可分析的结果，导出一份自带出处的 Markdown 文档。

## 0. 它和单人采访的区别

仓库里原本就有单人采访（`python generative_city_sim.py interview --agent-id 31 --question "…"`，
以及 Agent Studio 里的采访框）。它回答的是「31 号居民怎么想」。

群体采访回答的是另一个问题：**「这群人怎么想，答案会不会按城市／年龄／户籍分化」**。
这不是把单人采访套个循环，差别是结构性的：

| | 单人采访 | 群体采访 |
|---|---|---|
| 受访者 | 一位居民 | 多位居民 **＋** cohort 群体智能体，**可跨城市** |
| 题型 | 自由问答 | 开放题／选择题／是非题（后两者会被**统计**） |
| 材料 | 纯文本 | 可附**图片**与**网址** |
| 连续性 | 一次一批问题 | 逐题作答，**答后面时看得见自己前面的回答**；可多轮追问 |
| 产出 | stdout 上的 JSON | 会话落盘 + 统计 + 分组分布 + 一份完整 Markdown |
| 执行 | 一次同步调用 | 后台任务，按城市分进程，带进度 |

**采访不写入智能体的长期记忆。** 采访是对人口的一次**观测**，不是干预——
一次「居民记得自己被调查过」的运行和一次没有的运行是两个不同的实验，
这不该作为提问的副作用发生。

## 1. 三分钟跑通

1. 起面板：

```bash
python -m gaworld.apps.dashboard_server --port 8766
```

2. 打开 `http://127.0.0.1:8766/site/dashboard/survey.html`（或控制台里的「群体采访」页签）。
3. **第 1 步**：城市选「全部城市」，勾几位个体居民，再勾一两个**群体智能体**。
   右栏「这次要问多少」会实时显示受访者数、代表人数和**模型调用次数**。
4. **第 2 步**：写标题，加两三个问题，其中一个设成选择题并填上选项。点「开始采访」。
5. **第 3 步**：看摘要、选项统计、按城市/年龄段/户籍的分布，展开某个人看原话，
   点「下载完整 Markdown」。

## 2. 选受访者：个体与群体智能体

名单直接读自**城市 bundle**（`data/cities/<slug>/agents.csv` + `profiles.md`），
不经过运行中的配置——否则你只能看见当前选中那一座城市的居民，「跨城市」就无从谈起。
未选城市时的默认人口（`data/hangzhou_*`）以 **默认世界** 的名字出现。

**群体智能体（cohort）** 是 `gaworld/group/cohort.py` 里的那个 cohort：
按属性把人口切成若干格，每格带着**均值和离散度**两套统计量。它一次回答代表整群人，
所以 500 人的小镇问得起；代价是拿不到个人原话。

可用的划分维度只有能从磁盘上还原的那几个：

| 维度 | 说明 |
|---|---|
| `age_band` | 年龄段（默认开） |
| `hukou` | 户籍（默认开） |
| `gender` | 性别 |
| `district` | 片区，由 `residence` 的「·」前半段得到 |

> **为什么没有 `industry`**：行业只存在于人口合成时的内存对象上，既没写进
> `agents.csv` 也没写进 profile。把它列成维度只会把所有人塞进 `industry=none`，
> 那是一个看起来能用、其实骗人的选项。

维度一改，cohort 的编号（`c001`、`c002`…）就指向另一群人，所以面板会清掉已选的群体智能体。
受访者记录里也因此**带着成员 id**，子进程照着它重建那一群人，不重新划分。

## 3. 出题：三种题型

| 题型 | 模型要交什么 | 怎么统计 |
|---|---|---|
| `open` 开放题 | 2-4 句话 | 不计数，生成摘要 |
| `choice` 选择题 | 从给定选项里**原样**挑（可设允许多选）+ 一句理由 | 按选项计数 |
| `boolean` 是非题 | 先明确「是」或「否」+ 一句理由 | 是／否两桶 |

解析对**形式**宽容、对**内容**严格：模型把 JSON 包在 ```` ```json ```` 里、
前面加一段客套话、把选项写成「B. 不支持」，都能读出来；但**答了选项之外的东西**
会被标成 `unparsed`，原话照样进文档，只是不进统计。

这条界线是刻意的。把它塞进某个桶等于替受访者编了一个意见；悄悄丢掉则会在不说明的情况下
缩小分母——那正是一份调查用三份有效回答宣称「100% 支持」的方式。
文档和面板都会写明有多少份没解析出来。

## 4. 多模态：图片与网址

问题上可以挂两种材料：

- **网址**：抓取一次，用现有的正文抽取器（`gaworld/io/web_scrape.py`）压成 ≤1800 字，
  注入提问。**在父进程里抓一次给所有人**——否则每个子进程各抓一遍，
  既是对别人服务器的无谓压力，更糟的是第 1 位和第 40 位受访者可能读到了不同版本的页面。
- **图片**：真的作为图像发给模型。三种线格式都支持：
  OpenAI 的 `image_url` data URL、Anthropic 的 `image` block、Ollama 的 `images` 数组。

图片能不能真的被「看见」取决于模型。provider 配置里可以显式声明：

```json
{"llm": {"providers": {"gpt": {"type": "openai", "model": "gpt-5.4", "vision": true}}}}
```

没声明就按模型名启发式判断。**判断为不支持时，图片会降级成你填的那句「说明」，
并在回答上留下「材料降级」标记**——「这张图说明了什么」由一句 caption 答出来，
和由图片答出来是两种不同的测量，只有一种是你以为你问的那个。

如果模型当场拒绝图片（把 `vision` 设错了、endpoint 不支持 image part），
会自动去掉图片重问一次，并记下「模型拒绝了图片输入」。丢掉一张图并说明，
好过因为一处配置错误丢掉整场采访。

## 5. 连续提问：追问一轮

同一位受访者的问题是**逐题**问的，每一题的提问里都回放着**他自己**前面的问答。
结果页点「继续追问」，写新问题再跑一轮，新一轮的提问里会带上前面所有轮的问答。

问题编号跨轮连续（第二轮从 `q3` 开始），不复用旧编号——复用会把两个不同问题的统计合并。

这份「记忆」只存在于会话记录里，不写 episodic memory。

## 6. 读结果：统计与分组分布

每个问题给三样东西：

1. **摘要**：一次模型调用，读所有回答，写主流看法 + 值得注意的少数看法 + 分歧和什么相关。
2. **选项统计**：每个选项三个数——
   - `受访者`：多少个受访者选了它
   - `代表人数`：这些受访者代表多少居民（一个 8 人的 cohort 算 8 人）
   - `占比`：代表人数 / 有效回答代表的总人数

   两个计数都报，因为混了个体和群体智能体之后，不加权的数字讲的是**抽样设计**，
   不是人口。

3. **分组分布**：按城市／年龄段／性别／户籍／片区交叉。每组按**自己的**有效回答归一化到
   100%——问题是「年长的人答得和年轻人不一样吗」，那是比例问题；用绝对计数会让一个大组的
   形状彻底盖掉一个小组的分歧。

   **只分化了样本的维度才画。** 一座城市的调查画一张只有一根柱子的「按城市」图，
   等于请读者去看一个根本没测过的分布。

## 7. 导出的 Markdown 文档

「下载完整 Markdown」给的是一份能独立存在的文档，顺序是 摘要 → 统计 → **每个人的原话**：

```
# <标题>
| 采访时间 / 受访者 / 代表人数 / 涉及城市 / 问题数 / 回答模型 |

## 访谈背景
## 一、汇总摘要        每题：摘要 + 统计表 + 有效回答说明
## 二、分组统计        每题每个维度一张交叉表
## 三、全部回答        每位受访者的全部问答，含降级与解析失败标记
## 附录 A：未能作答的受访者
## 附录 B：问题清单    题型、选项、附带的材料
```

自带出处是这份文档的设计要求：哪个模型答的、什么时候、问了谁、问题原文，
以及**什么没成功**。一份悄悄省掉六位解析失败居民的文档，是一份夸大了自己样本的文档。

图片不内嵌（一题一个 base64 PNG 会把可读文档变成几兆噪声），附录里记它的说明文字。

## 8. 成本与并发

**一次调用 = 一位受访者 × 一个问题。** 80 人 × 5 题 = 400 次。
这正是连续记忆的代价：他答第 4 题时看得见自己第 1 题的回答，就不能把一轮压成一次调用。

所以面板在开跑前先 `POST /api/interview/plan`，把这个数显示出来。

执行结构：

- **按城市一个子进程**（`python -m gaworld.interview`，环境变量
  `GAWORLD_CONFIG_OVERRIDES={"city": "<slug>"}`）。
  因为 `build_agent`、记忆库、向量库读的都是配置加载时定好的模块级路径，
  一个进程里换城市等于在线程池底下改全局配置。
- 子进程内：**受访者档案串行构建**（记忆库持有的是**进程级单个** SQLite 连接），
  **提问循环按受访者并发**（`concurrency`，默认 4，上限 16）。
- 一位受访者失败不影响其他人；一座城市失败不影响其他城市——
  失败的人拿到一条带错误的记录，文档里写明谁没问到。

上限：一次最多 500 位受访者、每轮最多 20 个问题。

## 9. HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/interview/roster` | 城市、个体、群体智能体、可用模型、可用维度；`?cities=a,b&axes=age_band,hukou` |
| POST | `/api/interview/plan` | 校验并回报「要问多少人、多少次调用」，不花钱 |
| POST | `/api/interview/run` | 起一轮，返回 `job_id`（202） |
| GET | `/api/interview/jobs/<id>` | 进度 / 结果 / 错误 |
| GET | `/api/interview/sessions` | 历史会话列表 |
| GET | `/api/interview/sessions/<id>` | 一次会话的全部内容 |
| GET | `/api/interview/sessions/<id>/export` | Markdown 文档 + 建议文件名 |
| POST | `/api/interview/delete` | 删一次会话 |

> 路径都带尾段。原来的单人采访端点 `POST /api/interview` **没有变**，
> Agent Studio 的采访框仍然走它。

同一时间只允许一轮采访：两轮同时往一个会话文件追加会写坏记录，
两轮打同一个模型后端只会让两边都更慢。

## 10. 落盘位置

```
output/interviews/<session_id>/
    session.json     问题、受访者、全部问答、统计
    report.md        渲染好的文档，每轮重新生成
    round-<n>/       每座城市的 spec 与原始回答
```

**刻意不放在城市的运行目录下。** 别的运行产物都被重指到 `output/cities/<slug>/`，
因为它们属于某一座城市的历史；一次跨城市的会话不属于其中任何一座——
归到某一座，换城市后它就消失了；每座存一份，记录就分叉了。

## 11. 常见问题

**问：选择题的统计比受访者数少。**
有回答没按题型作答（`unparsed`）。面板和文档都会写明有几份。小模型上把选项写短一些、
数量少一些会好很多。

**问：某座城市整体没问到。**
那座城市的子进程失败了（超时、配置、人口文件缺失）。会话的 `rounds[].failures` 里有原因，
结果页顶部和文档附录 A 也会写。其他城市的回答不受影响。

**问：图片好像没起作用。**
先看回答上有没有「材料降级」。有就是路由到的模型被判定为不支持图片——
在 provider 配置里加 `"vision": true`，或换一个多模态模型。

**问：能不能让采访影响之后的仿真？**
目前不能，这是刻意的（见 §0）。需要「把采访当干预」的实验，
应该走事件注入或 `gaworld.kernel.interventions`，让它成为一次显式的干预而不是提问的副作用。

**问：追问时能不能换人？**
不能。追问复用会话自己的受访者名单——否则改一下已选名单就能在一个系列中途悄悄重定义样本。
要换人，开一次新会话。
