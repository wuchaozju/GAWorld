# 普通账号使用研究工作台

## 2026-10-15 权限修复

此前普通账号可以调用 `/api/research/analyze` 生成研究想法，但后续
`/api/research/studies` 和研究操作仍被全局权限表判定为仅管理员。
因此“转成研究 / 自动执行”会立即返回 403。这与所选模型及 API Key 无关。

现在普通账号可以编译、调整、批准、运行、暂停、继续、停止、重置、删除自己的研究，
并下载自己的报告。管理员仍能查看和管理研究。没有归属信息的历史研究仍仅管理员可见，
不自动转交给任意账号。

## 使用步骤

1. 使用自己的账号登录研究工作台，打开自己已生成的研究想法。
2. 首次尝试建议关闭“自动执行”，点击“转成研究”。无需重新生成已有的研究想法。
3. 查看预注册协议和跑前检查，先选择少量居民、较短时间和少量随机种子验证流程。
4. 在协议参数中确认“仿真模型”。顶部用于分析的模型与实际仿真模型是两个设置。
   使用本机 Qwen 时，仿真模型选择 `qwen_27b_server13`；云端模型需该登录账号自己的 Key。
5. 跑前检查通过后批准并运行。以后可使用自动执行，但自动执行不会绕过跑前检查。

研究绑定创建时所在的世界。要修改协议或重新运行，应切回该世界，避免无意中换掉样本。
普通用户不能使用 `force` 绕过预算或安全检查；管理员权限也不意味着模型、指标和政策
机制已经验证可用。

## 隔离与限制

- 研究记录、后台任务及生成的平行世界结果保留归属信息。其他普通账号不能读取、修改、
  删除或直接下载轨迹文件。管理员代为启动研究时，结果仍属于原研究所有者；模型调用
  仍使用实际发起执行的账号身份，不借用研究所有者的个人 Key。
- 模型生成的条件配置仍是不可信输入。成员研究只能调整已有允许范围内的仿真参数，
  不能改凭据、模型端点、文件路径、插件或外部执行设施。
- 每次普通用户启动研究会重新检查协议，不仅信任磁盘中旧的“已批准”标记。
- 新增模型工作的请求受现有每日调用额度检查约束，停止和删除不受该额度阻拦。
  这是启动时的软额度，不是逐 token 的硬计费上限。
- 保留一次只运行一项研究，以及全站仿真进程的并发上限；长研究仍应先缩小规模。
- `85/100` 等可行性评分是模型给出的方案评估，不是实验成功、因果有效性或政策机制
  已实现的证明。报告中应区分原生机制、文本事件近似和无法测量的指标。

## 验证边界

新增测试使用两个普通账号和一个管理员账号，经真实 HTTP 会话覆盖研究创建、人工批准、
自动执行、报告下载、删除、额度、越权访问和轨迹静态文件访问；测试中的模型与仿真后端
使用桩实现，以便稳定验证流程而不产生云端费用。
这些测试不等价于已完成某项具体政策研究或长期仿真的有效性验证。
