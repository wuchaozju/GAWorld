## 0. 这是什么，什么时候该用

GAWorld 原本的个体模拟里，每个 agent 每天要走多次完整认知流水线。这对几十个 agent 是合适的
保真度，对几百人就不可行了——500 人跑一天大约 **10 万次 LLM 调用**。

**群体模拟（group mode）** 增加了一个更粗的层：把人口划分成若干 **cohort（群体）**，
每个群体每天只花 **1 次 LLM 调用**，同时每天挑一小批个体按完整保真度运行。

### 什么时候用它

| 研究问题 | 用群体模式？ |
|---|---|
| 人口分布级指标（收入、情绪、需求满足度的分布怎么变） | ✅ 适合 |
| 政策冲击的处理效应与子群异质性 | ✅ 适合 |
| 极端个体、破产率、稀有事件占比 | ✅ 适合 |
| 观点扩散、极化、少数派引爆、信息级联 | ⚠️ **必须开网络耦合**，并跑验证门确认 |
| 单个居民的完整生活叙事 | ❌ 用个体模式，或把 TA 设为 focal |

这不是猜的——见 [§4 验证门](#4-验证门这个近似可信吗)，四层判定会直接告诉你。

### 三个概念

- **cohort（群体）**：属性空间里的一个格子（默认按 `年龄段 × 行业 × 户籍` 划分），
  500 人约 30–40 个群体。群体同时携带**均值**和**离散度**——只留均值就退化成了
  "代表性个体"，那是 Kirman (1992) 批判的东西。
- **实体化（materialization）**：每天按预算挑一批人跑完整个体流水线。四类：
  `focal`（你点名跟踪的）、`event`（今天卷入关键事件的）、`tail`（群体均值代表不了的离群者）、
  `audit`（随机抽样，**用来量误差而不是减误差**）。
- **网络耦合（network coupling）**：群内零均值的社交图耦合项。cohort 层保留均值，
  社交图决定群内谁动得多。**不开这个，验证门的 L2 一定不通过。**

## 1. 五分钟跑通

```bash
# 1) 造一座 500 人的小镇（不写文件，只看结果）
python -m gaworld.population --size 500 --seed 42 --check

# 2) 按群体模拟 7 天（零 LLM 成本）
python -m gaworld.group --size 500 --days 7 --no-llm

# 3) 验证这个近似可不可信（关键一步）
python -m gaworld.group.validate --size 100 --days 14 --network-coupling 0.7
```

第 3 步不通过时**退出码为 1**，可以直接放进 CI。

## 2. 生成人口

### 2.1 预览（不生成文件）

```bash
python -m gaworld.population --preset cn_county_town --size 500 --seed 42 --check
```

输出：

```
生成完成：500 人 | preset=cn_county_town seed=42
  IPF：2 轮，收敛，最大边缘偏差 0.0006
  关键指标（目标 → 实际）：
    median_age                 36.000 →     36.000
    employment_rate             0.680 →      0.692
    tertiary_rate               0.350 →      0.355
    income_median            6500.000 →   6500.000
    income_gini                 0.420 →      0.414
    household_mean_size         2.600 →      2.604
    mean_degree                12.000 →     12.000
  社交网络：3000 条边，平均度 12.0，聚类 0.115（随机图 0.024），平均路径 2.83，small-world σ=4.2
  被松弛的旋钮（相对误差最大的几个）：
    share_over_65          要求 0.14 → 实际 0.132 （偏差 5.7%）
```

**「被松弛的旋钮」是重点。** 达不成的参数会被显式列出来，而不是假装达成了。
上例里老龄占比差了 5.7%，是整数化取整造成的，可以接受；如果某个旋钮偏差 30%+，
说明你的参数组合本身有内在冲突，改它。

### 2.2 可用预设

| preset | 特征 |
|---|---|
| `cn_county_town` | 默认，中位年龄 36，就业率 68%，收入中位数 6500 |
| `cn_tier1_district` | 一线城区：更年轻、高教育、tech/finance 占比高、收入 11000 |
| `aging_community` | 老龄社区：中位年龄 52，65+ 占 34%，就业率 42% |
| `college_town` | 大学城：中位年龄 27，高教率 80%，合租 45% |
| `us_suburb` | 美国郊区：少儿比 23%，自有住房 72%，基尼 0.48 |

每个预设自身都通过可行性检查（有测试锁住这一点）。

### 2.3 写出文件

```bash
python -m gaworld.population --size 500 --seed 42 --name my_town --out data/town
```

产出三个文件：

| 文件 | 内容 |
|---|---|
| `my_town_state_init.csv` | 与 `data/hangzhou_agents_state_init.csv` **完全同格式**（含 BOM） |
| `my_town_profiles.md` | 与 `data/hangzhou_profiles_with_names.md` 同格式的 profile 块 |
| `my_town_manifest.json` | 完整 spec、代码可复现信息、IPF 收敛报告、校验结果 |

因为格式完全一致，**`build_agent` 不需要任何改动**就能读它（见 [§6](#6-把生成的人口喂给个体模拟)）。

### 2.4 用 JSON spec 精细控制

```bash
cat > my_spec.json <<'EOF'
{
  "size": 800,
  "seed": 7,
  "name": "aging_town",
  "preset": "aging_community",
  "demography": { "median_age": 54, "share_over_65": 0.36 },
  "education_work": { "employment_rate": 0.38 },
  "income": { "median_monthly": 3800, "gini": 0.33 }
}
EOF

python -m gaworld.population --spec my_spec.json --out data/town
```

### 2.5 参数冲突会被拦住

参数不是互相独立的。例如单人户占 60% 时，户均规模的可行区间是 `[1.4, 3.0]`：

```
1·s + 2·(1−s)  ≤  户均规模  ≤  1·s + max_size·(1−s)
```

要求 3.2 会直接报错并告诉你该动哪个旋钮：

```
[error] household.mean_size: 单人户占比 60% 且最大户规模 6 时，户均规模最多是 3.00，但设定为 3.20。
        建议：把 mean_size 降到 3.00 以下，调低 share_single_person，或放大 max_size。
```

同类检查还有：中位年龄能否达成、就业率+失业率是否超 100%、三代同堂户是否超过老人供给。

## 3. 群体模拟

### 3.1 最简运行

```bash
python -m gaworld.group --size 500 --days 7 --no-llm
```

```
群体模拟完成：500 人 → 38 个群体，7 天
  LLM 调用（实测）：0
  实体化个体-天：140
  全个体模拟估算：693000（按 198 次/人/天）
  成本比：本次未调用 LLM（--no-llm），故不可比
  审计残差 L1 最大：0.0000
```

`--no-llm` 下群体简报走确定性 fallback，整轮零成本——用来调参数、看划分、估成本很合适。

### 3.2 成本从哪来

500 人 × 30 天，逐次实测（mock LLM）：

| 实体化预算 | cohort 层调用 | 实体化层调用 | 合计 | 相对全个体 |
|---|---|---|---|---|
| 0 | 1,140 | 0 | 1,140 | **2605× 省** |
| 10 | 1,140 | 59,400 | 60,540 | 49× 省 |
| **20**（默认） | 1,140 | 118,800 | 119,940 | **25× 省** |
| 50 | 1,140 | 297,000 | 298,140 | 10× 省 |

**结论：cohort 层几乎免费，成本几乎完全由 `--budget` 决定。** 调 cohort 粒度对成本影响很小。

### 3.3 跟踪特定居民

```bash
python -m gaworld.group --size 500 --days 7 --focal 7,42 --no-llm
```

focal 居民**每天**都按完整个体保真度运行，即使预算被占满也不会被挤掉——
悄悄丢掉研究者点名跟踪的人，是一种很难发现的失效。

### 3.4 改变划分维度

```bash
python -m gaworld.group --size 500 --axes age_band,district --days 7 --no-llm
```

可用轴：`age_band` `industry` `hukou` `employment` `gender` `district`。
轴越多群体越细、越准、越贵。写错轴名会**直接报错**，不会静默退化成更粗的划分。

### 3.5 开启网络耦合

```bash
python -m gaworld.group --size 500 --days 7 --network-coupling 0.7 --no-llm
```

这个开关让邻居间的共变在群体层能够表达出来——**不开它，验证门的 L2 一定不通过**（见 §4）。
额外成本为零，纯粹是已有社交图上的算术。

在 Python 里：

```python
from gaworld.group.driver import GroupRunConfig, run_group_simulation

cfg = GroupRunConfig(days=7, materialization_budget=20, network_coupling=0.7)
result = run_group_simulation(agents, cfg, llm_fn=call_llm, neighbours=neighbours)
```

⚠️ 两个防呆：

- `network_coupling > 0` 却不传 `neighbours`（社交图）会直接抛 `ValueError`；
- CLI 用 `--population` 读 state CSV 时不能开耦合并会明确报错——**CSV 里没有边**。
  传了强度却静默不生效，会让人以为修复起作用了，其实没有。

### 3.6 用已有人口

```bash
python -m gaworld.group --population data/town/my_town_state_init.csv --days 3 --no-llm
```

注意 state CSV 里**没有 `industry` 列**（个体层是从职业文本推断行业的），
所以这条路径默认按 `age_band,hukou` 划分，群体数会明显变少（上例是 13 个而不是 38 个）。
需要行业轴就用 `--size` 现场生成，或自己用 API 传完整 agent 记录。

## 4. 验证门：这个近似可信吗

**这是整套流程里最重要的一步。** 只看到"省了 25 倍"而不看判定结论，
等于把群体模式当成免费午餐。

```bash
python -m gaworld.group.validate --size 100 --days 14 --network-coupling 0.7
```

### 4.1 四层判定

| 层 | 测什么 | 为什么单列 |
|---|---|---|
| **L1 分布级** | 关键变量边缘分布的 Wasserstein-1 距离 | 比均值会放过"分布塌成一个点但位置正确"的近似 |
| **L2 网络级** | 邻居间状态共变（Moran's I） | 度分布、聚类是**静态图**的属性，两层天然一样，测了等于同义反复 |
| **L3 尾部** | 极端个体占比、分位区间宽度、首次越阈时间 | 聚合近似的已知失效模式正是**保住主体分布、压扁尾部** |
| **L4 因果响应** | 同一政策冲击下的 ATE 方向、量级、子群异质性 | 基线全对但 ATE 反号的近似，用于政策研究会得出相反结论 |

**L2 与 L4 是分水岭**：这两层不过，`gate_passed` 就是 false，退出码 1。

### 4.2 阈值不是拍脑袋的

L1 和 L2 的判定都**相对于实测基线**：先把参照层跟它自己跨种子跑几遍，量出它本身的
run-to-run 波动，近似误差落在同一量级内才算通过。

```
判定 = |群体 I − 参照 I| ≤ 2 × 参照层跨种子标准差
```

量难测时容差自动放宽，好测时自动收紧。绝对常数（比如"比值必须在 0.5–2.0 之间"）
在这里是行不通的——实测下来那个带宽跟估计量本身的噪声同量级，判定会随种子翻转。

### 4.3 读懂输出

```
✅ 通过  L2  网络级：邻居间的状态共变（Moran's I）是否落在参照层自身噪声量级内
          stress           参照 I=+0.069  群体 I=+0.090  比=1.28 z=0.87（容差 2.0σ，σ=0.025）
          emotion          参照 I=+0.035  群体 I=+0.139  （参照信号低于噪声地板，不参与判定）
```

- `z` 是标准化偏差，**这才是判据**；`比` 只是给人看的诊断。
- 「参照信号低于噪声地板」= 这个变量上参照过程本身没产生足够强的传染信号，
  拿两个接近 0 的数相除毫无意义，所以不参与判定。
- 四个变量**全部**低于地板时，整层报 **`⚠️ 无法判别`**——既不是通过也不是失败。
  分水岭层无法判别时，关口**不算通过**。

### 4.4 网络耦合强度怎么定

N=100、14 天、预算 20、3 种子：

| 耦合强度 | 0.0 | 0.5 | **0.7** | 0.9 |
|---|---|---|---|---|
| L2 最差 z | 3.87 | 2.26 | **0.88** | 4.14 |
| 关口 | ❌ | ❌ | **✅** | ❌ |

太小 = 传不动（欠传播），太大 = 传太猛（过传播），两头都算失败。

> ⚠️ **0.7 不是普适常数。** 它是针对验证门内那个参照过程（传染权重 0.6）标定出来的。
> 换成真实 LLM 驱动的个体层后**必须重新标定**——用同样的方法扫一遍，找 z 最小的那档。
> 默认值是 `0.0`（关闭），需要显式开启。

### 4.5 这个门验证了什么、没验证什么

参照层是**逐个体**跑同一个透明的传染过程。所以它衡量的是
「把个体聚合成群体」这一步的误差，**不等于**群体模式对完整 12 阶段 tick 流水线的复现度。

后者需要单独的人工实验：tick 阶段是 `run_simulation` 的内部闭包，从外部调不到，
也没法进 CI。

### 4.6 面板上的验证结果怎么读

CLI 输出是给写方法学的人看的。面板把同一份结果翻译成三段：

**第一段：一句话结论。** 「✅ 这次群体模拟站得住」或「❌ 还不能全信」。
后者会直接给最可能的原因——绝大多数情况是耦合强度还留在 0，提示你回到第 4 步调到 0.7 重跑。

**第二段：能做 / 不能做清单。** 这是四个层真正的含义，按层的通过情况自动分栏：

| 层 | 通过后你可以拿这次结果做什么 |
|---|---|
| L1 | 看整体分布怎么变（收入、情绪、压力的分布） |
| L2 | 研究观点扩散、极化、口碑传播这类靠社交网络传的东西 |
| L3 | 看边缘人群（极端困难者的比例） |
| L4 | 做政策实验（某个冲击造成多大影响、谁受影响最大） |

没通过的那几条会出现在右边的「❌ 不要用来」里。这一栏比任何 z 值都重要：
它是「这次跑出来的东西能不能拿去下结论」的直接答案。

**第三段：逐项白话说明。** 每一层都写出它在问什么、这次差了多少、以及那个容差
是怎么来的（「不是拍脑袋定的，是先让逐个模拟自己换几个随机种子跑几遍、量出它本身
的波动有多大，再拿这个波动当尺子」）。L2 还会额外指出差在哪一边——
「传得太弱」和「传得过强」是两种完全不同的毛病，但在 z 值上长得一样。

完整的技术输出（就是上面 4.3 那种）折叠在最下面的「展开完整技术输出」里，没有丢。

> 实现注记：L2 的 `ratio` 在参照信号低于噪声地板时是 `NaN`。Python 的 `json.dumps`
> 会写出裸的 `NaN`，而这**不是合法 JSON**——浏览器的 `JSON.parse` 会整个报错，
> 于是一个字段让整份验证结果都显示不出来。`job_status()` 现在用 `parse_constant`
> 把非有限浮点统一转成 `null`。

## 5. Dashboard 面板

```bash
python -m gaworld.apps.dashboard_server
# 浏览器打开 http://127.0.0.1:8766/console，切到「人口与群体」tab
```

面板五步，与 Agent Studio 同构：

| 步骤 | 内容 |
|---|---|
| 1 选模板 | preset / 规模 / 种子，选中预设后显示它是什么、什么时候用它 |
| 2 人口结构 | 年龄、家庭、就业、收入旋钮 + **目标 vs 实际对照表** + 年龄金字塔 / 洛伦兹曲线 / 度分布 |
| 3 心理状态 | 九维状态均值 + **均值雷达与 P25–P75 包络** |
| 4 跑模拟 | 天数 / 实体化预算 / 审计比例 / 耦合强度 / **后端模型**，跑完显示每日群体简报 |
| 5 检查结果 | 四层判定的白话解读 + 写出人口文件并给出可直接打开的链接 |

每一步底部都有自己的主按钮（「生成人口 →」「开始模拟 →」等），不依赖页脚的
「下一步」——主操作藏在会变文案的页脚按钮里，用户找不到就会以为功能坏了。

#### 面板上的几件事，值得单独说

**预设有说明。** 选中 `college_town` 之类的模板后，下面会出现一张卡片，写清楚它
是什么人口（例如「学生占比高、单身户多、流动性强」）以及什么时候该用它。

**随机种子有解释。** 页面上写的是「换个数字就是另一批人；填回同一个数字，得到的
还是原来那批人」——而不是「逐字节相同」这种只有实现者才懂的说法。

**指标是中英文双标的。** 「压力 stress」「经济安全感 econ_security」这类标注来自
后端 schema 的 `labels` 字段，面板不再自己抄一份中文名。之前一半中文一半英文
标识符，同一个量在不同卡片里看起来像两个东西。

**写出的文件可以直接点开。** 第 5 步保存后会列出三个文件，每个都带
「在新标签打开 ↗」「下载」和一段折叠的前几行预览：

| 文件 | 是什么 |
|---|---|
| 状态表 State CSV | 每人一行：id、姓名、年龄、户籍、住处 + 九个状态变量 |
| 人物志 Profiles | 每人一段自然语言画像，个体仿真器读它来了解这个人 |
| 生成记录 Manifest | 完整参数、拟合报告、校验结果——复现这批人靠它 |

链接是仓库相对路径（dashboard 本来就静态托管仓库根目录），所以点开即可在浏览器里
查看，不用去文件管理器里翻。卡片里同时显示绝对路径，那是你要粘进
`CONFIG["csv_path"]` / `CONFIG["md_path"]` 的东西。

**验证结果说人话。** 见 [4.6](#46-面板上的验证结果怎么读)。

**选后端模型。** 第 4 步的「后端模型」下拉列出 `gaworld/llm/providers.py` 里实际
配置好的 provider（例如 ollama 的本地模型）。只有勾选「调用真实 LLM」时才生效；
不选就用默认链。本地模型跑群体模拟是最省钱的组合。

两个设计上的提醒会直接显示在面板里：

- **耦合强度滑到 0** → 黄色警告，说明这一档只适合分布级与政策效应级问题。
- **勾选「调用真实 LLM」** → 会产生 API 费用；默认是关的。

右侧常驻**参数体检**面板：纯数学检查、不生成任何人、跟着滑块实时更新，
参数冲突时直接指出该动哪个旋钮，并显示可达区间。

### API（也可以直接调）

| 端点 | 用途 |
|---|---|
| `GET /api/population/schema` | 旋钮契约（面板的单一事实源） |
| `POST /api/population/preview` | 可行性预检，不生成 |
| `POST /api/population/generate` | → `job_id` |
| `GET /api/population/jobs/{id}` | 轮询进度 |
| `POST /api/population/group-run` | 群体模拟 |
| `POST /api/population/validate` | 跑验证门 |

生成与模拟都是**异步 job**（返回 id、轮询进度），500 人生成不会把浏览器卡住。

## 6. 把生成的人口喂给个体模拟

生成的文件格式与现有数据完全一致，所以可以直接换掉：

```python
# config.py / dashboard_config.json
CONFIG["csv_path"] = "data/town/my_town_state_init.csv"
CONFIG["md_path"]  = "data/town/my_town_profiles.md"
CONFIG["agent_ids"] = [1, 2, 3, 4, 5]   # 挑几个跑个体模拟
```

已验证：500 个生成的 agent **全部**能通过 `build_agent` 加载，地图位置有效。

⚠️ 但**不要**直接把 `agent_ids` 设成 500 个跑个体模式——那是 10 万次 LLM 调用起步。
大规模就用群体模式，或者先做下面这件事。

### 顺带：一个与群体无关的性能修复

个体模式的 tick 数其实是随 agent 数**超线性**增长的：`build_master_timeline` 把固定网格
和每个 agent 的 LLM 自拟日程时间**取并集**，而 LLM 生成的 `HH:MM` 没有对齐逻辑。

```python
CONFIG["time_step_minutes"] = 30
CONFIG["time_grid_snap"] = True    # 默认 False
```

开启后 tick 数恒等于 `1440 / step`，与人口规模无关。

> ⚠️ 只设 `time_step_minutes` **不够**——那只是给 tick 数加了个下界，上界仍随 N 增长。
> 必须同时开 `time_grid_snap`。默认关闭是因为它会改变日内时序，旧 run 的 trace 不再逐字节可比。

## 8. 常见问题

**Q：群体数太多／太少？**
调 `--axes`。轴越多越细。低于 4 人的格子会被合并到最近的群体，不会被丢掉。

**Q：`--population` 加载后群体数变少了？**
state CSV 没有 `industry` 列，默认退化为 `age_band,hukou` 两轴。见 §3.6。

**Q：审计残差 L1 一直是 0？**
`--no-llm` 且预算内的个体也没变化时，这是**正确**的——预测为零、实际为零、残差为零。
接上真实个体层后它才会有值。

**Q：验证门某一层报「无法判别」？**
参照过程在那些变量上没产生足够强的信号。这不是通过也不是失败。
把 `--days` 调大让信号积累，或检查参照过程是不是真的有你要测的机制。

**Q：能直接把 group 模式接到 `generative_city_sim.py` 吗？**
目前不能——`CONFIG["simulation_mode"]` 开关还没接。群体模式是平行驱动器
（`python -m gaworld.group`），个体模式因此按构造不受影响。验证门已经过了，
这个开关随时可以接，但接之前建议先按 §4.4 用你自己的个体层重新标定耦合强度。

**Q：怎么确认我没破坏个体模式？**
个体模式的代码路径完全没被改动过（除了默认关闭的 `time_grid_snap`）。
跑 `pytest tests` 即可。

**Q：面板上点「生成人口」没反应？**
先升级到当前版本。旧版有两个问题：主按钮只存在于页脚（文案会变，看不出那是主操作），
且一次请求失败后 `busy` 标志不会复位，之后每次点击都被静默吞掉。现在每一步都有
自己的主按钮，任何请求失败都会在页脚显示红色错误并解除锁定。

**Q：第 5 步一片空白 / 验证跑完了却什么都不显示？**
同样先升级。见 §4.6 末尾的实现注记——`NaN` 让整份 JSON 无法解析。
如果升级后仍然空白，打开浏览器控制台看有没有报错，并附上 `/api/population/jobs/{id}`
的原始返回。

**Q：面板上的指标名和 CLI 输出对不上？**
现在对得上了。面板的中英文标注统一来自 `GET /api/population/schema` 的 `labels`
字段，英文名就是 CLI 和 CSV 列里用的那个标识符。

**Q：写出的文件点开是 404？**
说明输出目录在仓库之外。dashboard 只静态托管仓库根目录，所以只有仓库内的文件能生成
链接；仓库外的文件会照常列出路径，但不带链接。
