# 教育背景、大学生样本与实验入选条件

## 两个不同的字段

- **已获最高学历 `education`**：小学及以下、初中、高中/中专、大专、本科、硕士及以上，或未知。
- **当前在读阶段 `student_status`**：非在读、小学、初中、高中/中专、大专、本科、硕士、博士，或未知。只知道大类时可选大学生、研究生、在读。

例如本科在读者通常填写“已获高中/中专学历、当前本科在读”；已本科毕业并就业者填写“已获本科学历、非在读”。“大学生”筛选匹配大专、本科和仅标明大学生的人，“研究生”匹配硕士、博士和仅标明研究生的人。

字段写入人口 CSV，并在档案中用“教育背景”一行表达。旧 CSV 没有这些列时，只从明确的学历与在读文字读取；年龄、青年身份、家庭照料者身份或本科毕业学历都不能推出大学生身份。辅导员、导师和过去的学生经历也不会被当作当前在读证据。

## 构建与筛选居民

在 **智能体工作台 → 身份** 编辑已获学历、在读阶段和职业，保存后重新选择居民可核对读回。确认修改档案文字中的相应结构化行时，筛选字段也会同步更新。新增、批量导入和真人蒸馏部署都保留显式教育字段。

工作台左侧“筛选居民”和同居模式的“筛选居民”可以组合学历、在读阶段、年龄、性别、职业关键词。结果显示符合人数；同居模式的“随机 4 人”从当前筛选结果中抽取，人数不足四人时只抽取可用人数。已有勾选保留，若要重新抽样可点随机或清空。

## 为现有世界补充学生

打开 **智能体工作台 → 身份 → 补充大学生 / 研究生样本**：

1. 选择大专、本科、硕士或博士，填写 1–200 人和随机种子。
2. 点击“预览学生样本”，核对姓名、年龄、已获学历和在读阶段。此步不写人口文件。
3. 点击“确认追加到当前世界”。已有居民、编号与实验记录保留；新居民使用后续编号。

人口、档案、生成参数或本地姓名配置发生变化后，必须重新预览。重复提交同一预览会被拒绝。追加失败会恢复追加前的两个种子文件。多用户模式下只写当前世界的种子副本，实验复现和游戏在该世界读取这些新增居民。

这些是虚构的补充研究样本，没有经过真实大学生人群的校准，不代表所在城市的真实人口比例。既有城市不会自动重生成，也不会把青年非就业者批量改标成大学生。

## 生成人口

**人口与群体 → 人口结构** 新增“成年高等教育在校生比例”，分母为 18 岁以上人口。普通预设默认 8%，大学城预设 35%；这些是可编辑的合成配置，并非对现实城市的估计。

生成器使用独立种子流，从年龄、已获学历和非劳动人口身份都合适的人中分配在读阶段，保持就业与成年学历拟合。生成结果同时显示目标人数、可安排人数和实际人数；容量不足时不把已就业者改成学生。学生档案使用学习日常。

CSV 和人口清单格式版本为 1.1；旧列仍可读取。默认仿真读取的既有种子文件未被本次功能自动改写。

## 复现大学生实验

在 **研究工作台 → 社会调查/实验拟合度** 核对抽取规格：

- 文献限定本科在读时，将“当前在读阶段”设为本科；仅说大学生时选择大学生。
- 文献未限定已获学历时保留“不限”，不能把本科在读样本设为“已获本科学历”。
- 年龄、性别、学历、在读阶段和职业条件取交集；信息未知者不会匹配指定的已知条件。
- 页面按所选城市显示符合人数。样本少于请求人数时提示不足，并使用全部符合者；零人时不能开始。可先去工作台补充样本再返回。
- 教育和在读阶段也可作为文献分组条件；同一维度内比较。抽样后的居民教育信息随研究记录保存。

模型抽取只保留文献明确报告的条件；研究者仍须对照原文核对。满足入选条件本身不表示智能体与真实被试等价。

## API 与导入

- `POST /api/population/students/preview`：`count`、`student_status`、`seed`，返回预览和 `preview_token`。
- `POST /api/population/students/append`：相同参数加 `preview_token`，向当前世界追加。
- `POST /api/research/replication/check`：`spec` 加 `city`，返回规范化规格及 `eligible` / `total`。
- 居民创建和状态编辑接受 `education` / `student_status` / `job`。
- 导入列支持 `education` / 学历，`student_status` / 在读阶段 / 学籍，`job` / 职业。
- 城市 CLI 单人追加支持 `--education` 与 `--student-status`。
