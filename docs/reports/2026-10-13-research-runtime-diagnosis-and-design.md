## 原因与边界

### 1. 限流后的处理没有匹配限流窗口

`gaworld/llm/providers.py::_retrying` 将 HTTP 429 与连接错误都列为可重试，默认最多三次，等待 0.6、0.9 秒；没有读取 `Retry-After`，没有共享 provider 冷却或研究级失败预算。多个世界会分别触发相同重试链。

已有错误正文明确写明 MiniMax Token Plan 限制（2062）。现有证据无法区分短期 RPM/TPM 限流和更长窗口配额耗尽，不能假设等几秒就会恢复。更换付费渠道或套餐属于另行决策，代码改动不能增加服务商配额。

运行时 MiniMax 失败后确有回退到 `ollama_gemma4`；此前 Ollama 连接拒绝使部分请求彻底失败。2026-10-13 本轮检查中 `localhost:11434/api/tags` 已返回 200，`gemma4:e4b` 和 `gemma4:12b` 均已安装。历史故障不能据此标记为当前仍不可连接；模型列表可访问也不能证明生成质量或延迟。

### 2. “快速模式”的估算与执行不同

`gaworld/research/protocol.py::estimate_calls` 将 `fast=true` 按 1 次/居民/天估算，该研究跑前估算为 360 次。

但 `gaworld/parallel/spec.py::world_overrides` 只设置 `fos_fast_mode`：确定性认知、跳过每日总结与日记。它没有启用 `long_run.enabled`。`ExperimentRunner` 启动的命令也是普通 `run`。离线构造配置已确认：在当前按天、`long_run.enabled=false` 的基配置下，`fast=true` 后实际的 `long_run_enabled()` 仍是 False。

因此日内动作、事件影响、日程调整等仍会反复调用模型。只计算已有 15 个完成世界，其预估为 300 次，实际逻辑请求为 14,705 次，约为预估的 49 倍。这个倍率是当前任务的证据，不应直接作为所有研究的校准系数。

### 3. 并行和时钟因素

种子按顺序运行，每个种子最多并行 2 个世界；这是现有的过载保护。直接增加并发容易加重同一 Token Plan 的限流，也可能增加本地模型排队。

本次继承了 `simulate_realtime=true`，会产生展示用等待，批量研究应显式关闭。等待量由 `seconds_per_day` 决定；不能将数十小时全部归因于这一开关。

世界清单的单调时钟时长与开始/结束日历时间差异很大。例如 seed 2024 baseline 的单调时长约 6.04 小时，但日历时间跨度约 16.51 小时。机器休眠、暂停等是可能解释，当前没有持久化历史能判定具体原因。47:12:06 是实际日历跨度，不是已证明连续工作了 47 小时；需要新增阶段、排队、暂停和 provider 等待的持久化计时。

### 4. 网页没有运行日志数据通路

世界 stdout/stderr 已直接写入隔离的 `run.log`，并设置 `PYTHONUNBUFFERED=1`。研究任务 API 返回进度、状态消息和计时；前端每 1.5 秒轮询，未请求或展示世界日志。不是子进程没有日志，而是日志没有接入研究页面。

## 三种处理方案

| 方案 | 内容 | 取舍 |
| --- | --- | --- |
| A：诊断与可靠性 | 实时日志、provider 检查、限流处理、准确成本说明 | 保留当前细粒度行为；健康调用量仍然高 |
| **B：可靠性 + 独立快速试跑（推荐）** | A，加上使用现有按天简报引擎的独立研究版本 | 大幅减少日内调用；降低行为细节，必须单独标记证据用途 |
| C：月/年步长或群组聚合 | 面向多年宏观政策实验，另设建模规则与兼容性检查 | 潜在更快，但不能通用于传播、日内交互及家庭个体机制实验 |

建议本轮实施 B。C 留给指定研究问题，不能作为通用加速开关。

## 方案 B 的具体实现设计

### Provider 检查与失败处理

1. 跑前呈现实际路由、主模型、备用模型、本地模型是否安装。复用现有配置页 provider 检查能力；本地模型列表检查不发推理，远程生成探测只在用户点击测试或开始已批准实验时做单次有界请求，不能在页面轮询时调用模型。
2. 普通瞬时 429 优先遵循合法 `Retry-After`，无提示时采用可配置的退避；超过单次等待上限/研究等待预算时明确结束或阻止继续提交，不擅自缩短服务商要求的等待再发请求。保留主、备用两条失败原因。
3. 对反复出现的 Token Plan 2062 暴露“等待配额/需检查套餐”状态，达到研究失败预算后停止未启动世界，防止同样失败扩散到所有种子。跨世界的冷却状态应由研究目录下的轻量共享存储协调，而非只存在单个子进程的内存里。
4. 正式研究使用明确选定的模型，避免静默跨模型回退；沿用已存在的显式 `sim_provider` 固定模型功能。若需要切换模型，创建/重新批准新协议，记录实际 provider。探索版本的回退也必须显式记录，降级进入质量标记。

### 实时运行日志

- 新增 `GET /api/research/studies/<id>/logs`，只接受 seed、world 和预定义日志种类，不接受任意文件路径。从已授权 study 的运行记录或活跃 runner 的 manifest 定位文件。
- 用文件字节游标增量读取，限制每次最多 64 KiB，返回 `next_offset`、截断/重置标志。处理重试换文件、日志截断和 UTF-8 多字节边界。既支持运行中世界，也支持运行完成后查看。
- 在研究卡片加入可折叠日志区：种子/世界选择、状态、错误提示、自动滚动和暂停滚动。复用现有 1.5 秒轮询频率，不重建整个研究卡片；隐藏页面降低轮询，终态读取最后一段后停止。
- 文字以 `textContent` 展示，API 输出脱敏，不显示密钥或认证头。多用户环境先检查 study 的所有权和所属世界，路径需限定在该次运行目录。新增接口登记 OpenAPI 和权限策略。
- 运行后问卷的 subprocess 输出也应写到独立日志，而非等 `capture_output` 完成后才能读。编译、评估、解读等阶段写研究任务事件日志，避免只有世界运行阶段可观察。

### 准确成本和耗时

- 保留原 `fast` 的行为，名称解释为“精简认知”，纠正其每天一次调用的错误估算；新协议另设 `execution_mode`，明确 `tick`、`lean_tick`、`daily_brief`。旧协议不因软件升级自动变成新模式。
- 成本分项列出启动、居民简报、环境模型、后置问卷和解读，估算与实测分开；按天简报的“每人每天一次”仅指主体简报，不能承诺整个运行只有这些调用。
- 将实际请求数、失败数、回退次数、provider 延迟和当前阶段呈现在卡片并持久化。区分日历时间、活动时间、暂停、排队和 provider 冷却；有足够实测进度后才给 ETA，停止后不再显示 ETA。
- 批量研究显式设置 `simulate_realtime=false`；保持按种子顺序和 provider 可承受的并行数，不能靠扩大并发掩盖调用量问题。

### 独立“快速试跑”版本

- 从研究卡片创建新 study，记录 `parent_study_id` 和所有协议差异，原协议和产物保留。创建只是生成待审协议，不自动花费模型调用。
- 使用 `daily_brief` 显式启用 `long_run.enabled=true, unit=day`，调用既有 `gaworld/sim/_fastforward.py`。不改默认仿真引擎，不往根入口增加子系统逻辑。
- 默认保持条件、指标、事件日期、天数和同一实际样本；将种子缩到原列表第一项，显式展示这个变化。允许用户在审阅时调整，但天数不得短于末次事件与必要观察窗口。
- 若原研究样本留空，则在创建时解析为当前有效的具体居民 ID，显示人口数量和实际城市；未能验证城市/样本匹配时阻止声称运行了原先文字人口。
- 该案例在相同 20 天、6 条件、1 居民、1 种子下，主体简报调用理论量为 120 次，外加启动、环境、扩展插件、问卷和解读。与 14,705 次现有请求的差异说明有很大提速空间，不能在未跑代表性验证前承诺分钟数或速度倍率。
- 网络传播、细粒度对话、特定插件或依赖日内轨迹的指标先做兼容性检查。缺失机制/指标不能返回成功的效应结论；页面指出不兼容项，提示回到细粒度模式。
- 快速版本报告始终标记“近似探索/流程检查”，即使有安慰剂也不把单种子判定升级为正式验证结论。评估结果必须带 mode/用途；快速与正式、多模型之间不能混合汇总种子或当作同一实验复现。

## 验收与实施边界

1. Mock 测试覆盖 429/Retry-After、2062 连续失败、备用端口拒绝、失败预算及停止后不启动剩余世界，不调用真实模型。
2. API 测试覆盖运行中与已结束日志、游标/截断、UTF-8、重试、脱敏、路径限制和跨用户/跨世界访问拒绝；OpenAPI 与账号权限检查通过。
3. 快速版本测试覆盖继承事件与样本、种子差异、原协议不变、按天简报真正开启、旧 fast 不被重释，以及不兼容指标与探索判定边界。
4. 浏览器使用受控运行/日志验证实时追加、切换世界、停止后最后一段日志、移动端展示和错误状态；无需启动新的付费研究来验证日志功能。
5. 运行研究相关测试、core suite 和变更文件 lint ratchet。新模式默认关闭；若实现实际改变默认运行结果，按仓库规则追加 comparability epoch。
6. 正式性能倍数必须通过用户批准的代表性运行测量；本轮诊断没有新运行。服务商配额/付费模式不会擅自修改。

## 实施记录

方案 B 已实现。验证使用 mock/隔离子进程，没有启动新的付费研究。实时日志、实测调用统计、共享 provider 冷却/失败预算、独立按天简报探索版本及协议差异已接入研究卡片。日内与快进引擎明确固定；人口输入文件使用尝试级快照，模型定义固定，凭据仅进入子进程环境、不写入实验 manifest。

对旧研究的进一步来源审计发现，不同世界的运行清单曾使用不同 CSV（含绍兴柯桥和默认人口来源）。因此默认快速克隆会被拒绝。用户可以明确改用当前城市创建独立探索版，样本变化会记录；不兼容指标及相关假设也只有在探索子研究里显式排除后才改变。系统不会声称它与旧运行具有相同人口。

core suite 验证为 485 passed、1 skipped；一次广泛研究相关验证为 195 passed、1 skipped。跳过项是可选 OpenAPI 校验库未安装。最终聚焦回归为 171 passed、1 skipped、690 subtests，JavaScript 日志控制器 4 项测试通过。390px 浏览器布局无横向溢出，日志追加、脱敏与结束后的最后一行可见。完整工作区 lint ratchet 的剩余失败来自既有无关改动；本轮新增文件及相对脏工作区基线的 lint 增量单独核对。

这证明实现与受控流程通过验证，不代表 MiniMax 当前配额已恢复，也不提供真实模型下的提速倍率或研究结论。

### 快速试跑兼容性误判修复

默认配置将 `distributed` 和 `moltbook` 标为开启，但平行世界的 `world_overrides` 已关闭这两项，避免跨世界通信及向真实账号发帖。按天简报的检查此前读取了全局默认值，导致快速版本在批准时被错误阻止。检查现在保留运行中的多人交互限制及条件明确启用日内机制的限制，不再误判已被隔离引擎关闭的继承配置。

已用实际快速研究 `S20261013-134320-a188` 做只读兼容性验证；129 项相关测试与变更文件 Ruff 检查通过。测试确认快速批准、实际世界配置仍关闭这两项、原协议与全局配置未变，以及显式日内机制仍被拦截。未启动新的模型实验。

### 简报失败预算耗尽：2026-10-13 后续诊断与修复

研究 `S20261013-163758-4977` 的第 1 次尝试使用 MiniMax-M3、按天简报、1 位居民、6 个世界、1 个种子及 90 天。保存的运行统计记录 271 次 HTTP 请求，HTTP 失败为 0，provider 失败为 0，简报不可用为 3。基准世界已生成到 Day 25，低补贴世界已生成到 Day 10，随后分别在下一天发生简报解析异常。本次错误不是已证实的 HTTP 429，也不表示此前完全没有生成简报。部分输出不能替代完整世界的可比较研究结果。

旧研究路径遇到一次不合格简报就终止该世界，并累计研究失败预算。旧日志未保存失败响应或解析分类，因此无法复原这三次输出的具体错误，不能将下面的解析器弱点认定为实际故障的唯一原因。

复现检查发现，完整 JSON 前的思考块中若包含大括号，旧解析器可能取错范围。研究按天简报现在使用独立解析器，支持完整前置思考块、代码围栏及前后文字；拒绝未闭合思考段、截断 JSON、多份候选简报、缺失状态对象和非法状态增量。未闭合思考段内的示例不会被用于居民状态。

每份简报最多额外调用一次模型重新输出结构化结果，使用同一任务和原始资料，不制造占位简报；两次仍不可用才记一次终止失败。provider 异常继续按 provider 的预算处理，不作为格式错误再次调用。页面与报告增加有效简报、解析错误、修复成功及最终不可用计数。诊断仅存世界日志、任务、居民、次数、日期、失败分类、响应长度及哈希，不保存原响应。研究总预算及停止边界仍生效，普通快进仿真路径不变。

原尝试及其部分日志保留。本轮修复只使用 mock 和已有产物，未重新运行真实模型，也未调整 MiniMax 套餐或全局模型配置。修复会增加不合格简报的有限调用开销，不能保证服务商输出一定恢复合格。

本次验证：简报、共享运行预算、快进、研究运行及研究生命周期共 100 项测试通过；core suite 为 485 passed、1 skipped（可选 OpenAPI 校验库未安装），另有 746 subtests；前端控制器 8 项测试通过。复核发现并修复的未闭合思考块问题有两项独立回归。新增文件及计数/报告模块 Ruff 检查通过，快进文件的既有 6 条检查项未增加。确认无运行任务后重启本地 8766 服务；浏览器查看原失败研究，修正提示与原 271 次调用统计可见，无页面错误。未点击重置或运行按钮。
