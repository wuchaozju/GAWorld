# 模型 HTTP 连接复用：第二阶段

日期：2026-10-30。本轮延续保持模拟行为的工程优化，降低连续模型请求的重复建连开销。

## 改动

`gaworld/llm/providers.py` 的 `_post` 保留为研究账本 HTTP 提交计数入口，下层改用 `gaworld/llm/http_transport.py`。原先的 `requests.post()` 每次创建并关闭 Session；新实现仅在线程内保留底层 HTTPAdapter，Session、CookieJar、模型认证头和请求参数仍为每次请求独立创建。

- 每线程独立池；线程退出销毁，进程退出清理，显式关闭后下次重建。fork 后重置线程状态及互斥锁，并检查 PID，避免使用继承的连接。
- 有效 TLS verify、客户端证书或本次 URL 实际选择的代理发生变化时关闭并替换适配器。代理认证变化不会持续累积旧 ProxyManager。
- HTTPAdapter 不自动重试；provider 原有重试、限流、账本 HTTP 次数、模型调用顺序和载荷不变。
- 继续使用 Requests 的环境代理、CA、超时和重定向处理。TLS 验证没有关闭。每个管理器缓存最多 8 个原点池、每池最多保留 2 个闲置连接；不限制调用方同时持有的活动响应，也不引入等待池空位的阻塞。
- 阻塞请求及完整读尽的流可以归还连接。现有 OpenAI/Ollama 在结束标记处停止时，未完成的 HTTP body 仍可直接关闭；不为追求复用额外等待服务端 EOF。

本轮未增加主入口行数或新根模块；没有更换模型、合并认知调用、降低认知频率或开启居民并发。工作区原有改动及上一阶段优化保留，未提交更改。

## 本地 TLS 基准

环境：Python 3.12.9、Requests 2.34.2、arm64。仅使用 127.0.0.1 上的 HTTP/1.1 TLS 替身服务器，临时证书包含 localhost/127.0.0.1 SAN，客户端以临时 CA 文件验证证书；没有外部模型请求、没有付费调用。

每批 24 次请求，各模式重复 5 轮；交替执行旧 `requests.post` 与新传输，每轮先关闭旧池，故时间包含该批首次建连。服务器启用 TCP_NODELAY，避免测试服务器小包的延迟确认影响。新旧请求体、认证头、无跨请求 Cookie 及响应内容逐项一致。

| 场景 | 原实现中位 ms/批 | 新实现中位 ms/批 | 局部倍数 | 每批连接数 |
|---|---:|---:|---:|---:|
| 普通 JSON 响应 | 50.341 | 13.976 | 3.60× | 24 → 1 |
| 完整读尽的流式响应 | 46.203 | 13.463 | 3.43× | 24 → 1 |

原始各轮测量和断言结果：`output/performance/2026-10-30-http-transport-benchmark.json`，是本地生成产物，不纳入提交。

**这些倍数只描述无模型生成时间的本地传输。** 不能据此声称整场模拟快 3 倍。真实运行仍包含模型生成时间和其他阶段，应查看上一阶段新增的运行耗时报告。流式表格特指完整读尽响应；真实模型在结束标记处提前关闭分块流时不保证复用连接，这一路径已用真实本地 HTTP 分块响应验证输出及请求次数。

## 使用与边界

下一次从控制台新启动的模拟子进程会加载该传输，无需新增操作；已经运行的进程不会热更新。服务端若主动关闭连接、客户端放弃未读完的流，或代理/TLS 策略变化，需要重新建连。并发上限仍由已有调用方控制，本轮不会增加模型请求数量。

第一阶段记忆优化及耗时统计说明见 `docs/reports/2026-10-29-simulation-performance.md`。后续可依据实际耗时决定是否处理日志/轨迹写入，或单独设计会改变认知机制的加速模式。
