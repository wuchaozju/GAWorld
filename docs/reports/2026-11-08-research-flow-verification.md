# 研究工作台：流程恢复与分层阅读验证

日期：2026-11-08（Asia/Shanghai）。范围为「实施方案」中的论文解读、生成方案、编译协议、运行状态和结果报告；用户已确认推荐设计。本次使用当前 checkout 增量修改，保留原有未提交改动。

## 修复与行为

1. 生成任务采用独立提交标识与用户/世界范围内的幂等预留；POST 回包丢失时通过 GET 恢复同一任务，包括已完成的论文解读。断连按退避自动重连，HTTP 401/403/404 明确结束追踪。浏览器请求覆盖响应体解析，20 秒内结束等待。打开的方案/研究通过 URL 恢复；运行时旧响应不能覆盖新选择。
2. 生成/编译任务保存在 `output/research/jobs/`，终态可在内存淘汰后读取；服务重启留下的生成任务显示中断。读取、恢复、幂等判断均保留用户与世界隔离。上下文仅返回任务元数据，原论文及解读通过对应授权任务读取。
3. 修复生成按钮的忙碌状态：轮询不会反复累积计数，终态恢复可点击。编译期间防止重复点击。论文解读保留原始材料和恢复指针；刷新可继续设计实验，材料发生变化时阻止误用旧解读。
4. 研究文档模型调用的等待预算为 300 秒，补充结果解读为 90 秒。使用有界 I/O worker 的 Future 等待，避免非流式请求持续返回少量字节时无限卡住；复制用户、世界、调用账本上下文。最多四个 I/O worker，迟到回答不能落盘覆盖结果。无法强制取消服务商已经接收的请求，I/O worker 可能到原 HTTP 请求返回时才释放；普通仿真的超时配置与统计判定规则未改变。
5. 统计完成即保存可下载报告，再等待可选解读。页面先展示研究对象、实验比较、观察指标和规模；结果先展示逐条假设判定、依据、质量及适用边界，再看完整表格和折叠日志。页面与 Markdown 共用确定性摘要，不新增模型摘要调用。替代设计未单独估算成本时明确标注；探索试跑与方向性指标的限制保留。
