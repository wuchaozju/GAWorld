## 0. 它做什么

研究工作台分两段，前一段产出**文档**，后一段产出**证据**：

```
┌─────────────── 方案（plan）──────────────┐   ┌──────────────── 研究（study）────────────────┐
材料 ──(论文)──→ 解读 ──→ 你审阅修改 ──→ 方案 ──→ 预注册协议 ──→ 跑前检查 ──→ 批准 ──→ 运行
  └──(想法)─────────────────────────────↗   (选一个设计)                         │
                                                                                  ↓
                                                   报告 ←── 模型解读 ←── 代码判定假设
```

| 阶段 | 谁来做 | 产物 |
|---|---|---|
| 解读论文 | 模型（不看功能目录，只读论文） | 理论 / 方法 / 关键变量 / 发现 / 研究问题 / 假设，**可编辑** |
| 生成方案 | 模型（对照 `docs/FEATURES.md`） | 功能映射、2–3 种实验设计、实施步骤、可信度检验、局限、成本 |
| 编译协议 | 模型 + 代码校验 | 每个条件是一个平行世界，每条假设有指标、方向、最小效应 |
| 跑前检查 | 代码 | 通过 / 不通过（错误会拦住批准） |
| 运行 | 平行世界引擎 | 每个种子一次普通的平行世界实验 |
| 判定 | 代码 | 每条假设：支持 / 反向 / 不确定 / 未测到 |
| 解读 | 模型（只能引用给定数字） | 发现、局限、后续研究 |
| 报告 | 代码 | 一份 Markdown：先预注册，后结果 |

三条原则贯穿始终：

1. **模型只能引用存在的东西。** 方案只能映射到功能目录里的功能，协议只能用可测量目录里的指标，做不到的写进「局限与替代」或「编译时丢弃」，不会被悄悄保留。
2. **预测先于结果。** 方向和最小效应在跑之前就写进协议，跑完不能改。
3. **判定在代码里，解释在模型里。** 模型不能推翻代码的判定，也不能把「不确定」写成「有效应」。

只想要一份实验方案文档？做完第一段就可以停，方案随时能下载成 Markdown。

## 1. 三分钟跑通：一个研究想法

1. 起面板：

```bash
python -m gaworld.apps.dashboard_server --port 8766
```

2. 打开 `http://127.0.0.1:8766/site/dashboard/research.html`（或控制台里的「研究工作台」页签）。
3. 材料类型选 **研究想法**，在「内容」里写一两段话，例如：

   > 我想研究在一座 500 人的县城里，给低收入家庭发放租金补贴之后，他们的压力会不会下降、经济安全感会不会上升；和不发补贴的世界比较。

4. 「分析用的模型」选一个（或留「按配置路由」），点 **生成实施方案**。
5. 等进度条走完（本地模型可能要几分钟），右侧「历史方案」里多出一条，结果卡片展开。
6. 点 **下载 Markdown** 拿走方案文档。

## 2. 完整教程：从一篇论文到一份报告

下面用一篇**示例**论文走完整条链。假设你手上有一篇研究「租金补贴对低收入租户心理压力的影响」的 PDF，
方法是双重差分，结论是补贴组的自评压力显著下降。

### 2.1 上传论文

1. 材料类型选 **一篇论文**（上传 PDF 时会自动切过去）。
2. 点 **从文件读入（.txt / .md / .pdf）**，选中论文。
   - PDF 在服务器端用 `pypdf` 提取文字；`.txt` / `.md` 直接在浏览器里读。
   - 读完会提示「已读取 xxx：N 页，M 字」，标题栏自动填入文件名。
   - 扫描版 PDF 没有文字层，会提示改为粘贴文本。
3. 看一眼字数。超过 **80,000 字** 的部分会被截断——全文的尾部通常是参考文献和附录，截掉不影响分析。
   如果论文很长而关键内容在后面，可以只贴摘要、方法和结果三节。

> 论文贴摘要就够用，贴全文会更准：方法和变量定义往往只在正文里。

### 2.2 第一步：解读论文

点 **① 解读论文**。这一步只做一件事：读懂论文。提示词里不带功能目录，所以比完整分析快得多。

完成后，表单下方出现 **「2 · 论文解读（可修改）」** 卡片，六个字段都是可编辑的文本框：

| 字段 | 该检查什么 |
|---|---|
| 理论框架 | 论文的核心论点有没有被读偏 |
| 方法与数据 | 样本、数据来源、识别策略（DID / RDD / 实验……）是否准确 |
| 关键变量 | 每行一条；自变量、因变量、调节/中介变量是否齐全 |
| 主要发现 | **最容易出错的地方**——有没有编造论文里没有的发现、把方向写反 |
| 研究问题 | 每行一条；删掉仿真回答不了的问题 |
| 假设 | 每行一条；写成「干预 → 结果变量往哪个方向变」的形式，后面编译协议时最好用 |

**这一步值得花时间。** 读错的方法或编造的发现，在这里改只要几秒；等三种实验设计都建立在它上面之后再发现，就得全部重来。

几个实用的改法：

- 把「自评压力」这类论文里的测量，改写成 GAWorld 能测的状态变量名（压力、经济安全感、情绪……，完整列表见 [4.3](#43-可测量指标)），后续协议编译的丢弃会少很多。
- 假设写清方向：`H1：发放租金补贴后，低收入家庭的压力下降`，比 `H1：补贴影响压力` 好得多。
- 解读不满意，点 **重新解读**；改了材料或切换了类型，旧解读会自动作废。

> 不想分两步？表单下方有 **跳过解读，直接生成方案**，走原来的一步流程——解读和方案在同一次模型调用里完成。

### 2.3 第二步：据此设计实验

改好后点 **③ 据此设计实验**。模型会拿到三样东西：论文原文、**你确认过的解读**、整份功能目录。
提示词明确要求沿用你的解读，方案保存时也以你的版本为准——模型重新表述的解读会被覆盖。

### 2.4 读方案

结果卡片从上到下依次是：

1. **标题与徽章**：材料类型、模型、生成时间、可行性（高 / 中 / 低 + 0–100 分）。
2. **概要**与**可行性依据**。
3. **论文摘要**、**研究问题**、**假设**——就是你确认过的那份。
4. **功能映射**：「研究需要 → GAWorld 功能 → 用法 → 入口」。入口是 CLI 命令、控制台页签或配置项，可以照着找。
5. **实验设计**：见下一节。
6. **实施步骤**：按推荐的设计，每一步带命令（可复制）和对应的面板。
7. **可信度检验**、**局限与替代**、**成本估算**。
8. 折叠的**原始材料**。

「局限与替代」要认真读：它列的是 GAWorld 做不到或做不好的地方（比如没有住房市场），以及替代做法或需要新写的插件。

### 2.5 比较几种实验设计

「实验设计」一节顶部有一排标签：`设计 1：忠实复现`、`设计 2：机制检验 [推荐]`、`设计 3：延伸情境`……
模型被要求给出 **2–3 种思路实质不同**的设计，常见的组合是：

| 类型 | 思路 | 典型取舍 |
|---|---|---|
| 忠实复现 | 尽量照原研究的样本、干预和时间跨度 | 可比性最好，但往往最贵，且原研究的一些条件在仿真里做不到 |
| 机制检验 | 只保留核心干预与一两个结果变量 | 便宜、干净，能回答「机制在仿真里是否成立」 |
| 延伸 | 换情境、换剂量、换人群 | 回答原研究没回答的问题，但与原文不可直接比较 |

每个设计都有：思路、优势、短板、城市、人口、Agent 设定、时间跨度、实验条件、事件、测量指标。
点标签切换；带 **推荐** 的是模型的建议，实施步骤也是按它写的。

下载的 Markdown 里会列出全部设计，推荐的那个标着「（推荐）」。

### 2.6 转成研究

选中你想跑的设计标签，点结果卡片右上角的 **转成研究**。

- 编译的是**当前选中**的设计，不一定是推荐的那个。
- 旁边的 **自动执行** 勾上后，跑前检查一旦通过就直接批准并运行，不再等你点；**检查不通过时自动执行也不会跳过闸门。**

编译是一个后台任务（一次模型调用），完成后右侧「研究」列表多出一项，下方展开研究卡片，阶段是 **待批准**。

### 2.7 审阅协议，调参数

研究卡片上是编译出来的**预注册协议**（字段见 [第 4 节](#4-预注册协议)）：

- **条件**：每行一个世界，角色是基准 / 处理 / 安慰剂，列出它的事件表。
- **假设与预测**：指标、对比的两个条件、预测方向、最小效应、聚合方式。
- **编译时丢弃**：模型写了、但代码判定无法执行的内容，以及原因。**这里有东西一定要看**——比如一条假设用了不在目录里的指标，它就不会被检验。
- **跑前检查**：错误（红）和警告（黄），以及估算调用量。

协议的科学内容（条件、指标、预测）编译后就固定了，但成本和范围的旋钮可以调：

| 旋钮 | 作用 |
|---|---|
| 仿真天数 | 1–3650；必须晚于最后一个事件日，否则事件来不及起作用 |
| 种子（逗号分隔） | 最多 5 个；至少 2 个才有跨种子一致性 |
| 快速模式 | 每位居民每天只做一次日程简报，调用量降两个数量级 |
| 参与居民 id | 留空 = 当前城市配置里的全部居民；只选十几个人是最有效的省钱办法 |
| 仿真模型 | 居民跑在哪个模型上，和编译协议用的模型分开 |

每次修改都会重新做跑前检查。

### 2.8 批准并运行

跑前检查通过后，点 **批准** 或 **批准并运行**。运行时：

- 每个种子是一次普通的平行世界实验，写在 `output/parallel_worlds/study_<研究 id>_s<种子>/` 下，工作台的「平行世界 · 反事实推断」页签可以直接打开、看分歧曲线、回放；同一研究的各种子会被识别为一组，在「跨种子重复」里合并。
- 一次只能跑一项研究（每项都是好几个完整仿真，同时跑会互相拖慢）。
- 运行中可以 **暂停** / **继续** / **停止**，见 [第 8 节](#8-研究的生命周期暂停停止中断重置)。

### 2.9 读结果与报告

跑完后，阶段依次变为 **已判定** → **已出报告**，卡片上多出：

- **结果表**：每条假设的各种子效应、均值效应、噪声底线和判定徽章（支持 / 反向 / 不确定 / 未测到），以及判定依据。
- **数据质量**：有没有世界没产出数据，有没有指标在所有世界里都不变（全程为 0 的指标不能拿来下结论）。
- **解读**：模型给出的发现（每条挂在一个假设 id 上）、局限和后续研究建议。

点 **下载报告** 拿走完整的 Markdown。

## 3. 方案里有什么

一份方案（`output/research/<plan_id>.json`）的字段：

| 字段 | 内容 |
|---|---|
| `kind` | `idea` / `paper` |
| `title`、`summary` | 标题、一段话概要 |
| `paper_digest` | 仅论文：`theory` / `method` / `key_variables` / `findings` |
| `research_questions`、`hypotheses` | 字符串列表 |
| `feasibility` | `score`（0–100，缺失为 -1）、`verdict`（high / medium / low）、`rationale` |
| `capability_map` | `[{need, feature, how, entry}]` |
| `designs` | 2–3 个设计，每个含 `name` / `approach` / `strengths` / `weaknesses` / `city` / `population` / `agents` / `timeline` / `conditions[{name, manipulation}]` / `events[]` / `measures[{name, operationalization, source}]` |
| `recommended_design` | 推荐设计在 `designs` 里的下标 |
| `design` | 推荐的那个设计的副本（编译协议的默认输入；旧方案只有这个字段） |
| `steps` | `[{title, detail, commands[], panel}]` |
| `validation` | 可信度检验列表 |
| `gaps` | `[{limitation, workaround}]` |
| `estimated_cost` | `{llm_calls, note}` |
| `material`、`material_truncated` | 分析时的材料原文，是否被截断 |
| `markdown` | 渲染好的文档 |

模型的回答是 JSON，由代码逐字段校验：缺一节只会让那一节留空，不会让整次分析失败；
推荐下标越界时退回第一个设计；按旧格式只回一个 `design` 的回答也照样能解析成一个设计。

## 4. 预注册协议

### 4.1 为什么要有这一层

方案是写给人看的文档：条件、事件、指标都是文字。协议是同一项研究写给执行器看的版本——
每个条件已经是一个平行世界，每条假设都点名了一个可测量指标、两个要对比的条件、一个方向和一个最小效应，
这样跑完可以**不经任何人判断**直接打分。这就是开放科学意义上的预注册：预测在跑之前定死，判定是算出来的而不是争出来的。

### 4.2 协议字段

| 字段 | 内容 |
|---|---|
| `kind` | `parallel_worlds`（只跑世界），或 `composite`（跑完世界再采访各世界的居民，见 [4.5](#45-问卷先跑世界再采访居民)） |
| `sample` | `city`、`agent_ids`（空 = 全部）、`note` |
| `sim_days`、`fast`、`max_parallel`、`sim_provider` | 天数、快速模式、并行世界数（1–4）、仿真模型 |
| `conditions` | 最多 8 个：`{id, label, role, events[], config}`；`role` 是 `baseline` / `treatment` / `placebo` |
| `measures` | 用到的指标 id |
| `survey` | 只有 `composite` 才有：`{context, questions[]}`，每题 `{id, text, kind, options}` |
| `hypotheses` | 最多 20 条：`{id, statement, measure, treatment, control, direction, min_effect, aggregation}` |
| `validity` | `seeds`（最多 5 个，默认 `[42, 43]`）、`placebo` |
| `dropped` | 编译时丢弃的内容：`{what, where, reason}` |
| `notes` | 测不到的东西、简化之处 |

- `direction`：`increase` / `decrease`（「上升」「降低」这类中文也能识别）。
- `aggregation`：`final`（最后一步的值）或 `mean`（全程均值）。
- 协议要求有安慰剂时，代码会补一个「市政通告」式的无关事件世界，作为噪声底线。

### 4.3 可测量指标

协议只能用下面这些指标——都来自每个世界的 `state/agent_state_history.csv`，取值 0–1（`stance_score` 是 −1–1）：

| 类别 | 指标 id（名称） |
|---|---|
| 九维状态 | `emotion`（情绪）、`stress`（压力）、`econ_security`（经济安全感）、`city_identity`（城市认同）、`policy_sensitivity`（政策敏感度）、`platform_dependence`（平台依赖）、`risk_preference`（风险偏好）、`voice_propensity`（表达倾向）、`mobility_intent`（流动意愿） |
| 干预插件 | `stance_score`、`toxicity_score`、`misinformation_risk`、`cross_viewpoint_exposure`、`intervention_reward`——**需要开启 `CONFIG["intervention"]["enabled"]`** |
| 生理 / 需求 | `energy`、`hunger`、`fatigue_debt`、`self_control`、`social_need`、`time_pressure` |

以当前代码为准：`gaworld/research/measures.py` 的 `registry()`。composite 研究另有问卷指标 `survey.Q<n>`，见 [4.5](#45-问卷先跑世界再采访居民)。社交网络统计、经济账本还不在其中。

**来源等级。** 每个指标都带一个等级：它依赖的机制里最弱的一级，分级沿用 [`benchmark/MECHANISM_PROVENANCE.md`](../benchmark/MECHANISM_PROVENANCE.md)——
(a) 从真实数据校准，(b) 文献里的标准机制、参数有公开区间，(c) 我们自定的合理猜测或按目标标定的旋钮。
**目前目录里的指标全是 (c)**：

| 指标 | 由什么驱动 |
|---|---|
| 九维状态 | 事件和政策对它的影响由**一次模型调用直接给出**（每件事 ±0.2 以内，`infer_event_effect`）——效应方向就是模型对这件事的判断；之后按手写的均值回归公式每步拉回，人生事件、家庭事件另带固定增量。`econ_security` 还每天按账本资产 / 三个月开销平滑更新 |
| 干预指标 | 对信息流和居民所写文字做关键词匹配打分，关键词表和权重是定的；文字由模型生成 |
| 生理 / 需求 | 手写规则，目标值与回归速率是定的 |
| 问卷 | 模型扮演居民的自述 |

(c) 级指标**不得单独立论，只读方向，效应大小不作数**。判定规则不因等级改变，但等级会出现在编译提示词、协议、结果和报告里：
每个效应旁边写着「只读方向，大小不作数」，解读里给 (c) 级指标写了具体大小的结论会被标出来（见[第 7 节](#7-解读与报告)）。
把鼠标移到面板上指标旁的 `(c)` 上可以看到它由什么驱动。

第一行值得多想一步：「补贴让经济安全感上升」这类结论，很大一部分是在复述模型被问到「补贴对这个人有什么影响」时给的答案。
它能说明的是：模型的这个判断穿过了状态动态、在多个种子上方向一致——而不是现实里补贴有多大作用。

### 4.4 什么会被丢弃

| 情况 | 结果 |
|---|---|
| 假设的指标不在上表里 | 该假设丢弃 |
| 处理条件不存在，或对照缺失 / 与处理相同 | 该假设丢弃 |
| 方向不是上升 / 下降 | 该假设丢弃 |
| 条件超过 8 个 | 多出的丢弃 |
| 事件或 config 补丁格式不对 | 该事件 / 补丁丢弃 |
| 已有 8 个世界又要安慰剂 | 安慰剂丢弃 |
| 问卷题文字为空，或超过 8 题 | 该题 / 多出的题丢弃 |
| 假设引用的是开放题 | 该假设丢弃（开放题不计分） |

丢弃的内容**会被记下来并显示**，不会被悄悄修正——否则就会在一次昂贵的运行之后才得到一句「未测到」。

### 4.5 问卷：先跑世界，再采访居民

状态变量回答不了「居民怎么看」——信任、满意度、支持与否只能问。方案要测这类东西时，编译出的协议是 `composite`：
平行世界照常跑，每个种子跑完后，在**每个世界里**用该世界的记忆和该世界最后一步的状态采访居民，答案计分后和状态指标一样进判定。

| 题型 | 计分 |
|---|---|
| `scale` | 有序单选，默认五级同意度（非常不同意 … 非常同意），也可以自己给 3–7 个有序选项；按所选选项的位置归一，第一项 0、最后一项 1，取均值 |
| `boolean` | 是 / 否；答「是」的比例 |
| `open` | 不计分，只进报告 |

- 每道 `scale` / `boolean` 题成为一个指标 `survey.Q<n>`（如 `survey.Q1`），假设可以像引用 `stress` 一样引用它，方向、最小效应、安慰剂噪声底线规则全部照旧。一个世界、一个种子、一道题只有一个分数，所以 `final` 和 `mean` 是同一个数。
- 只要有一道可计分题，协议就是 `composite`；模型写了 `composite` 却一道可计分题都没有，跑前检查报错。
- **受访者**：协议里指定了居民就是他们，否则是该世界状态表里出现过的全部居民。开了 `family.members_as_agents` 时被升级成居民的家人没有档案，不采访。
- **每个世界是隔离的**：采访进程带着这个世界运行时的 config 覆盖启动，记忆、向量库、目标都读这个世界自己的文件——补贴世界里的居民记得补贴，基准世界里的不记得。
- **答不上来的不算 0**：回答对不上选项或是非时记为「无法计分」，不进得分；某题超过 20% 无法计分会列为数据质量问题。
- **居民配对检验**同样适用（见[第 6 节](#6-假设怎么判定)）：同一批居民在每个世界都答了，逐人配对。

题目要中性、不诱导——编译提示词里有这条要求，但审阅协议时仍值得自己读一遍：问卷题目在批准后就固定了。

## 5. 跑前检查与成本

### 5.1 规则

**错误**（有任何一条就不能批准）：

- 没有处理条件（至少一个 `role = treatment` 的世界）；
- 没有一条可评估的假设；
- `composite` 研究没有一道可计分的问卷题；
- 仿真天数不晚于最后一个事件日；
- 估算调用量超过上限（默认 **50,000**）。

**警告**（不拦，但要看）：

- 只有一个种子：没有跨种子一致性，没有安慰剂时判定最高只能到「不确定」；
- 没有安慰剂世界：没有噪声底线；
- 每一条编译时丢弃。

### 5.2 成本怎么算

```
估算调用量 = 居民数 × 仿真天数 × 每人每天调用数 × 世界数 × 种子数
每人每天调用数：完整模式 198（48 个 tick × 约 4 次调用），快速模式 1
```

例：20 位居民、7 天、3 个世界（基准 + 处理 + 安慰剂）、2 个种子：

| 模式 | 估算 | 能过默认上限吗 |
|---|---|---|
| 完整 | 20 × 7 × 198 × 3 × 2 = 166,320 | 不能 |
| 快速 | 20 × 7 × 1 × 3 × 2 = 840 | 能 |
| 完整，只选 5 位居民 | 5 × 7 × 198 × 3 × 2 = 41,580 | 能 |

`composite` 研究还要加上采访：每位居民每道题一次调用。

```
问卷调用量 = 居民数 × 题数 × 世界数 × 种子数
```

例：20 位居民、3 道题、3 个世界、2 个种子 = 360 次——相比仿真本身通常可以忽略。

所以常见的做法是：先用**快速模式 + 少量居民**跑通，看判定和数据质量，确认值得做再加大规模。

## 6. 假设怎么判定

每条假设在每个种子上算一个效应：`处理条件的值 − 对照条件的值`（按 `aggregation` 聚合）。
有安慰剂世界时，`|安慰剂 − 基准|` 的最大值作为**噪声底线**。然后按固定规则判定：

| 判定 | 条件 |
|---|---|
| **支持** | 所有种子方向都与预测一致，且均值效应 ≥ 最小效应，且 > 噪声底线 |
| **反向** | 所有种子方向都与预测相反，幅度同样过线 |
| **不确定** | 其他一切情况——方向不一致、幅度不够；**单种子且无安慰剂时最高只能到这里** |
| **未测到** | 没有任何种子同时拿到处理和对照的值 |

**居民配对检验（第二道关）。** 每个种子的报告里还有逐居民的配对估计（同一居民在处理与对照世界之差，
事件后窗口均值，按居民 bootstrap 区间 + BH-FDR，见 [平行世界教程 §13](./PARALLEL_WORLDS_TUTORIAL.md#13-反事实推断效应区间异质性与重复)）。
当假设的对照条件就是这些估计的对照世界时，「支持 / 反向」还要求**每个种子**的配对检验在所判方向上显著
（q < 0.05 且 95% 区间不含 0），否则降为「不确定」，依据里写明是哪个种子没过。它只会让判定更严，不会更松；
预注册的效应（按 `aggregation`）仍是主要数字。另外，两个以上种子时依据里还会给出种子层面的 95% t 区间。

问卷指标（`survey.Q<n>`）的配对检验来自问卷本身：同一位居民在处理世界的答案减去他在对照世界的答案，
按居民 bootstrap 区间、符号翻转 p、同一种子各问卷假设之间 BH 校正。因为每个世界都问了同一批人，这一关**不要求对照是基准世界**。

规则故意保守：它要防的正是「单种子、无对照，就下一个自信的结论」。每个判定都附带判定依据
（几个种子方向一致、均值效应多少、噪声底线多少），可以手算复核。

指标的来源等级不改变判定，只改变怎么读：(c) 级指标的依据里会多一行「指标来源 (c) 级：只读方向，效应大小不作数」，
结果里的均值效应旁也写着同一句话（见 [4.3](#43-可测量指标)）。

数据质量检查和判定同时进行：没有状态数据的世界、在所有世界里都不变的指标，都会列在结果之前。

## 7. 解读与报告

**解读**是一次模型调用，拿到的是判定好的结果表。它被要求：

- 每条发现必须挂在一个假设 id 上，只能引用表里的数字；挂不上的会被标成「未挂到任何假设，不作数」；
- 指标是 (c) 级的假设，结论里只说方向（上升 / 下降），各种子效应只能放在依据里；结论里写了具体大小（小数、百分比、百分点）的会被标成「对只读方向的指标写了效应大小，大小不作数」；
- 判定为不确定 / 未测到的假设，不能写成有效应；
- 数据质量问题必须写进局限；
- 给 2–3 个能在平行世界里继续做的后续研究（剂量反应、机制探查、稳健性）。

解读失败不算研究失败：报告会少这一节，但结果照常出。

**报告**的顺序本身就是论证：先是预注册（样本、条件、假设与预测、指标来源、编译时丢弃、跑前检查），
然后才是执行记录、结果、数据质量和解读。读者在看到任何数字之前先看到预测，结果就没法被悄悄改说成「本来就是这么预期的」。

## 8. 研究的生命周期：暂停、停止、中断、重置

```
待批准(protocol) → 已批准(approved) → 运行中(running) → 已判定(evaluated) → 已出报告(reported)
                                            ↘ 出错(error)
```

| 操作 | 什么时候能用 | 效果 |
|---|---|---|
| 修改旋钮 | 待批准 / 出错 | 改天数、种子、快速模式、居民、仿真模型，重新检查 |
| 批准 | 待批准，且跑前检查通过 | 进入已批准 |
| 运行 | 已批准 | 开跑；同一时间只能有一项研究在跑 |
| 暂停 / 继续 | 运行中 | 挂起进行中的世界，其余排队 |
| 停止 | 运行中 | 终止运行 |
| 重置运行 | 不在运行中 | 清空结果回到可运行状态；**已有的平行世界产物保留**，重跑写到新目录 `study_<id>_r<次数>_s<种子>` |
| 删除 | 任意（运行中需先停止） | 删除研究记录 |

**中断**：运行句柄只在面板进程的内存里。面板重启、崩溃或 Ctrl-C 后，停在「运行中」的研究会在下一次读取时被标为
「运行已中断（服务重启或进程退出）」，不会永远显示运行中。此时点 **停止** 整理记录，或点 **重置运行** 重新跑。

## 9. HTTP 接口

所有长操作都是**后台任务**：POST 返回 `job_id`（HTTP 202），然后轮询 `GET /api/research/jobs/<job_id>`，
直到 `status` 变成 `done` 或 `error`；结果在 `result` 里。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/research/context` | 模型列表、功能目录状态、字数上限、方案与研究列表，面板首屏一次拿齐 |
| POST | `/api/research/extract` | `{name, data}`（base64 或 data URL）→ `{text, pages, name}` |
| POST | `/api/research/digest` | 解读论文（任务）→ `result` 是解读 |
| POST | `/api/research/analyze` | 生成方案（任务）→ `result.plan_id` |
| GET | `/api/research/jobs/<id>` | 任务状态 |
| GET | `/api/research/plans` | 方案列表 |
| GET | `/api/research/plans/<id>` | 方案全文 |
| GET | `/api/research/plans/<id>/export` | `{filename, markdown, bytes}` |
| POST | `/api/research/delete` | `{plan_id}` |
| POST | `/api/research/studies` | 编译协议（任务）：`{plan_id, design_index?, provider?, autopilot?, seeds?, sim_days?, fast?, agent_ids?, max_parallel?, sim_provider?}` |
| GET | `/api/research/studies` | 研究列表 |
| GET | `/api/research/studies/<id>` | 研究详情 |
| GET | `/api/research/studies/<id>/report` | 报告 Markdown |
| POST | `/api/research/studies/<id>/<动作>` | `update` / `approve`（`{run?, force?}`）/ `run` / `pause` / `resume` / `stop` / `reset`（`{run?}`）/ `delete` |

用 curl 走一遍论文两步流程：

```bash
curl -s -X POST http://127.0.0.1:8766/api/research/digest -H 'Content-Type: application/json' -d '{"title":"租金补贴与心理压力","text":"（论文正文）","provider":""}'
```

```bash
curl -s http://127.0.0.1:8766/api/research/jobs/digest-1a2b3c4d
```

把返回的 `result` 改好后，作为 `digest` 字段带上：

```bash
curl -s -X POST http://127.0.0.1:8766/api/research/analyze -H 'Content-Type: application/json' -d '{"kind":"paper","title":"租金补贴与心理压力","text":"（论文正文）","digest":{"paper_digest":{"theory":"…","method":"…","key_variables":["补贴","压力"],"findings":"…"},"research_questions":["…"],"hypotheses":["H1：补贴后压力下降"]}}'
```

编译第二个设计（下标从 0 开始）：

```bash
curl -s -X POST http://127.0.0.1:8766/api/research/studies -H 'Content-Type: application/json' -d '{"plan_id":"20260926-101500-abc123","design_index":1,"fast":true,"seeds":[42,43]}'
```

说明：

- `digest` 只对 `kind: "paper"` 生效；字段全空时被忽略。
- `design_index` 不是整数或越界时返回 400；不传时编译推荐的设计。
- 跑前检查没通过时 `approve` 返回 400，除非带 `force: true`（面板上没有这个按钮，是留给脚本的逃生口）。
- 任务记录只保留最近 10 个，并且在内存里——面板重启后旧的 `job_id` 会 404。

## 11. 工作原理与边界

**功能目录就是事实来源。** 每次分析都在调用时读取 `docs/FEATURES.md`（最多 60,000 字）放进提示词。
给 GAWorld 加了新功能，把它写进 `FEATURES.md`，下一次分析就会用上，不需要重启面板。
面板侧栏会显示目录的路径和字数；找不到目录时会警告，方案只能依据平台概况。

**可测量目录是代码。** 协议编译用的是 `gaworld/research/measures.py`，因为判定器要读的正是提示词里承诺的那一列。

**模型调用与上限：**

| 调用 | 输出上限 | 路由 |
|---|---|---|
| 解读论文 | 3,000 token | `task="research"` |
| 生成方案 | 12,000 token | `task="research"` |
| 编译协议 | 6,000 token | `task="research"` |
| 解读结果 | 3,000 token | `task="research"` |

「分析用的模型」下拉框选的是这四类调用用的模型；居民本身跑在哪个模型上由研究卡片上的「仿真模型」决定。

**边界：**

- 协议能编译成**平行世界**实验，或**平行世界 + 跑后问卷**（composite）。不跑世界的独立问卷、提示词网格等设计还不能自动执行——方案里仍然会写，但只能照着步骤手动做。
- 指标是状态变量和问卷题，见 [4.3](#43-可测量指标)、[4.5](#45-问卷先跑世界再采访居民)。研究社交网络结构、收入分布的假设会在编译时被丢弃。开放题不计分。
- 一次只跑一项研究。

## 12. 常见问题

**上传 PDF 提示「读取 PDF 需要安装 pypdf」？**
`pypdf` 已在 `requirements.txt` 里，重新 `pip install -r requirements.txt` 即可。

**「这个 PDF 里没有可提取的文字」？**
扫描件没有文字层。先 OCR，或直接把摘要、方法、结果粘进文本框。

**解读或方案报「模型没有返回可解析的 JSON」？**
模型没按格式回答，或输出被截断了。换一个更强的模型，或把材料缩短到摘要 + 方法 + 结果。

**方案只有一个实验设计？**
模型没按要求给多个，或者这是更新之前生成的旧方案。重新生成一次即可；旧方案照常能打开、能转成研究。

**编译后所有假设都被丢弃了？**
看「编译时丢弃」里的原因，最常见的是指标不在可测量目录里。回到论文解读那一步，把假设改写成用 [4.3](#43-可测量指标) 里的指标，再生成方案。

**跑前检查说调用量超过上限？**
打开快速模式、减少参与居民、减少天数或种子，见 [5.2](#52-成本怎么算)。

**结果全是「不确定」？**
先看判定依据：是种子方向不一致，还是效应没过最小效应 / 噪声底线。再看数据质量：某个指标全程不变的话，它什么也说明不了。
单种子且无安慰剂时，最多只能判到「不确定」——这是有意的。

**点「运行」提示有别的研究正在运行？**
一次只能跑一项。等它结束，或先停止它。

**面板重启后研究卡在「运行中」？**
下一次打开时它会被标成「运行已中断」。点停止整理记录，或重置运行重新跑；上一次的平行世界产物会保留。

## 13. 严肃游戏

研究工作台顶部的 **严肃游戏** Tab：写一段情景描述，模型把它设计成一个回合制的角色扮演游戏；每个角色可以由城市里的居民智能体扮演，也可以由真人来玩，两者可以混坐一桌。

### 13.1 流程

1. **描述**：谁在场、各自想要什么、要决定什么。可指定轮数（2–8）和角色数（2–8），留「自动」由模型定。
2. **生成**：一次模型调用，产出背景、角色（公开身份 / 目标 / 只有自己知道的私密信息）、公共指标、每轮事件与可选做法、评分维度、复盘问题。输出不可玩（少于 2 个角色或没有回合）时自动重试一次。
3. **安排座位**：每个角色选「居民智能体」（指定某位居民或随机，来自所选城市，同一局不会重复入座）或「真人」（可填称呼）。
4. **对局**：每一轮所有角色**同时**行动——居民按自己的档案 + 角色简介由模型来演；真人座位有一个链接，发给参与者在自己的浏览器里打开，只能看到自己角色的私密信息。人齐了，主持人（一次模型调用）裁定本轮结果、调整指标。主持面板可以「不等了，结算本轮」，缺席的真人记为未行动。
5. **复盘**：最后一轮结束后，按评分维度给每个角色打 1–5 分，逐条评估学习目标、回答复盘问题，可下载 Markdown。

### 13.2 谁能看到什么

| 视图 | 打开方式 | 能看到 |
|---|---|---|
| 主持 | 侧栏「对局」或 `?tab=game&session=<id>` | 所有角色的私密信息、居民的心里话、本轮已提交的行动、真人座位链接 |
| 玩家 | 座位链接 `?tab=game&session=<id>&seat=<token>` | 公开信息 + 自己角色的私密信息；本轮别人的行动在结算前看不到 |

座位链接只是区分身份，不是鉴权——它适合在一台本地面板上组织的课堂或工作坊。

### 13.4 落盘与边界

- 设计存放在 `output/research/serious_games/<id>.json`，对局在 `output/research/serious_games/sessions/<id>.json`，每次状态变化都会写盘；不会写回任何城市。
- 进程重启时正在进行的模型调用会丢失；下次打开该对局会从「裁定中 / 复盘中」继续。
- 实现：`gaworld/research/serious_game.py`（设计、提示词、规则，无线程无 HTTP）+ `gaworld/apps/serious_game_api.py`（后台推进与路由，经 `research_api` 转发）。

## 14. 政策仿真与优化

研究工作台顶部的 **政策仿真与优化** Tab：选一座城市，写一段政策描述（可选再写一个候选政策），让城市里的居民逐个对它作出反应，由代码汇总出效果，再由模型提出修改建议，并在同一批居民上验证修订版。

### 14.1 流程

1. **抽样**：从所选城市按种子随机抽 6–30 位居民（16 岁以下不参加）。所有版本都用**同一批人**，版本之间比的是配对的回答，不是抽样运气。
2. **居民反应**：每位居民按自己的档案，对每个版本输出一个固定格式的 JSON——支持度（−2~2）、半年后生活变化（−5~5）、钱包影响（−5~5）、遵从度（0~100）、实际会怎么做、最担心什么、只能改一处会怎么改。读不出 JSON 的回答记为无效，不算作中立。
3. **代码汇总**：支持率 / 反对率 / 日子变差的比例、各项均值、按年龄段 / 性别 / 户籍的分组均值、分组之间生活感受的最大差距，以及综合分：`支持度 35% + 生活 30% + 钱包 15% + 遵从 20%`（各自归一到 0–1，再乘 100）。
4. **评估与修改**：一次模型调用读入上述数字、分组和最不满意居民的原话，给出效果评估、主要效果、风险与被忽视的人群、（有候选时）两版对比、逐条修改（改什么 / 为什么 / 回应谁）和一份完整的修订版政策。
5. **验证**（默认开启）：修订版在同一批居民上再仿真一次。**推荐版本按综合分由代码选出**，修订版跑输原政策时会如实标出。
6. 结果页可「以修订版为原政策再优化」，把修订版填回输入框进行下一轮；也可下载 Markdown。

一次运行的模型调用数 = 居民数 × 版本数 + 1（例如 12 人、原政策 + 候选 + 修订版 = 37 次）。

### 14.2 HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/research/policy` | 仿真记录列表 |
| POST | `/api/research/policy/run` | `{policy, candidate?, city?, city_name?, sample_size?, seed?, verify?, provider?}` → `{job_id}`（202） |
| GET | `/api/research/policy/jobs/<job_id>` | 任务进度，完成后 `result.run_id` |
| GET | `/api/research/policy/<run_id>` | 完整记录：版本、居民、逐人反应、指标、分组、建议、推荐版本 |
| GET | `/api/research/policy/<run_id>/export` | `{filename, markdown}` |
| POST | `/api/research/policy/<run_id>/delete` | 删除记录 |

### 14.3 落盘与边界

- 记录存放在 `output/research/policy/<id>.json`，只在运行结束时写盘；不会写回任何城市。
- 居民反应是大模型按档案扮演出的**情景推演**，不是民意调查，也没有跑完整的日程仿真；样本小，适合比较版本、发现受损人群和修改方向，不适合给出精确的比例。
- 实现：`gaworld/research/policy_sim.py`（抽样、提示词、汇总、导出，无线程无 HTTP）+ `gaworld/apps/policy_sim_api.py`（后台任务与路由，经 `research_api` 转发）。

## 15. 平行世界 · 反事实推断

研究工作台顶部的 **平行世界 · 反事实推断** Tab（原来控制台里单独的「平行世界」页签，旧链接 `/console#worlds` 会跳到这里）：
手动设计 2–8 个平行世界（同一批居民、同一个种子，只换事件或配置），跑完后除了分叉图、走向对比、偏离曲线，还给出：

- **反事实推断**：每个世界 × 指标的平均处理效应（同一居民两个世界之差），按居民 bootstrap 的 95% 区间、
  符号翻转随机化检验 p、BH-FDR q、配对效应量、事件前差与 DiD，以及按固定规则给出的判定；可以切换对照世界（重度对轻度）而不用重跑。
- **安慰剂噪声底线**：把某个世界的角色设为「安慰剂」，它就成为效应判定与分叉阈值的噪声参照。
- **机制线索**（哪个指标先动）、**异质性**（按性别 / 年龄段 / 户籍 / 事件前水平的条件效应与置换检验）、
  **剂量反应**（给世界填剂量）、**跨种子重复**（「重复种子数」≥ 3 时按种子合并）。
- **参数扫描**：选一个数值配置项、填几组取值，自动生成「基准（保持当前值）+ 每个取值一个世界」，剂量就是取值，跑完直接看剂量反应；见[平行世界教程 §4](./PARALLEL_WORLDS_TUTORIAL.md#参数扫描一个配置项几组取值)。
- **模型解读**：一次模型调用，把上面这些表格写成结论、局限和下一步实验；每条发现必须指向估计表里的一行并带上那一行的判定，
  指不到的标「不作数」，指向非稳健效应的会被提醒。按对照世界缓存在实验目录的 `interpretation.json`。

和「转成研究」的关系：研究是**预注册**的路径——协议先写好假设，跑完由代码逐条判定；这个 Tab 是**探索与诊断**的路径——
自己设计世界、看效应落在哪、量噪声、试剂量，适合在写预注册之前摸清楚效应大小和噪声水平。
研究跑出的实验也会出现在这个 Tab 的历史列表里，并按种子合并。

方法、判定规则与接口见 [平行世界教程 §13](./PARALLEL_WORLDS_TUTORIAL.md#13-反事实推断效应区间异质性与重复)。
