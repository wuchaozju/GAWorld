# 机制来源表

日期：2026-09-25
用途：**每一条结论在引用某个指标之前，先在这里查这个指标依赖的机制属于哪一类。**

这份表是 2026-09-19 那轮提案里 P7 的落地。当时的理由是：GAWorld 已经吃过两次
「把自己写进去的东西当发现」的亏（Track A 的循环论证、group agent 的单种子 L2）。
建立 agent→环境反馈之后这个风险被放大，因为涌现结果**看起来更像发现**。

---

## 分级定义

| 级别 | 含义 | 能支撑什么 |
|---|---|---|
| **(a)** | 从真实数据校准 | 可以单独立论 |
| **(b)** | 从文献搬来的标准机制，参数有公开区间 | 可以单独立论；须注明出处与参数取值 |
| **(c)** | 我们自己定的合理猜测，或按某个目标标定出来的旋钮 | **不得单独立论**。只能用「跨取值的方向一致性」立论，并且**被用来标定它的那个量，不再是它的证据** |

第三条最后半句是整张表的重点。一旦用通勤时长标定了 `distance_decay`，通勤时长就不
再是 `distance_decay` 的证据；还想用通勤时长立论，就得换一个没参与标定的判据。

## 空间与出行

| 机制 | 级别 | 出处 / 理由 | 参数 | 代码 |
|---|---|---|---|---|
| BPR 路阻函数 `t = t0(1+α(v/c)^β)` | **(b)** | 交通分配标准 link performance function，α/β 有公开标定区间 | α=0.15, β=4.0 | `world/traffic.py` |
| 引力式住处/工作地分配 `容量 / (1+d)^decay` | **(b)** | 标准 gravity/attraction 形式 | 见下两行 | `sim/_location.py` |
| 地铁可达判定（两端同线步行圈内） | **(b)** | 与「路线经过站点」相对，这是可达性的常规定义 | `METRO_ACCESS_KM=0.8` | `world/city_map.py` |
| 拥车率对收入的 logistic | **(b)** | 标准形式；50% 点设在**本镇中位收入**的倍数上，可跨种群迁移。量级印证：杭州人口 1262.4 万 / 机动车 479 万 ≈ 0.379 辆/人（2024） | `spread=0.55` | `world/traffic.py` |
| 两轮车拥有权 | **(b)** | 同一形式，pivot 远低于中位、曲线更平（便宜品）。锚点：全国电动自行车保有量 >4 亿辆（2024）对 ~14.1 亿人 ≈ 0.28 辆/人（含老幼） | `pivot=0.35, spread=1.1` | `world/traffic.py` |
| 广义出行成本模式选择 | **(c)** | 形式是 (b) 类（时长 + 票价/时间价值），但七个不适参数无法由三个总量分担率识别。**默认关** | `mode_choice.scored=False` | `world/city_map.py` |
| 时间价值 = 时薪 × 0.5 | **(b)** | 通勤时间价值取工资率一半，是评价文献的常规取值 | `VALUE_OF_TIME_WAGE_SHARE` | `world/city_map.py` |
| 道路通行能力（按等级） | **(b)** | arterial 1800 PCU/h/方向是教科书量级 | 见 `ROAD_TYPE_CAPACITY` | `world/traffic.py` |
| PCU 折算（bus 2.0 / e-bike 0.2 …） | **(c)** | 量级合理，未校准 | `MODE_PCU` | `world/traffic.py` |
| **`agents_represent`** | **(c)** | 抽样放大倍数。**建模旋钮，不是人口学事实** | 默认 1.0，须显式设定 | `settings/environment.py` |
| **`distance_decay`（工作地）** | **(c)** | 决定通勤距离分布 | 1.5 | `settings/runtime.py` |
| **`home_distance_decay`** | **(c)** | 决定住处向心集中度。与上一条**刻意不同**：离家远近和离市中心远近不是同一种偏好 | 0.5 | `settings/runtime.py` |
| **`car_ownership.pivot_income_multiple`** | **(c)** | 按**拥车率本身**标定（县城量级 ~35%，按人计），不是按公交分担率标定 | 1.2 | `settings/environment.py` |
| 拥车按**个人**而非按**户** | **(c)** | 户是运行时派生的，模式选择拿不到。富裕家庭里的退休老人在这里算作无车 | — | `world/traffic.py` |
| 模式选择用**直线**距离，计时计价用**路网**距离 | **(c)** | 两个口径并存；不一定错，但调阈值时容易算错账 | — | `world/city_map.py` |

## 人口与经济

| 机制 | 级别 | 出处 / 理由 | 代码 |
|---|---|---|---|
| 失业率 = 失业 / 劳动力 | **(b)** | ILO 口径，退休与在读学生不进分母 | `economy/finance.py` |
| 人口 IPF 拟合（年龄 × 就业等边缘分布） | **(a)** | 对规格里的真实统计目标拟合 | `population/synth.py` |
| 收入以 profile 声称值为锚 | **(a)** | 采纳人口合成器按 median/gini 目标采样的结果，不再由职业名重摇 | `economy/finance.py` |
| `profile_income_jitter` | **(c)** | 只为避免整镇收入都是整数；设 0 即严格照发 | 0.08 |
| 职业 → 行业的子串匹配 | **(c)** | **已知失效**：「跨境电商运营」被判成 service。合成种群现在直接带 `industry` 列，这条只对老语料生效 | `economy/finance.py` |
| 非就业人群的低收入带（8–22 元/时） | **(c)** | 刻意给的低收入而非零收入；此处**没有养老金发放机制**，改成 0 会让开局即退休的人立刻赤贫 | `economy/finance.py` |

## 对 Track A 两个通勤锚点的当前判定

| 锚点 | 状态 | 理由 |
|---|---|---|
| 单程通勤 34.5 min | **口径不符，不计分** | 全市口径 vs 片区仿真 |
| 公交机动化分担率 47.6% | **口径不符，不计分** | 同上 |
| 绿色出行 >70% | **口径不符，不计分** | 同上 |
| 单程通勤距离 8.1 km | **口径不符，不计分** | 片区最多做到 5.94 km，19 km 的图上没有那条尾巴 |
| 5 公里以内通勤比重 52% | **口径不符**（但片区能复现 52.3%） | 复现属巧合级证据，不单独立论 |

**这不是「还没调到」，是尺子和被量的东西不是一回事。** 仿真的是杭州滨江一带约
19×15 km 的片区，锚点描述的是全杭州。一个半数通勤在 5 公里以内的片区，本来就该比全市
更多步行骑行、更少小汽车。

已按 2026-09-25 的决定（方案 B）落实：`gaworld_bench.py` 的每条锚点带 `scope` 字段，
`city_wide` 的只报告不打分（`context_metrics`），并有回归测试锁住。
要恢复这些锚点的判据资格，只有两条路：换成全市口径的地图，或找到片区口径的参照。

## 维护规矩

1. 每加一条 agent→环境的机制，同时加一行。
2. (c) 类旋钮的默认值变更，要在提案里写明「按什么标定的」。
3. Bench 的 scorecard 引用某个指标时，附上它最弱的那一级依赖。
